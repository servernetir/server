# گرهٔ رلهٔ پیامک در n8n

کدِ گرهٔ **Verify & Map Template** از ورک‌فلوی
`ServerNet SMS Relay (Bale → IPPanel) v2` (`ZKnSuClgcwG7QiqK`) روی
`https://flow.servernet.cloud`.

زنجیرهٔ کامل:

```
Laravel (BaleRelaySender) → رباتِ فرستنده → گروهِ خصوصیِ بله
  → رباتِ گیرنده → وب‌هوکِ n8n → این گره → آی‌پی‌پنل → موبایلِ مشتری
```

## چرا این فایل این‌جاست و نه فقط داخلِ n8n

کدِ یک گرهٔ n8n در دیتابیسِ n8n زندگی می‌کند: نه نسخه‌بندی دارد، نه تست، نه
بازبینی. این گره **امضای رمزنگاری‌شده** را تأیید می‌کند و تصمیم می‌گیرد چه
پیامکی با پولِ واقعی فرستاده شود. یک ویرایشِ اشتباه در رابطِ n8n یعنی یا هر
پیامک می‌ایستد، یا بدتر: هر کسی می‌تواند پیامِ جعلی به صف تزریق کند.

پس نسخهٔ مرجع این‌جاست، با تست، و از این‌جا به n8n دپلوی می‌شود.

## 🔴 چرا رمزنگاری دستی نوشته شده

task-runnerِ این نصبِ n8n هیچ راهی به رمزنگاری نمی‌دهد:

```
require('crypto')  →  Module 'crypto' is disallowed
globalThis.crypto  →  crypto is not defined      (نه WebCrypto)
```

نسخهٔ اولِ گره روی `require('crypto')` می‌شکست. نتیجه: **هیچ پیامی هرگز از
فیلتر رد نمی‌شد** و هیچ پیامکی نمی‌رفت — و چون خطا فقط در تاریخچهٔ اجرای n8n
می‌نشست نه در سایت، از بیرون شبیهِ «بله پیام را تحویل نداده» به‌نظر می‌رسید.

پس SHA-256 و HMAC و Base64URL و UTF-8 همه دستی و **بدونِ هیچ وابستگیِ محیطی**
نوشته شده‌اند — نه `Buffer`، نه `TextEncoder`، نه `atob`. سندباکسی که `crypto`
را برداشته، فردا ممکن است اینها را هم بردارد.

## تست

```bash
node relay/n8n/verify-and-map-template.test.js
```

۱۶ ادعا، و پاکت‌ها را **خودِ PHP** می‌سازد (`make-envelope.php`) تا واقعاً
هم‌خوانیِ دو زبان سنجیده شود، نه تعریفِ دوبارهٔ همان منطق در جاوااسکریپت:

| | |
|---|---|
| مسیرِ خوش‌بینانه | پاکتِ PHP → `ipPanelBody` درست، با کدِ الگو و متغیرها |
| امضا | دستکاریِ امضا و **تعویضِ شمارهٔ گیرنده با امضای قدیمی** هر دو رد |
| بازپخش (replay) | پاکتِ خارج از پنجرهٔ ۱۸۰ ثانیه رد |
| مرجع | گروه و فرستندهٔ غیرمجاز رد |
| داده | الگوی ناشناخته، متغیرِ جاافتاده (با نامِ دقیقِ کلید) |
| یونیکد | ارقامِ فارسی و جداکنندهٔ ممیز دست‌نخورده عبور می‌کنند |

خودِ HMAC جداگانه با **۳۴ بردارِ مرجع** از `hash_hmac` در PHP تطبیق داده شد:
مرزهای بلاکِ ۵۵/۵۶/۶۳/۶۴/۶۵ بایت، کلیدِ بلندتر از ۶۴ بایت (که اول هش می‌شود)،
فارسی، و ایموجی (جفتِ جانشین).

## دپلوی

کد را در گرهٔ `Verify & Map Template` جای‌گذاری کن. **پیکربندی این‌جا نیست** —
توکن‌ها و رازها در گرهٔ `Relay Config` می‌مانند و هرگز به این مخزن نمی‌آیند.

⚠️ رجیستریِ `TEMPLATES` بالای فایل، کدهای الگوی آی‌پی‌پنل را دارد. سمتِ چپِ هر
`vars` نامِ متغیر در الگوی اپراتور است و سمتِ راست کلیدی که پروژه می‌فرستد —
این دو **یکی نیستند** (مثلاً `otp ← code`) و اشتباه‌گرفتنشان یعنی
`missing_param` برای هر پیام.

🔴 **تا این فایل در رابطِ n8n جای‌گذاری نشود، الگوهای تازه کار نمی‌کنند.** گره
نسخهٔ خودش را از دیتابیسِ n8n می‌خوانَد، نه از مخزن. الگویی که فقط این‌جا اضافه
شده باشد، در n8n با `unknown_template` رد می‌شود و پیامکش **بی‌صدا** نمی‌رود —
و چون پاسخِ ورک‌فلو برای پاکتِ ردشده هم ۲۰۰ است، از بیرون شبیهِ موفقیت است.
عیب‌یابی: `/system/sms-status` → `sms:last_error`.

# گرهٔ «Iran Probe» — نقطهٔ سنجشِ داخلِ ایران (iran-probe.js)

ورک‌فلوی **جدا** از رلهٔ پیامک، روی همان n8n ایرانی. مصرف‌کننده: ابزارهای
عمومیِ «تست سرعت» و «دسترسی از ایران» روی سایت
(`App\Services\WebProbe::probeFetch`).

```
Laravel ──POST {target}──▶ Webhook → Set (probeToken) → Code (iran-probe.js) → Respond
```

ساختِ ورک‌فلو در n8n:

1. **Webhook** — متد POST، مسیرِ تصادفی، Respond: «Using Respond to Webhook node».
2. **Set** — فیلد `probeToken` با رمزِ مشترک (رمز فقط این‌جا؛ در مخزن نیست).
3. **Code** — محتوای `iran-probe.js`، حالت «Run Once for All Items».
4. **Respond to Webhook** — JSONِ آخرین گره.

سپس در `.env` سرورِ اصلی:

```
IRAN_PROBE_URL='https://flow.servernet.cloud/webhook/…'
IRAN_PROBE_TOKEN='…'
```

- توکنِ ست‌نشده یا غلط ⇒ `{ok:false, error:"bad_token"}` — **fail-closed**.
- پاسخِ ردشده هم HTTP 200 است؛ لاراول فقط `ok` را می‌خوانَد (قاعدهٔ «۲۰۰ ولی نرفت»).
- بدونِ این ورک‌فلو هیچ‌چیز نمی‌شکند: ابزارها فقط از دید اروپا می‌سنجند و
  ردیفِ ایران «پیکربندی‌نشده» می‌مانَد.
- ⚠️ اولین قدمِ عیب‌یابی، مثل رله: **وب‌هوک را مستقیم بزن** (curl با هدرِ
  `X-Probe-Token`). اگر `no_http_capability` گرفتی یعنی سندباکسِ این n8n نه
  helper دارد نه fetch — گزینهٔ جایگزین: گرهٔ HTTP Request به‌جای Code
  (بدونِ زمان‌سنجی).

تست: `node iran-probe.test.js` (۱۵ ادعا، بدونِ تماسِ شبکه).

### وضعیت دیپلوی (۱۶ اوت ۲۰۲۶ / ۲۵ مرداد ۱۴۰۵)

ورک‌فلو ساخته و **فعال** شد: `ServerNet Iran Probe (Speed & Access tools)`
(شناسه `zAHK7jJdD8GuQfjw` روی flow.servernet.cloud). آزموده‌شده با تماس
مستقیم: توکن غلط ⇒ bad_token · هدف خصوصی ⇒ private_target · ftp ⇒
bad_scheme · example.com از ایران ⇒ ‎200 در ~180ms · servernet.cloud از
ایران ⇒ ‎200 در ~820ms.

🔴 **درس دوم سندباکس:** علاوه بر crypto، گلوبال `URL` هم وجود ندارد.
نسخه‌ی اولِ گره با `new URL(target)` هر هدفِ سالمی را «bad_target» می‌کرد —
بی‌هیچ خطایی در لاگ، چون catch عمومی آن را می‌بلعید. پارس URL حالا فقط با
رجکس است. به هیچ گلوبالِ محیطی (URL، Buffer، TextEncoder، crypto) تکیه نکن؛
فقط رشته و رجکس و Date.

⚠️ تست محلی از این ماشین ویندوزی ممکن نیست: `C:\php\extras\ssl\cacert.pem`
خراب است و HTTPS از PHP شکست می‌خورد (curl.exe سالم است). روی سرور اصلی
همین مسیر HTTPS به همین هاست را رله‌ی پیامک هر روز می‌رود.
