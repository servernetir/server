# DeepInfra remaining native contracts — 2026-10-11

This implementation supplements the native launch checkpoint. It adds **12 bounded execution candidates** among the former 17 pending DeepInfra models: six Bria video editors, audio-driven Pruna avatar, Wan reference-to-video, two FLUX.2 image models and two Seedance video models. It preserves the previous 75 DeepInfra native contracts and three GapGPT image contracts. The primary manifest therefore has 90 supported contracts, including 87 DeepInfra contracts. A supported source contract is not proof of production activation or a paid result; the final deployment record owns those facts.

No paid provider request, token creation, production database mutation or installation was performed by this implementation subtask. Five DeepInfra models still have explicit blockers; they are not marked saleable to satisfy a target count.

## Input decoder

`AiVideoInput` accepts a complete non-fragmented MP4 with one H.264 video stream and at most one AAC audio stream. It verifies box sizes, track durations, sample counts and sample timing before decoding. Limits are decoded bytes ≤6 MB, duration ≤10.1 seconds, dimensions ≤1920 pixels per side, total pixels ≤2,097,152, at most 600 video frames and 3000 audio samples. Version-one duration headers and unsupported tracks/codecs are rejected rather than guessed.

Admission then fully decodes the input with the configured trusted FFmpeg binary. The default path is `storage/app/private/ai-media/bin/ffmpeg`; missing executable or unavailable `proc_open` closes models that require video input validation. Execution uses an argument array, not a shell, and a 20-second process timeout. MOV format is forced; remote protocols and external references are disabled. Decoder safeguards include one thread, the H.264/AAC decoder whitelist, a 16 MiB maximum individual allocation and the 2,097,152-pixel codec limit. Full decoded frame count must match the MP4 sample table, every decoded frame's actual dimensions must match the declared dimensions, decoding must complete successfully, and output time must stay within the declared duration allowance. Header inspection alone never opens the paid route.

Input files are written only in the private app temporary directory, mode 0600, and removed in a `finally` block. No customer URL is fetched. Measurements used to build the hold do not add raw input media to usage snapshots. Installing/verifying the production decoder belongs to the root deployment record; this source note does not infer installation from local tests.

The test decoder was the parent task's verified FFmpeg 9.0 Linux binary, downloaded from the build distribution linked by the official FFmpeg download page. Its SHA256 was `4e9f3e0b5cea8b37fd5878196f37ea1e1510033d968be46a977ad01323ac9148`. A new, synthetic 1-second blue video fixture contains 10 frames at 320×240. The earlier real DeepInfra FastWan output was also fully decoded locally without another paid request: 5.062500 seconds, 81 frames, 832×480.

Initial focused validation: **26 tests /621 assertions**, PHP8.4.25, using the trusted Linux decoder in an isolated container with networking disabled. Tests cover all 90 primary supported contract request shapes, actual full decoding, temporary-file cleanup, corrupt encoded samples, false duration and dimension headers, decoder absence, all six Bria request paths, invalid coordinates/frame bounds, exact FLUX first/additional/reference MP arithmetic, Seedance output controls, measured avatar speech and Wan nested-reference types/counts. Fake provider responses exercise financial settlement/replay and scope/balance/project guards. The relay/duration/geometry/logging follow-up passed **52 tests /776 assertions** using narrow overlays of the supplied actual production route and error-tracker files. No paid inference was performed here. The final integrated suite and production proof are reported separately.

The parent task's first live FLUX.2 Pro probe returned `upstream_bad_body`, with its real cost initially pending reconciliation. Inspection of the official output metadata found that this family returns `image_url`, which the generic native parser had omitted. The parser now recognizes that result and requires the documented top-level `status: ok`; it still rejects failed, queued, running and unknown inference states. The same documented shape applies to FLUX.1.1 Pro and the three Clarity models. Tests verify scientific-notation USD receipts, moderation/error states, malformed or empty image output, invalid cost strings, exact receipt settlement and single-charge replay. This source correction is not by itself evidence that the earlier live response had a specific cost or state; the deployment record must report the recovered receipt and the subsequent validation.

A read-only output-schema audit covered all 87 supported DeepInfra native contracts. It also identified the omitted Veo `videos` list and the Bria `mask_url` result used when only a mask is produced. Both are now recognized with their documented successful top-level states: `ok` for Veo and `COMPLETED` for Bria. Veo's published example inconsistently uses a single URL although its schema says URL array; both nonempty string URLs and nonempty lists of string URLs are admitted. Malformed collections and all published error, cancellation and processing states remain pending reconciliation rather than being charged as successful output. Seedance's reported `out_tokens` are retained as native video-token information; chat token columns remain null. Every supported output schema now declares at least one recognized result field, and tests explicitly cover image, mask-only and video-list receipt shapes.

Bria's optional mask can be null or empty when a valid primary video is returned. This fallback is accepted without treating an empty/whitespace mask as a successful result on its own. Non-string masks and unsuccessful top-level states still reject. The focused regression tests cover both mask-only results and the optional-empty-mask primary-video workflow.

Two CLIP models (`openai/clip-vit-base-patch32`, `openai/clip-vit-large-patch14-336`) are priced at USD0.0005 per runtime second. Their public schema does not expose a server-enforced runtime or request-cost ceiling. HTTP client timeout does not establish a billing limit. The current official scoped-JWT OpenAPI says the spending limit invalidates the token as its total budget is used; it does not document interruption of a running inference before a single request exceeds that budget. Therefore a JWT counter is not represented as a proven runtime cap. No JWT was minted.

Three MiMo speech models (`MiMo-V2.5-tts`, `MiMo-V2.5-tts-voicedesign`, `MiMo-V2.5-tts-voiceclone`) are explicitly **temporarily free** on DeepInfra. Their confirmed zero wholesale tariff cannot support a percentage-profit paid offering without a separate, disclosed minimum service-fee policy. They remain unavailable for paid sale under the current 5%-markup instruction. A positive provider cost, signed contract or verified invoice is not invented. VoiceClone additionally refers to provider-account voice IDs; ownership isolation would be needed for a future voice-management workflow.

## Bria supplier relay

The representative inline-video Bria probe failed upstream. [Bria's current input documentation](https://docs.bria.ai/getting-started/working-with-images) explicitly requires a reachable video URL; the documented raw-base64 image option does not extend to video. `AiMediaRelay` therefore handles only the six exact reviewed DeepInfra Bria video models. The client still submits inline MP4 bytes; admission fully decodes them, freezes the original request hash and measured reservation, and forbids customer URLs. The driver creates relay files only after financial reservation and immediately before sending. Replayed responses create neither another file nor another provider call.

Files reside only under `storage/app/private/ai-media/relay`, with directory mode 0700 and file mode 0600. A 256-bit random opaque ID and a relative Laravel HMAC-signed URL grant GET/HEAD access for at most 15 minutes. The generated host is fixed to the public site, independent of incoming Host headers or console worker origins. The controller validates signature and expiry, never reads a client-selected path, and streams exact MP4 bytes with one bounded byte range, `no-store` and `noindex`. Customer authentication and sessions are excluded from this supplier-fetch route. Invalid, expired, tampered and missing media return no bytes. Relay creation failures are classified as unsent, releasing the wallet reservation without a provider request.

File operations and garbage collection use a private mutex; all input fields are validated before any file is created. Expired regular files matching the exact relay filename are removed during publication and the existing hourly `ai:prune-replay` job. Unrelated files, directories and symlinks are preserved; no recursive removal is used. A reader opens the file under the mutex, so an already authorized transfer can finish after expiry cleanup. Application error/404 tracking redacts relay IDs, signed query strings and media referrers. Web-server or CDN access logs may still contain these short-lived URLs; the application change does not alter host logging policy. Retention can last until the existing hourly task or next publication, while access expires after 15 minutes.

[Prompt-mask documentation](https://docs.bria.ai/video-editing/masking/mask-by-prompt) and the eraser/key-point schema constrain those routes to five seconds and 750p; the gateway rejects longer decoded input instead of silently trimming and conservatively caps both pixel dimensions at 750. [Upscaling documentation](https://docs.bria.ai/video-editing/editing/increase-resolution) permits longer input and preserves frame rate and duration; the gateway keeps its narrower local video decoder limit and rejects a selected scale that would exceed the documented 7680×4320 output dimensions. Model pages interpolate the applicable duration and input-size allowance. The one-second synthetic H.264 retry uses 320×240 at 10fps; its native reserve is USD0.10 (one measured second plus one-second allowance at USD0.05/s). Parent task owns the paid retry, supplier proof, activation and cumulative USD5 accounting.

The offline relay suite exercises signed GET/HEAD/ranges, expiry/tampering, traversal and symlink rejection, SSRF rejection, corrupt and invalid multi-input refusal without file creation, permission checks, safe cleanup/open-reader behavior, the existing scheduler command hook, reservation-before-publication, receipt-based 5% settlement and zero-cost replay, plus application log redaction. A real six-second fully decoded fixture separately confirms the three five-second admission caps; the longer-input upscale route remains valid. No supplier request is performed by these tests.

The parent task's unpaid production relay diagnostic confirmed HEAD200 with an empty body, GET200 with all1903 reviewed bytes, Range206 with the requested bytes and tampered signature403. The public frontend omits Content-Length and streams GET with chunked transfer; neither response sets a session cookie. Laravel's HTTP client represents an absent header as an empty string. The first private smoke helper incorrectly required a HEAD length header and tested absent cookies against null, so it stopped before creating a synthetic customer or reserving any paid test; the cumulative guard remained USD4.372. Its evidence is preserved. The corrected fresh helper accepts an omitted HEAD length, rejects any explicitly wrong length (including zero), requires an empty HEAD body and the video MIME type, verifies the GET hash/range bytes and checks empty cookie headers. Offline regressions reproduce those cases. No application route, decoder or relay source change was needed for this observation; later paid validation remains the parent deployment record's responsibility.
