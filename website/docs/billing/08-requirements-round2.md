# خواسته‌های دور دوم کارفرما

> ثبت‌شده از پیام کارفرما. این‌ها به طراحی موجود اضافه می‌شوند.

## ۱. زیردامنه‌ی پنل — تصمیم برگشت‌خورد

کارفرما زیردامنه می‌خواهد (نه مسیر `/panel`). گزینه‌ها: `my.` / `console.` / `dash.`

**پیشنهاد من: `console.servernet.cloud` و `console.servernet.ir`.**
«console» لحن ارائه‌دهنده‌ی ابری جدی را دارد (AWS/GCP همین را می‌گویند)؛
`my.` صمیمی و استاندارد WHMCS است ولی کم‌ابهت‌تر؛ `dash.` ضعیف‌ترین.

هر نصب زیردامنه‌ی خودش را دارد چون دو دیتابیس مستقل داریم:
- ایران: `console.servernet.ir`
- خارج: `console.servernet.cloud`

نکته‌ی فنی: کوکی نشست باید per-subdomain باشد تا جداسازی امنیتی حفظ شود.

## ۲. اطلاع‌رسانی سه‌کاناله — روی هر رویداد

هر رویداد (ثبت‌نام، تیکت، سرویس جدید، فاکتور، اعلان، …) از سه کانال:
- **ایمیل** (از خروجی آلمان — IP ایران بلاک است)
- **پیامک**
- **ربات بله** (Bale — پیام‌رسان ایرانی)

این با جدول `notifications` و `messaging_providers` در حوزه‌ی support-ops
می‌خواند. کانال «بله» یک `MessagingProvider` جدید است.

## ۳. ناوبری موبایل پنل

منوی پایین‌صفحه برای مشتری سخت است. باید بالا بیاید — همبرگر/کشویی از بالا.
راحتی مشتری اولویت است.

## ۴. خودخدمتی پروفایل

- تغییر رمز: مستقیم توسط کاربر ✓
- تغییر اطلاعاتی که قبلاً **احراز هویت** شده: فقط با **تیکت** (نه مستقیم)

دلیل درست است: اطلاعات تأییدشده‌ی KYC نباید بی‌بازبینی عوض شود.

## ۵. همکاری در فروش (Affiliate)

اگر کاربری توسط شخص دیگری معرفی شود، **۱۰٪ مبلغ** به اعتبار معرف اضافه می‌شود.
- جدول جدید: `referrals` (معرف، معرفی‌شده، کد)
- `referral_commissions` (تراکنش کمیسیون، به `wallet_entries` وصل)
- کد معرف در پروفایل هر کاربر
- کمیسیون فقط پس از **پرداخت واقعی** معرفی‌شده حساب شود، نه ثبت‌نام
  (وگرنه ثبت‌نام جعلی = پول جعلی)

## ۶. دامنه — OpenProvider

- یک رسیلری: OpenProvider
- **همه‌ی** TLDهایش فروخته شوند
- **نیم‌سرورها (nameservers) از کاربر گرفته شوند** هنگام ثبت
- بقیه طبق طراحی حوزه‌ی domains (استعلام زنده، مقایسه، quote با انقضا)

## ۷. قیمت دلار لحظه‌ای — منبع قیمت‌گذاری

- منبع: **alanchand.com** — باید API‌اش بررسی شود (هنوز تأیید نشده وجود دارد)
- به‌روزرسانی: **هر ۱ ساعت** (کران)
- در **پنل مدیریت** نمایش داده شود
- **قیمت‌گذاری محصولات بر اساس آن:** قیمت دلاری از API → درصد سود → قیمت نهایی
- یعنی محصولات ارز-پایه دلاری دارند و قیمت تومان از نرخ زنده + مارجین ساخته می‌شود

### ⚠️ تعارض با تصمیم قبلی — باید روشن شود

قبلاً تصمیم گرفتیم «قیمت هرگز با نرخ ارز محاسبه نشود، هر نصب قیمت ثابت خودش را
دارد». حالا کارفرما می‌خواهد قیمت تومان **از نرخ دلار زنده** ساخته شود.

این‌ها با هم قابل جمع‌اند، ولی باید تصمیم بگیریم:
- **قیمت پایه دلاری + مارجین → تومان لحظه‌ای؟** (قیمت هر روز نوسان می‌کند)
- یا **دلار فقط مبنای محاسبه‌ی اولیه، بعد قیمت تومان قفل می‌شود** تا ادمین دستی عوض کند؟

پیشنهاد من: حالت دوم برای پایداری قیمت. نوسان روزانه‌ی قیمت، مشتری و حسابداری
را گیج می‌کند. دلار زنده «پیشنهاد قیمت» بدهد، ادمین تأیید/قفل کند.
**منتظر نظر کارفرما.**

## ۸. پنل مدیریت

کارفرما می‌خواهد پیش‌نمایش پنل مدیریت را ببیند (مثل پنل کاربری).

## وضعیت انتشار

پیش‌نمایش پنل کاربری در نوبت قبل اشتباهاً منتشر شد (روی سرور زنده رفت).
از این پس: **اول محلی، انتشار فقط با اجازه‌ی صریح کارفرما.**
