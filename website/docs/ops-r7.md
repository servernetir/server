# اقلامِ عملیاتیِ ممیزی ۷ که **کد نیستند** — با دستورِ دقیق

> مکملِ [ops-r6.md](ops-r6.md) — آن سند هنوز معتبر است (نرخ‌محدودسازی، RPO/RTO،
> پایشِ مستقل، ارزش افزوده). این‌جا فقط قلم‌های تازهٔ دورِ هفتم است.
> قاعدهٔ خودِ ممیزی: **تا بکاپ و لاگِ upstream انجام نشده، هیچ تغییرِ
> عملکردیِ دیگری نزنید.**

## ۰. یک ساعتِ طلایی — تله‌متری از داخل (مالک: زیرساخت، امروز)

هفت دور ممیزی از بیرون داریم و صفر عدد از داخل. سه کار، به همین ترتیب:

**الف) سه دستورِ بکاپ (۵ دقیقه):**
```bash
proxmox-backup-client snapshot list --repository <user>@pbs@<host>:<datastore>
pvesh get /nodes/$(hostname)/tasks --typefilter vzdump --limit 20
mysqldump --single-transaction <db> | gzip > /tmp/t.sql.gz && gzip -t /tmp/t.sql.gz && ls -lh /tmp/t.sql.gz
```
اولی خطا داد = PBS وجود ندارد. دومی خالی = هیچ بکاپی گرفته نشده.
نتیجه را با تاریخ در همین فایل بنویس — «هشت دور است بی‌پاسخ مانده».

**ب) لاگِ زمانِ اپ:** روی این هاستِ cPanel به nginx دسترس نداریم؛ معادلش
دو چیز است که **همین دیپلوی** فعال می‌کند:
- هدرِ `Server-Timing: app;dur=<ms>` روی هر پاسخِ سایت (میلی‌ثانیهٔ PHP، جدا از شبکه).
- مسیرِ `/healthz` — پاسخِ ثابت بدونِ DB و کش. تفکیک‌کنندهٔ قطعی:
```bash
for i in 1 2 3 4 5; do curl -s -o /dev/null -w '%{time_starttransfer}\n' https://servernet.cloud/healthz; sleep 2; done
```
اگر `/healthz` هم بالای ~۲۵۰ms بود ← مشکل زیرِ لاراول است (PHP-FPM/OPcache/CPU).
اگر سریع بود و صفحات کند ← لایهٔ اپ/DB. آن‌وقت — و فقط آن‌وقت — سراغِ بهینه‌سازی برو.

**ج) p50/p95 از لاگِ موجودِ Apache (دسترسی از cPanel → Metrics → Raw Access):**
```bash
awk '{print $10}' ~/access-logs/servernet.cloud | sort -n | awk '{a[NR]=$1} END{print "p50",a[int(NR*.5)],"p95",a[int(NR*.95)]}'
```

## ۱. شمارشِ قیف — اولین عددِ تاریخِ شرکت (مالک: رشد، بعد از دیپلوی)

هر کلیکِ «پرداخت» روی صفحاتِ سفارش از `/go/pay` می‌گذرد و سمتِ سرور ثبت می‌شود:
```bash
# روزانه — شمارِ کلیکِ پرداخت و تفکیکِ SKU:
grep -c '"e":"pay_redirect"' ~/servernet_app/storage/app/funnel/events-*.jsonl
grep '"e":"pay_redirect"' ~/servernet_app/storage/app/funnel/events-*.jsonl \
  | grep -oE '"sku":"[^"]*"' | sort | uniq -c | sort -rn
```
مخرجِ کسر (بازدیدِ /order) از اکسس‌لاگ: `grep -cE 'GET /(en/|tr/)?order/' ~/access-logs/*`.
نرخِ تبدیلِ سفارش ← پرداخت = همین دو عدد. بدونِ کوکی، بدونِ JS، بدونِ رضایت.

## ۲. اسکریپتِ هفتگی به‌جای ممیزیِ هشتم (مالک: هرکس — ۵ دقیقه)

```bash
bash scripts/rg-core.sh; echo "exit=$?"
```
خروجیِ خام (سه تستِ هسته + هشت عدد) را در گروه بگذار. **معیارِ دودوییِ دورِ
هشتم فقط همین است: «اجرا شد و خروجیِ خام ارائه شد؟»** — حتی اگر FAIL باشد،
معیار «بله» است. هیچ ممیزیِ کاملی تا ۳۰ روز، مگر ≥۶ قلمِ رودمپ ✅ شود.

## ۳. Search Console بعد از دیپلوی (مالک: سئو، همان روز + ۳۰ روز بعد)

- sitemap را در GSC دوباره Submit کن.
- Performance → فیلترِ URL با `-de-de-` و مشابه‌ها روی ۱۶ ماه: اگر کلیک>۰ بود،
  فقط ثبت کن (۳۰۱ از قبل equity را منتقل می‌کند — کارِ اضافه لازم نیست).
- پذیرشِ ۳۰روزه: «Duplicate, submitted URL not selected as canonical» → صفر،
  و هر ۲۲ آدرسِ دوبل در URL Inspection وضعیتِ «Page with redirect».
- رفع‌های GSC ۲۴ اوت (اسکیما، صفحات خالی ابر) هم در همین دیپلوی کامل لایو
  می‌شوند → Validate Fix های همان ممیزی را بزن.

## ۴. چهار آزمونِ ۵ دقیقه‌ایِ امنیت (مالک: بنیان‌گذار — از مرورگر/موبایل خودش)

از گزارشِ ممیزی، §۱۱ — این‌ها از بیرون قابلِ انجام نیستند و فقط تو می‌توانی:
1. **نشستِ دو دامنه:** در console لاگین کن → DevTools → Cookies. کوکیِ نشست
   باید `Secure`+`HttpOnly`+`SameSite=Lax` باشد. سپس مقدارش را کپی کن، Logout
   بزن، با `curl -H "Cookie: …"` صفحهٔ حساب را بگیر — ۲۰۰ یعنی logout سمتِ
   سرور نشست را باطل نمی‌کند (باید رفع شود).
   ⚠️ توجه: `SESSION_DOMAIN=.servernet.cloud` این‌جا **عمدی** است (نشستِ مشترکِ
   سایت/کنسول — CLAUDE.md §۳)؛ یعنی XSS در سایتِ مارکتینگ = ریسکِ نشستِ کنسول.
   این مصالحه ثبت شود؛ جبرانش CSPِ سخت‌گیرانه و logoutِ سمتِ سرور است.
2. **آپلود KYC:** یک `.txt` را `photo.jpg` کن و آپلود کن (باید رد شود)؛ URL
   فایل را در پنجرهٔ ناشناس باز کن (باید ۴۰۳)؛ عددِ داخلِ URL را ±۱ کن —
   اگر مدرکِ دیگری آمد = IDOR بحرانی، همان روز رفع.
3. **MFA ادمین:** مرورگرِ تازه + رمزِ درست — بدونِ گامِ دوم وارد شدی؟ ۱۰ رمزِ
   غلط — قفل نشد؟ هر دو یعنی کار دارد.
4. **Proxmox:** با موبایل روی دیتای همراه `https://<IP>:8006` — صفحهٔ لاگین
   آمد یعنی پنل روی اینترنتِ عمومی است؛ همان روز پشتِ VPN/فایروال ببر.
   هم‌زمان IP را در Shodan جست‌وجو کن.

## ۵. SSRF ابزارهای /lookup (مالک: امنیت — نیم‌ساعت)

محافظِ کد موجود است (`app/Services/SafeUrl.php`: فقط http/https، ردِ IP
خصوصی/loopback/link-local **پس از** DNS resolve، دنبال‌کردنِ دستیِ ریدایرکت با
اعتبارسنجیِ هر پرش). /webtools کلاً مرورگری است و به سرور نمی‌رسد.
آزمونِ زنده برای اطمینان — در فرمِ هر ابزارِ /lookup این‌ها را بده؛ همه باید
**پیش از تلاش** رد شوند:
`127.0.0.1` · `localhost:8006` · `169.254.169.254` · `10.0.0.1` · `http://[::1]`
· و یک دامنهٔ خودت که به IP داخلی resolve می‌شود.

## ۷. آنچه در این دیپلوی عمداً انجام **نشد** — و چرا

- **ادغامِ کاملِ ۷۷←۱۱ صفحهٔ /cloud:** ۲۲ صفحهٔ دوبل ۳۰۱ شدند، sitemap پاک شد
  و سقفِ صفحه قفل شد (RG-BUDGET)، اما ۶ صفحهٔ شهریِ واقعی (فالکن‌اشتاین،
  نورنبرگ، هلسینکی…) حذف نشدند: هرکدام متنِ سئویِ یکتا دارند، عنوانشان یکتاست
  و معماریِ قبلی («صفحهٔ کشور = /vps/{کشور}» — CloudCountry) همان هدفِ
  «هاب + کشور» را برآورده می‌کند. حذفشان یعنی دورانداختنِ کارِ سالمِ سه دورِ
  قبل. اگر تصمیمِ محصولی بر حذف ماند، یک مهاجرتِ ۳۰۱ کافی است.
- **اسپرایتِ پرچم‌ها:** /cloud فقط ~۱۰ فایلِ SVG یکتا بارگذاری می‌کند (کشِ
  مرورگر + lazy + `alt=""`+`aria-hidden` که هم‌اکنون لایو است). گلوگاهِ واقعی
  TTFBِ HTML بود که کشِ denylist حلش می‌کند. سنجهٔ RG-ALT-14 وضعِ سالم را قفل
  کرده؛ اسپرایت سود واقعی نداشت و ریسکِ رگرسیونِ ظاهری داشت.
- **قیدِ UNIQUE/CHECK در DB برای کدِ لوکیشن:** جدولِ cloud_locations ستونِ
  plan_type ندارد؛ گاردِ برنامه‌ای در CloudCatalogSync + تستِ رگرسیون +
  RG-DUP-PATH-11 سه‌لایه همان را می‌بندند بدونِ ریسکِ مهاجرتِ ناسازگار با
  MariaDB/SQLite.
