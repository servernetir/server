# سرورنت — راهنمای مخزن و شروع همکاری

سامانهٔ اختصاصی فروش، تحویل، صورتحساب، پنل مشتری، پشتیبانی و محتوای **servernet.cloud**؛ جایگزین اختصاصی WHMCS در کسب‌وکار سرورنت.

> **مرجع اصلی کار همهٔ توسعه‌دهندگان: `develop`.**
> مالک پروژه در ۱۴ اکتبر ۲۰۲۶ این موضوع را صریحاً تأیید کرده است. نام پیش‌فرض مخزن در تنظیمات GitHub هنگام بررسی `main` بود؛ این تنظیم، مرجع کاری پروژه را تغییر نمی‌دهد. هنگام clone، مقایسه و PR، شاخه را صریح تعیین کنید.

## کدام پوشه مربوط به چیست؟

| مسیر | نقش | انتشار همراه سایت؟ |
|---|---|---|
| `website/` | اپ واقعی Laravel؛ سایت عمومی، پنل و منطق کسب‌وکار | فقط فایل‌های اجراییِ تأییدشده، نه کل پوشه |
| `infra/` | Ansible، Proxmox، شبکه و عامل‌های زیرساخت | خیر؛ فرایند مستقل دارد |
| `relay/` | کد n8n و پراکسی GPU در Cloudflare و ابزارهای رله | خیر؛ مقصدهای مستقل دارد |
| `scripts/` | ابزارهای عملیات، انتشارهای موردی و Worker مستقل | بازبینی موردی؛ نه آپلود عمومی |
| `tools/`، `seo/`، `.claude/` | ابزارها و منابع کار توسعه/عملیات | خارج از بستهٔ عادی سایت |
| `docs/` و گزارش‌های تاریخ‌دار ریشه | مستندات و شواهد؛ بعضی شامل ترتیب بازگشت‌اند | خیر؛ در مخزن حفظ می‌شوند |
| `app/` ریشه، `Dockerfile` و `docker-compose.yml` | اپ قدیمی Laravel 9 طبق مستندات پیشین | مسیر اجرای سایت فعلی نیست؛ حذف هنوز تأیید نشده |

**نبودن یک فایل در cPanel دلیل اضافی‌بودن آن در Git نیست.** تست، مستند، کد زیرساخت و ابزار ساخت معمولاً نباید روی وب‌سرور عمومی باشند.

## فناوری و محیط‌ها

- محدودیت‌های اعلام‌شده در `website/composer.json`: PHP `^8.3` و Laravel `^13.8`؛ نسخهٔ دقیق وابستگی‌ها را از `composer.lock` بخوانید. PHP 8.4 مبنای محیط‌های ثبت‌شده در راهنمای فنی است، نه نتیجهٔ سنجش زندهٔ این بررسی.
- محلی/تست: SQLite؛ تست‌ها پایگاه دادهٔ درون‌حافظه‌ای دارند. **MariaDB برای تولید در راهنمای فنی گزارش شده است**؛ تنظیم محلی را به تولید تعمیم ندهید.
- رابط: فارسی/انگلیسی/ترکی؛ فارسی پیش‌فرض و RTL. Blade و منابع عمومی به‌علاوهٔ تعریف Vite/Tailwind در بستهٔ frontend وجود دارند؛ مسیر build هر تغییر باید مشخص باشد.
- چیدمان ثبت‌شدهٔ تولید: اپ خارج از webroot در `servernet_app/` و محتوای عمومی در `public_html/`. نسخهٔ تولید `index.php` سازگارکنندهٔ همین چیدمان است.

## شروع محلی

```bash
git clone --branch develop https://github.com/servernetir/server.git
cd server/website
composer install
```

ادامهٔ تنظیم محیط و تست را فقط مطابق [ONBOARDING](website/docs/ONBOARDING.md) و در checkout ایزوله انجام دهید. از `.env`، داده و اعتبارنامهٔ تولید برای توسعه استفاده نکنید. `composer setup` شامل migration و ساخت است و دستور انتشار تولید نیست.

## مرز این به‌روزرسانی

این بازنگری **مستندات** است: نه فایل اجرایی سایت، نه دیتابیس، نه cPanel، نه تنظیمات شاخه و نه منابع زیرساخت را تغییر می‌دهد. نقشهٔ پروژه از کد و مستندات snapshot `f455d44ed928fd01905da1d64d64a8b887324e60` استخراج شده؛ ادعای ممیزی خط‌به‌خط تمام کد، تطبیق کامل تولید یا قبولی تمام تست‌ها نیست. نتیجهٔ اجرای واقعی همیشه باید همراه SHA، محیط و زمان ثبت شود.
