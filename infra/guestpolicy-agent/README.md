# عاملِ سیاستِ شبکهٔ داخلی

«این مهمان اجازهٔ دیدنِ شبکهٔ داخلی را دارد یا نه» را از پنل می‌کشد و روی
هاستِ ایران اعمال می‌کند، بعد تأیید می‌فرستد.

```
پنل  ──GET /agent/guestpolicy──▶  عامل  ──iptables──▶  زنجیرهٔ SNET-GUEST
  ▲                                 │
  └──POST /agent/guestpolicy/ack────┘
```

## نصب — یک بار، به‌عنوان root روی هاستِ ایران

```bash
bash install.sh https://servernet.cloud '<AGENT_TOKEN>'
```

توکن همان `agent_pull_token` است که عامل‌های countryroutes/portforwards
استفاده می‌کنند (در `/admin/settings`). idempotent است.

برداشتن: `bash uninstall.sh` — فقط زنجیرهٔ خودش را پاک می‌کند.

## سه قاعده‌ای که این را امن نگه می‌دارد

**۱ — سرور داده می‌فرستد، نه دستور.** هیچ چیزی از پاسخ مستقیم به `iptables`
نمی‌رود. هر IP با regex سنجیده می‌شود و دستور را خودِ اسکریپت می‌سازد.
بدترین کارِ یک پاسخِ جعلی، بستنِ دسترسیِ داخلیِ یک IP در همان ساب‌نت است.

**۲ — فقط زنجیرهٔ خودش.** همه‌چیز داخلِ `SNET-GUEST` است و از `FORWARD`
قلاب می‌شود. قواعدِ VLESS (۲۰۸۷)، SSH (۲۰۰۰۰)، NPM و country-routing هرگز
خوانده یا پاک نمی‌شوند — «یک مالک برای هر دامنهٔ قاعده».

**۳ — پاسخِ نامعتبر هیچ‌چیز را پاک نمی‌کند.** خطای شبکه، صفحهٔ Cloudflare با
کدِ ۲۰۰، یا JSONِ بدونِ `schema` ⇒ خروج بی‌تغییر.

## چرا `ESTABLISHED,RELATED` اولِ زنجیره است

قاعدهٔ DROP فقط اتصالِ **آغازشده از خودِ مهمان** به شبکهٔ داخلی را می‌بندد.
بی آن خطِ اول، پاسخِ اتصال‌هایی که از بیرون به همان مهمان آمده‌اند (مثلاً
NPM که به سایتِ مشتری پراکسی می‌کند) هم می‌افتاد و سرویس قطع می‌شد.

⚠️ ترافیکِ مهمان به **خودِ هاست** (`10.10.10.1` — DNS و گیت‌وی) از زنجیرهٔ
`INPUT` می‌گذرد نه `FORWARD`، پس این قاعده آن را نمی‌بندد. عمدی است.

## تلهٔ jq که یک بار خورد

```
{a: empty}   ← کلِ آبجکت را نابود می‌کند، نه فقط آن فیلد را
```

نسخهٔ اول ack با `error:($e|select(.!=""))` ساخته می‌شد؛ در حالتِ **موفق**
خروجیِ jq کاملاً خالی می‌شد و بدنهٔ تهی می‌رفت — یعنی تأیید هرگز ثبت نمی‌شد
و پنل تا ابد «در انتظار» می‌مانْد، بی‌هیچ خطایی. با تستِ محیطِ ساختگی پیدا شد.

## تست

اسکریپت پیش از تحویل در یک محیطِ ساختگی (iptables/curl/logger جعلی) با شش
سناریو اجرا شد: اعمالِ اولیه · اجرای دوباره بدونِ تغییر (نباید flush کند) ·
پاسخِ HTML با کدِ ۲۰۰ · قطعِ شبکه · تغییرِ سیاست · و **تزریق** (یک «IP» حاوی
`; rm -rf /` که رد شد و بقیهٔ ردیف‌ها سالم اعمال شدند).

## عیب‌یابی

```bash
systemctl status servernet-guestpolicy.timer
journalctl -t servernet-guestpolicy -n 50
iptables -S SNET-GUEST
/usr/local/sbin/servernet-guestpolicy-agent -v      # اجرای دستی با خروجی
```
