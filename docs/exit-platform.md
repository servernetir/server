# پلتفرمِ اکسیت — معماری، قرارداد و عملیات

> مرجعِ واحدِ «زیرساختِ اکسیت»: از پنلِ لاراول تا قوانینِ iptables روی میزبانِ
> ایران. اگر فقط یک چیز از این سند می‌خوانید، **بخشِ ۲ (قراردادِ عامل‌ها)** را
> بخوانید — نبودِ همین بخش باعث شد سه نسخهٔ ناسازگار از یک قرارداد در گردش
> باشد و port-forward ماه‌ها بی‌صدا کار نکند.

---

## ۱. تصویرِ کلی

سرورِ اصلی (پنلِ لاراول) در **آلمان** است و میزبانِ Proxmox در **ایران**. آلمان
نمی‌تواند به ایران push کند (NAT/DPI)، پس جهتِ جریان همیشه **کششی** است:

```
        ┌──────────────────────────┐
        │  پنلِ اصلی (آلمان)        │   ← اپراتور اینجا تصمیم می‌گیرد
        │  console.servernet.cloud │
        └────────────┬─────────────┘
                     │  «حالتِ مطلوب» (فقط‌خواندنی، توکن‌دار)
                     │  GET /agent/countryroutes
                     │  GET /agent/portforwards
                     ▼
        ┌──────────────────────────┐
        │  میزبانِ Proxmox (ایران)   │
        │  ├─ servernet-country-agent → connmark + ip rule → tun<cc>
        │  └─ servernet-pf-agent      → iptables nat SERVERNET-PF (DNAT)
        └────────────┬─────────────┘
                     ▼
        ┌──────────────────────────┐
        │  LXC 113 — هابِ اکسیت      │  tun0/tunde/tunnl/tunfi → رله‌های خارج
        └──────────────────────────┘
```

**اصلِ طلایی:** پنل هرگز روی میزبان دستور اجرا نمی‌کند. پنل فقط «چه باید باشد» را
منتشر می‌کند؛ میزبان می‌کشد و **تطبیق (reconcile)** می‌دهد. یعنی هر تغییری در پنل
حداکثر تا یک پیمایش (۱۰–۶۰ ثانیه) روی میزبان می‌نشیند، و اگر ارتباط قطع شود
میزبان آخرین حالتِ سالم را نگه می‌دارد.

---

## ۲. قراردادِ عامل‌ها (Source of Truth)

منبعِ حقیقت **`app/Http/Controllers/Agent/PullController.php`** است. هر تغییری در
این قرارداد باید هم‌زمان در سه جا اعمال شود، وگرنه عامل بی‌صدا می‌خوابد:

1. `website/app/Http/Controllers/Agent/PullController.php` (تولیدکننده)
2. `infra/ansible/roles/pf_agent/templates/servernet-pf-agent.sh.j2` (مصرف‌کننده)
3. `infra/ansible/roles/control_panel/files/servernet-country-agent.sh` (مصرف‌کننده)

### ۲.۱ احرازِ هویت

```
X-Agent-Token: <agent_pull_token>     ← نامِ نو
X-PF-Token:    <agent_pull_token>     ← نامِ قدیمی، هنوز پذیرفته می‌شود
```

> ⚠️ **`Authorization: Bearer` پذیرفته نمی‌شود.** توکنِ خالی یا ناهم‌خوان ⇒ `403`
> (fail-closed). عاملی که Bearer بفرستد ۴۰۳ می‌گیرد و — چون خطا را بی‌صدا رد
> می‌کند — انگار هیچ کاری نکرده است.

### ۲.۲ `GET /agent/countryroutes`

```json
[ { "ip": "10.10.10.99", "cc": "de" } ]
```

- فقط ماشین‌هایی که کشورِ خروج دارند در پاسخ می‌آیند.
- «ایران / بدونِ اکسیت» یعنی ماشین **در پاسخ نیست** (نه اینکه `cc` خالی باشد).
- `meta.exit_country` (سوییچِ دستیِ پنل) بر `location_code` مقدم است.

### ۲.۳ `GET /agent/portforwards`

```json
[ { "ip": "10.10.10.99", "dest_port": 22, "public_port": 20999, "public_ip": "" } ]
```

- `dest_port`: ویندوز ⇒ `3389`، بقیه ⇒ `22`.
- `public_port`: **پایدار** است — یک‌بار از محدودهٔ فروش تخصیص و در `meta` ذخیره
  می‌شود، پس با پیمایشِ بعدی عوض نمی‌شود.
- `public_ip` ممکن است **خالی** باشد؛ در آن صورت عامل نباید `-d` بگذارد (وگرنه
  `iptables` قاعده را رد می‌کند).

### ۲.۴ نامهای منسوخ (فقط برای سازگاری)

| قراردادِ رسمی | نامهای قدیمی که هنوز پذیرفته می‌شوند |
|---|---|
| `public_port` | `pub_port`، `port` |
| `dest_port`   | `svc_port` |
| `ip`          | `dest_ip` |

عامل‌ها هر دو را می‌پذیرند، ولی **کدِ جدید فقط نامهای رسمی را تولید کند.**

## ۳. جریانِ کامل — از فروش تا بسته

1. **ساخت / ورود ماشین** — `/admin/exit-infra/import`: یا اسکنِ Proxmox، یا ثبتِ
   دستی (`hostname`, `vmid`, `ipv4`, OS, کشور، پورت). ماشین‌های خطِ‌قرمز (۱۰۸ و
   زیرساخت) عمداً قابلِ ورود نیستند.
2. **تخصیص به مشتری** — `/admin/cloud/attach`: پیش از ثبت، وجودِ VM را از خودِ
   Proxmox می‌پرسد. پس از ثبت، سرویس در پنلِ مشتری دیده می‌شود و **سررسیدِ تمدید**
   می‌گیرد تا کرونِ صورت‌حساب سرِ موعد فاکتور بسازد.
3. **صورتحساب** — دورهٔ ماهانه/سه‌ماهه/شش‌ماهه/سالانه. پیش‌فاکتور صادر می‌شود و پس
   از پرداختِ مشتری سرویس خودکار فعال می‌شود.
4. **اعمالِ کشور** — عاملِ کشور `{ip, cc}` را می‌کشد و برای هر IP:
   `connmark` می‌زند و `ip rule from <ip> fwmark 0xc0 lookup 50` می‌سازد. حذف از
   حالتِ مطلوب ⇒ قاعده‌ها برداشته می‌شوند (تطبیقِ دوطرفه).
5. **دسترسیِ عمومی** — عاملِ port-forward زنجیرهٔ `SERVERNET-PF` را بازسازی می‌کند:
   `<public_ip>:<public_port> → <ip>:<dest_port>`.

> **نکتهٔ مهمِ رفتاری:** سوییچِ کشور به «ایران» فقط مسیریابیِ خروج را برمی‌دارد؛
> **port-forward دست‌نخورده می‌مانَد** تا دسترسیِ SSH/RDP مشتری قطع نشود.

## ۴. عملیات

### تغییرِ کشورِ خروجِ یک ماشین
`/admin/exit-infra` → ستونِ «سوییچِ کشور» → کشور → «اعمال». حداکثر یک پیمایش بعد
روی میزبان می‌نشیند.

### وادار کردنِ اعمالِ فوری (روی میزبان)
```bash
systemctl start servernet-country-agent.service servernet-pf-agent.service
```

### وارسیِ سلامت
صفحهٔ `/admin/exit-infra` دو ضربان نشان می‌دهد. **هر عددِ بیش از ۵ دقیقه یعنی
عامل نمی‌دود** و هیچ تغییری از پنل روی میزبان اعمال نمی‌شود.

## ۵. عیب‌یابی

| نشانه | علتِ محتمل | وارسی |
|---|---|---|
| ضربان کهنه (دقایقِ زیاد / «هرگز») | آدرس یا توکنِ اشتباه در `/etc/servernet/pf-agent.env` | `curl -s -o /dev/null -w '%{http_code}' -H "X-Agent-Token: $PF_AGENT_TOKEN" https://servernet.cloud/agent/countryroutes` باید `200` بدهد |
| `403` از هر دو مسیر | توکن با `agent_pull_token` پنل یکی نیست، یا هدرِ `Authorization: Bearer` فرستاده شده | تنظیماتِ پنل ↔ فایلِ env |
| ضربان تازه ولی هیچ قاعده‌ای ساخته نمی‌شود | ناسازگاریِ کلیدهای JSON (بخشِ ۲.۴) | `journalctl -u servernet-pf-agent -n 30` — دنبالِ `KeyError` بگردید |
| کشور اعمال شده ولی اینترنت ندارد | تونلِ هاب (LXC 113) بالا نیست | `pct exec 113 -- systemctl is-active tun2socks-clean` |
| `Permission check failed (/vms/N, VM.Audit)` | آن VM اصلاً وجود ندارد (Proxmox برای مسیرِ ناموجود خطای مجوز می‌دهد) | vmid را از پنلِ Proxmox بردارید |
| اسکنِ ماشین‌ها خالی است | همهٔ ماشین‌های poolِ `customers` از قبل به مشتری وصل‌اند، یا خطِ‌قرمزند | `pvesh get /pools/customers` |

### وارسیِ سریعِ حالتِ میزبان
```bash
cat /etc/servernet/split.state        # کشورهای اعمال‌شده
ip rule show | grep fwmark            # قوانینِ split-routing
iptables -t nat -S SERVERNET-PF       # port-forwardها
```

## ۶. درس‌های حادثهٔ ۲۰۲۶-۰۸-۲۱

سه نقصِ هم‌زمان باعث شد پلتفرم «سالم به‌نظر برسد ولی هیچ کاری نکند»:

1. **`/etc/servernet/pf-agent.env` بیرون از IaC بود** و روی پنلِ interimِ قدیمی
   (`10.10.10.30`) و توکنِ قبلی مانده بود ⇒ ۳٫۵ روز ۴۰۳/۳۰۱ بی‌صدا.
   **رفع:** حالا این فایل را نقشِ `pf_agent` می‌سازد (`pf-agent.env.j2`).
2. **قرارداد در سه جا سه‌جور بود** (`port` / `pub_port` / `public_port`) ⇒
   `KeyError: 'port'` و هیچ DNATی ساخته نمی‌شد.
   **رفع:** بخشِ ۲ همین سند + پذیرشِ نامهای قدیمی در هر دو عامل.
3. **فیچرِ مدیریتِ اکسیت در گیت نبود** و فقط روی سرور زندگی می‌کرد ⇒ هر دیپلوی
   روت‌ها را پاک می‌کرد و صفحه ۵۰۰ می‌داد.
   **رفع:** همین کامیت، کلِ فیچر را وارد مخزن می‌کند.

**قاعده‌ای که از این حادثه می‌ماند:** هر چیزی که روی میزبانِ زنده «دستی» درست شود
و به IaC یا گیت برنگردد، دیر یا زود بی‌صدا می‌شکند — و چون بی‌صداست، ماه‌ها کسی
نمی‌فهمد. عامل‌ها باید **پرصدا** شکست بخورند: ضربانِ کهنه در صفحهٔ سلامت دقیقاً
برای همین است.
