# تقویم محتوای اولویت‌دار

این تقویم backlog تحریریه است؛ انتشار یا کار زمان‌بندی‌شده خودکار ایجاد نمی‌کند. هفته‌ها از پذیرش بسته آغاز می‌شوند. هر ردیف فقط پس از تأیید قابلیت واقعی محصول و بررسی متن منتشر می‌شود.

| زمان پیشنهادی | اولویت | کار | مخاطب و قصد | مقصد تجاری | شرط انتشار |
|---|---|---|---|---|---|
| هفته 1 | P1 | تکمیل راهنمای موجود ساعتی و لینوکس؛ سناریوی کوتاه‌مدت، هزینه و حذف | خریدار «وی پی اس ساعتی» و «سرور مجازی لینوکس ساعتی» | /vps/hourly | مثال از نرخ واقعی، تفکیک هزینه منابع/ترافیک، تأیید سیاست جاری |
| هفته 1 | P1 | راهنمای انتخاب هاست ویندوز/لینوکس و بازبینی metadata | توسعه‌دهنده ASP.NET/MSSQL یا PHP/WordPress | /hosting/windows و /hosting/linux | تغییر امروز در Git آماده؛ نسخه، quota و پنل وعده داده‌شده باید با تحویل واقعی بخواند |
| هفته 2 | P1 | به‌روزرسانی tutorial منتشرشده Jupyter و ComfyUI | خریدار GPU برای notebook/تصویر | /gpu | اجرای واقعی برنامه سازگار، checkpoint/خروجی، عدم ادعای دیسک پایدار یا ظرفیت تضمینی |
| هفته 2 | P1 | بررسی قصد خرید ترکیِ Python hosting | توسعه‌دهنده ترک‌زبان | /tr/hosting/python | تحلیل جداگانه باند رتبه؛ جهش رتبه قبلی با اثر متن تازه اشتباه نشود |
| هفته 2 | P2 | تکمیل یک مقایسه کشور با عرضه تأییدشده | خریدار آلمان/فنلاند و مسیر کاربر واقعی | همان صفحه کشور موجود | داده اختصاصی شبکه با روش/تاریخ معتبر؛ بدون ping تضمینی |
| هفته 3 | P2 | Windows hosting در برابر Windows VPS | نیاز IIS/SSMS در برابر اختیار سیستم‌عامل | /hosting/windows و /vps/windows | تأیید نسخه، لایسنس و دسترسی در پلن جاری؛ بدون ادعای blanket |
| هفته 3 | P2 | بکاپ و بازیابی workload قطع‌شدنی GPU | پروژه طولانی و داده مهم | /gpu | آزمون restore و خروجی واقعی؛ قید storage موقت |
| هفته 3 | P2 | راهنمای انتخاب هاست ایمیل/دانلود/بکاپ | خریدار با محدودیت quota/ترافیک | همان مسیرهای hosting | تأیید quota، سیاست استفاده و قابلیت پنل هر محصول |
| هفته 4 | P2 | تحلیل cohort ساعتی/GPU/کشور/هاست | تصمیم تجاری | صفحات بررسی‌شده | چهار هفته کامل داده پس از انتشار، همسان‌سازی device/country/position |
| هفته 4 | P3 | بررسی content gap رقبا و موضوع بعدی | قصد تجاری بدون صفحه مناسب | ابتدا URL موجود | شاهد تقاضای GSC؛ عدم تولید مقاله تکراری صرفاً برای تعداد |

هر نوشته باید سؤال مشخص، مخاطب، شاهد فنی، نویسنده واقعی، تاریخ، لینک داخلی و قدم بعدی داشته باشد. برای زبان‌های en/tr بررسی بومی intent لازم است؛ متن فارسی صرفاً با جایگزینی کلمات تکثیر نمی‌شود. عنوان جذاب نباید ویژگی پشتیبانی‌نشده، رایگان‌بودن، زمان تحویل یا SLA بسازد.

کلمات اصلی ساعتی/GPU از داده واقعی انتخاب شدند؛ تقویم برای آن‌ها search volume یا تعداد فروش آینده نمی‌سازد. صفحات نمونه سوئد یا کشور فاقد عرضه، فقط به‌خاطر رتبه تاریخی در تقویم فروش قرار نمی‌گیرند.
