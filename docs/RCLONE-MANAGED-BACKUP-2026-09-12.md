# ServerNet Backup Gateway — طرح فضای بکاپ مدیریت‌شده — 2026-09-12

## نتیجه و محدوده

کنترل‌پنل ServerNet اکنون یک تأمین‌کنندهٔ `rclone_storage` دارد که tenantهای
SFTP، WebDAV و S3-compatible را روی Gateway مستقل ایجاد، بازیابی، تعلیق و
بازنشسته می‌کند. هیچ حساب
Google، OAuth token یا نام backend به پنل یا مشتری داده نمی‌شود. این تغییر هنوز
روی شبکهٔ تولید مستقر نشده و محصولی نباید به این Server متصل شود.

فاز اول فقط این پلن‌ها را می‌پذیرد: 100GB، 500GB و 1TB. پلن‌های 5TB و 10TB به
عمد نگاشت نشده‌اند. هیچ پلن دانلود عمومی از این مسیر تحویل نمی‌شود. S3 تا
پایان آزمون سازگاری با برچسب beta باقی می‌ماند، چون `rclone serve s3` در مستند
رسمی هنوز Experimental است.

## اجزا و جریان

1. فروشگاه محصولی را که `server_id` آن به یک Server از نوع `rclone_storage`
   اشاره دارد ثبت می‌کند.
2. پنل با شناسهٔ قطعی `sn-svc-{service_id}` از Gateway وضعیت را می‌پرسد.
3. اگر وضعیت نامعلوم باشد، ساخت متوقف می‌شود؛ «پاسخ نگرفتیم» هرگز «وجود ندارد»
   محسوب نمی‌شود.
4. درخواست ساخت با HMAC، timestamp و nonce یک‌بارمصرف ارسال می‌شود.
5. Gateway ظرفیت رزروشده را در یک تراکنش کنترل و سپس tenant را ثبت می‌کند.
6. مشتری endpointهای ServerNet، username/password و access key مربوط به S3 را می‌گیرد.
7. rclone auth-proxy هر کاربر را به مسیر رمزنگاری‌شدهٔ اختصاصی او می‌فرستد؛
   یک credential قابل‌چرخش برای SFTP/WebDAV و S3 استفاده می‌شود، ولی مقدار خام
   آن در دیتابیس Gateway ذخیره نمی‌شود.
8. SFTP/WebDAV محتوای `backup/` را نشان می‌دهند و همان مسیر در S3 یک bucket
   با نام `backup` است؛ بنابراین فایل‌ها بین سه پروتکل مشترک‌اند.

هر rclone serve حافظهٔ فهرست مستقل دارد؛ تغییری که از پروتکل دیگری ایجاد شده
ممکن است تا حداکثر `dir-cache-time` فعلی (یک دقیقه) دیرتر در نشست قبلی دیده شود.
خود فایل در backend نوشته شده و نشست تازه آن را بلافاصله می‌بیند. کاهش این زمان
بار API گوگل را زیاد می‌کند و باید فقط پس از اندازه‌گیری انجام شود.

## جلوگیری از ضرر

- Gateway بیشتر از `SN_CAPACITY_BYTES - SN_RESERVE_BYTES` ظرفیت تعهد نمی‌دهد.
- پنل هزینه ماهانهٔ Server را روی ظرفیت قابل‌فروش تقسیم می‌کند و حاشیه حداقل
  `RCLONE_STORAGE_MIN_MARGIN_PCT` را روی خرید و تمدید نگه می‌دارد.
- مقدار پیش‌فرض ذخیرهٔ اطمینان 20٪ و حاشیه سود 20٪ است.
- تا وقتی ظرفیت یا هزینه ماهانه در تنظیمات کامل نشده باشد، محصول نباید فعال شود؛
  نبود کف عددی به معنای رایگان‌بودن زیرساخت نیست.
- به دلیل سقف‌های روزانه و نبود SLA فروش سازمانی در حساب مصرف‌کننده، این 10TB
  نباید معادل 10TB قابل‌فروش فرض شود.

## امنیت و چرخه عمر

- API مدیریت روی 127.0.0.1:9080 می‌نشیند و باید فقط از مسیر خصوصی یا reverse
  proxy دارای TLS و allowlist آی‌پی پنل قابل دسترسی باشد.
- HMAC secret حداقل 32 کاراکتر است و در فیلد رمزنگاری‌شدهٔ API Token پنل و env
  با مجوز 0600 نگهداری می‌شود.
- credential مشتری با HMAC از seed مستقل و نسخهٔ قابل‌چرخش مشتق می‌شود؛ مقدار
  خام در دیتابیس Gateway نیست و در پنل داخل ستون encrypted سرویس قرار می‌گیرد.
- تعلیق فقط ورود را می‌بندد و داده را حذف نمی‌کند.
- خاتمه tenant را 30 روز قرنطینه می‌کند. پاک‌سازی فیزیکی پس از مهلت، تا زمان
  نوشتن و آزمودن job پاک‌سازی، دستی و دومرحله‌ای باقی می‌ماند.
- کلید rclone crypt باید خارج از Gateway نسخه پشتیبان رمزگذاری‌شده داشته باشد.

## شبکه، فایروال و پایداری

هنوز هیچ ماشین، route، NAT یا قانون firewall در تولید تغییر نکرده است؛ بنابراین
`NETWORK-CURRENT.md` در این commit تغییر نمی‌کند. هنگام استقرار باید موارد زیر
با وضعیت زنده و عامل‌های reconcile شبکه هماهنگ و سپس همان فایل به‌روزرسانی شود:

- IP و VLAN ماشین Gateway و مسیر خروجی آن به Google؛
- رکورد DNS عمومی SFTP؛
- پورت SFTP عمومی `2022/tcp` فقط برای مشتریان؛ WebDAV و S3 روی loopback و پشت HTTPS؛
- مسیر API مدیریت 9080 فقط از پنل، ترجیحاً روی شبکه خصوصی؛
- persistence دیتابیس SQLite، rclone config، کلید host SSH و cache؛
- مانیتورینگ فضای cache، خطای OAuth، نرخ خطا و ظرفیت متعهدشده.

## اعتبارسنجی الزامی پیش از فعال‌سازی فروش

- تست سلامت API و امضای نامعتبر/replay؛
- ساخت تکراری همان سرویس بدون tenant دوم؛
- آپلود با هر سه پروتکل، دانلود از دو پروتکل دیگر و مقایسه checksum؛
- بازیابی رمز پس از پاسخ گمشده؛
- تعلیق/رفع تعلیق و جلوگیری از احیای tenant بازنشسته؛
- پرکردن سهمیه و مشاهدهٔ بسته‌شدن نشست جدید؛
- قطع یکی از backendها و سنجش رفتار pool؛
- restore واقعی با Restic/Borg، نه فقط مشاهدهٔ فایل؛
- تأیید کتبی نوع اشتراک و مجازبودن استفاده تجاری از ارائه‌دهنده.

## محدودیت‌ها و rollback

سهمیه در نسخه اول نرم است: `reconcile.py` مصرف را دوره‌ای اندازه می‌گیرد و یک
نشست SFTP از قبل باز ممکن است تا اسکن بعدی از سهمیه عبور کند. Google Drive نیز
برای workload چندمستاجری تضمین عملکرد یا SLA این محصول را نمی‌دهد. این backend
باید قابل تعویض با Hetzner/GCS/S3-compatible باقی بماند.

Rollback برنامه: اتصال محصولات به Gateway را قطع کنید، ساخت tenant جدید را
متوقف کنید و سرویس‌های موجود را read-only نگه دارید؛ داده یا دیتابیس حذف نشود.
پس از sync و checksum به backend جایگزین، endpoint مشتری جابه‌جا و تنها پس از
تأیید restore، backend قبلی بازنشسته شود.
