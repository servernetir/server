## رفتار و مرز پذیرش

- جستجو باید دسته‌ها را پشت سر هم و با یک درخواست در جریان ادامه دهد؛ افزودن انبوه درخواست‌های هم‌زمان یا استعلام پرداختی/نوشتنی مجاز نیست. پاسخ قدیمی نباید جستجوی تازه را بازنویسی کند. توقف/تغییر query باید زنجیرهٔ قدیمی را متوقف کند و خطا به حلقهٔ retry نامحدود تبدیل نشود.
- نمایش تدریجی و انیمیشن سبک باید با `prefers-reduced-motion` سازگار بماند؛ نتیجهٔ اصلی، کنترل‌ها و اعلان وضعیت برای صفحه‌خوان/کیبورد در دسترس بمانند. در موبایل سرریز افقی یا جابه‌جایی آزاردهندهٔ صفحه پذیرفته نیست.
- مرتب‌سازی قیمت فقط قیمت مثبت، معتبر و قابل سفارش را عددی مقایسه کند. نتیجهٔ فاقد قیمت یا ناموجود نباید با صفر ساختگی در ابتدای فهرست بنشیند. دوره‌های متفاوت سالانه فرض نشوند؛ مدت معتبر پاسخ حفظ و نبود مدت، «نامشخص» بماند. انتخاب کاربر هنگام رسیدن دستهٔ تازه حفظ شود.
- API، `cart_url` و رفتار رجیسترارِ نصب‌شده حفظ می‌شوند. نام تأمین‌کننده و بهای خرید/حاشیهٔ سود خصوصی به پاسخ عمومی اضافه نشوند. نبود شاهد تخفیف، مجوز ساخت قیمت خط‌خورده نیست.

پیاده‌سازی رابط، نام انتخابی را نخست و سپس صف یکتای پسوندها را با `tlds: [single]` و نامِ بدون پسوند به API فعلی می‌فرستد؛ در غیر این صورت API قدیمی پسوند اصلی را به هر درخواست اضافه می‌کرد و دوباره استعلام می‌زد. بین پایان هر پاسخ و شروع بعدی دست‌کم۱۸۰۰میلی‌ثانیه فاصله است. زمان درخواست۳۵ثانیه، توقف روی خطا، رعایت کامل `Retry-After`، مکث برگهٔ مخفی و کنترل توقف/ادامه وجود دارند. نتیجهٔ اصلی از تطبیق نام کامل سنجاق می‌شود؛ ورودی اصلی در عنوان و URL می‌ماند.

مرتب‌سازی در نوار مستقل بالای فیلترهاست و با هر نتیجهٔ تازه دوباره اعمال می‌شود. ردیف‌های قبلی node خود را حفظ می‌کنند؛ افکت محوشدن۲۶۰میلی‌ثانیه‌ای فقط کلاس موقت ردیف تازه است و برای reduced motion اجرا نمی‌شود. به‌روزرسانی انقضای تخفیف، کل فهرست را بازسازی نمی‌کند. این ادامه controller/service یا زمان‌بند را تغییر نمی‌دهد.

## بستهٔ انتشار محدود

[engine و launcher بررسی‌شده](domain-ui-release-20261102/README.md) بدون تغییر کد برای این ادامه کافی‌اند. محدوده همان هفت منبع/۹ مقصد است:

| گروه | مقصد نسبت به home |
|---|---|
| خانه | `servernet_app/resources/views/pages/home.blade.php` |
| دامنه | `servernet_app/resources/views/pages/domain-search.blade.php` |
| سه ترجمه | `servernet_app/lang/{fa,en,tr}/domain-discovery.php` |
| JavaScript مستقل | `servernet_app/public/assets/js/domain-home-discovery.js` و `public_html/assets/js/domain-home-discovery.js` |
| CSS مستقل | `servernet_app/public/assets/css/domain-home-discovery.css` و `public_html/assets/css/domain-home-discovery.css` |

تمام۹ مقصد و دو compiled view کنترل می‌شوند، اما فایل با `before_sha256 === after_sha256` دوباره نوشته نمی‌شود؛ compiled یکسان، mtime و mode خود را هم حفظ می‌کند. OPcache مرحلهٔ apply فقط مسیرهای PHP/compiled واقعاً تغییرکرده را هدف می‌گیرد. شمار فایل‌های نوشته‌شده از `files_written`/`compiled_written` رسید گرفته شود، نه از عدد۹ مقصد بررسی‌شده.

نسخهٔ خام خانه در Git با کاندید زنده تفاوت حساب‌شده دارد: محافظ‌های `IranSalesVisibility` بیرون بخش دامنه حفظ شده‌اند. اگر خانه در این ادامه تغییر ندارد، content همان بایت‌های نسخهٔ زندهٔ پذیرفته‌شده در payload باشد؛ کپی کور فایل Git ممنوع است. فایل‌های مشترک `site.js`، `site.css`، `site.min.css`، layout، controllerها، سرویس‌ها، routeها، config و کرون خارج بسته‌اند.

## چرخش stage و پشتیبان‌ها

آماده‌سازی مرحله‌های۱تا۴ انجام شد: inventory خام و verify مرحلهٔ قبلی۹فایل/دو compiled را تأیید کردند؛ هر شش URL عمومی قبل از تغییر با BYPASS پاسخ۲۰۰ دادند. آرشیو اولیه حفظ شد و stage اصلاح دوره به `domain-ui-release-20261102-before-auto` منتقل شد. stage تازه با mode۰۷۰۰، engine/payload۰۶۰۰ و UID۱۰۲۰ آماده است. خانه/assetها همان بایت‌های نصب‌شده‌اند؛ فقط view دامنه و سه ترجمه در کاندید تغییر دارند. مرحلهٔ۵ زیر هنوز اجرا نشده است.

1. پیش از هر تغییر، verify و inventory خام احرازشدهٔ آخرین مرحله، وضعیت `verified` و نبود launcher فعال/عملیات نیمه‌تمام بررسی شود. UID حساب و modeهای واقعی دوباره ثبت شوند. رسید قبلی UID۱۰۲۰، خانه۰۶۴۴، دامنه۰۶۰۰، وابستگی‌ها۰۶۴۴ و compiled موجود۰۷۵۵ را ثبت کرده است؛ این مقادیر را پیش از نصب بعدی مفروض نگیرید.
2. پشتیبان اولیهٔ `domain-ui-release-20261102-initial` دست‌نخورده بماند. stage ثابتِ فعلی `domain-ui-release-20261102` شامل پشتیبان اصلاح دورهٔ ثبت است؛ پیش از استفادهٔ دوباره، **تمام پوشه** شامل `engine.php`، `payload.json`، `state.json`، `before/` و کاندیداها به نام خصوصیِ یکتای هنوزموجودنبوده، مانند `domain-ui-release-20261102-before-auto`، منتقل شود. وجود مقصد یا drift، توقف می‌آورد؛ آرشیو قبلی بازنویسی/ادغام/حذف نشود.
3. stage تازه با همان مسیر ثابت، mode۰۷۰۰ و مالک تأییدشده ساخته شود. engine/payload خصوصی و بدون راز باشند. payload جدید هر۹ مقصد را یک‌بار با `before` برابر وضعیت **فعلیِ نصب‌شده** و `after` برابر کاندید این ادامه ثبت کند؛ mode موجود حفظ شود. کد جدید engine لازم نیست.
4. SHA-256 بایت‌های واقعی engine و payload تازه در launcher جدید و یکتا pin شود. launcher پس از فایل‌های خصوصی منتقل شود و پس از verify و پذیرش مرورگر فوراً از webroot خارج گردد. نام‌های قبلیِ launcher نباید دوباره در دسترس عمومی قرار گیرند. نشست واقعی مدیر، CSRF و سه قفل موجود انتشار حفظ شوند.
5. GET ابزار فقط inventory محدودِ خام را می‌دهد؛ سپس `preview` پنج lint خصوصی و قبل‌هش‌ها را بررسی می‌کند. پس از موفقیت همان preview، `apply` و `verify` با همان payload pin اجرا شوند. موفقیت HTTP به‌تنهایی پذیرش رابط نیست.

**هش خام الزامی است:** Fileman در خواندن متن HTML/CSS قبلاً charset metadata را تغییر داده بود؛ خروجی تبدیل‌شدهٔ آن، قبل‌هش نیست. inventory احرازشدهٔ engine باید `hash_file`/size/mode/UID واقعی هر۹ مقصد و همان۷ protected فعلی را تأیید کند. حفاظت‌ها برای عبور از mismatch حذف نشوند.

## خطرهای قابل پیشگیری

- بهینه‌سازی فایل یکسان در engine فعلی برای **apply** است. مسیر rollback با کنترل کامل hash/mode می‌تواند نسخهٔ قبلِ هر۹ مقصد/دو compiled را بازنویسی کند؛ آن را rollback تک‌فایل یا حفظ mtime فایل‌های یکسان معرفی نکنید.
- state قدیمیِ `verified` برای payload تازه قابل استفاده نیست؛ engine هم payload pin و هم duplicate apply را رد می‌کند. حذف state برای دورزدن این گارد به‌جای آرشیو کامل مجاز نیست.
- engine مسیر stage را ثابت دارد. اجرای مستقیم engineِ آرشیوشده، آن را به آرشیو متصل نمی‌کند. برای rollback مرحله‌ای، stage و payload همان مرحله باید با همان کنترل‌ها به مسیر ثابت برگردند.
- compiled۰۷۵۵ فقط وقتی مجاز است که از قبل وجود داشته و دقیقاً همان mode حفظ شود؛ compiled جدید۰۶۴۴ است. chmod هم‌زمان با preview/apply/rollback باید توقف ایجاد کند؛ مجوزها برای آسان‌کردن انتشار گسترده نشوند.
- engine فقط۱۲ کلید PageCache همین دو صفحه/سه زبان/دو base URL را باطل می‌کند. `cache:clear`، `opcache_reset`، پاک‌کردن config/route، migration و اجرای دستی scheduler جزو این کار نیستند.
- ادامهٔ خودکار رابط، خواندن واقعی دامنه‌ها را بیشتر می‌کند؛ یک درخواست در جریان، تقدم query تازه، توقف روی خطا و سقف دستهٔ موجود باید با تست و مشاهدهٔ مرورگر تأیید شود. خود ابزار انتشار هیچ تماس تأمین‌کننده‌ای ندارد.

## آزمون و رسید مورد نیاز

[CI نهایی runtime](https://github.com/servernetir/server/actions/runs/41500448597/job/125466248453) با PHP۸٫۴ و Node۲۲ موفق شد: **۳۴ تست رابط (۲۵دامنه/۹خانه)،۵۰ بررسی native انتشار/بازگشت و۴ بررسی محدوده**؛ صفر شکست/لغو/skip. خانه و دامنه با Blade واقعی در fa/en/tr رندر و سه ترجمه lint شدند. تمرین native ساختگی و بدون مسیر تولید/تماس تأمین‌کننده بود؛ این نتیجه پذیرش نصب نیست. JavaScript syntax، برابری۵۴کلید سه زبان و diff checks محلی هم موفق بودند؛ PHP محلی در دسترس نبود.

بازبینی مستقل، راه دورزدن cooldown با ارسال دوبارهٔ فرم را پیدا کرد؛ `throttleUntil` مشترک اکنون همان query، نام تازه، پیشنهاد نام و زمان‌بندی خودکار را تا پایان کامل `Retry-After` نگه می‌دارد. تست اختصاصی Search/Enter و query تازه در۳۴تست بالا موفق است. انقضای مهلت، خودش درخواست تازه نمی‌فرستد. بازبینی خودکار نیز تغییر هویت `www.com`/`www.net` بر اثر حذف بی‌قید `www.` را پیدا کرد؛ این حذف از جستجو و ایده‌ها برداشته شد. نام `www` و پسوند چندبخشی، دقیقاً مطابق قرارداد backend حفظ و با تست اختصاصی پذیرفته شدند. هر دو thread بازبینی پس از اصلاح و CI موفق resolve شدند.

## توقف انتشار و بستهٔ آماده

ورود به launcher تازه در مرورگر با رد **خودکار بررسی مجوز** متوقف شد: ابزار اعلام کرد اختیار مشاهدهٔ مبدأ جداگانهٔ `https://console.servernet.cloud` برای این درخواست را ندارد. این رد، رد دستی مالک نبود. مسیر جایگزین برای ورود به همان حساب اجرا نشد. **preview/apply/verify بستهٔ تازه انجام نشده، چهار فایل کاندید و compiled تولید نوشته نشده و عملکرد رابط تازه در مرورگر زنده هنوز تأیید نشده است.** نسخهٔ منتشرشدهٔ قبلی همچنان وضعیت نصب‌شده است.

- payload آماده: `db558562954f7203071c575cb570594979ab2e1df6b6ebb0a3380fb036e215b6`
- engine بدون تغییر: `fd6f40607b79417e7506a1ef5eb398711061607b6ac153f83bb1435a2b86e352`
- launcher کاندید pin‌شده: `fd85c144adc627e8d17c94d4179464c19bea5725befe02d1a566f27cc985ab41`
- [manifest آماده‌سازی بدون content/راز](domain-auto-discovery-prepared-20261102.json)

هر دو launcher تازهٔ `…-auto-inventory.php` و `…-auto.php` از webroot به stageهای خصوصی منتقل شدند؛ پاسخ۴۰۴ هر دو با درخواست عمومی بدون دنبال‌کردن redirect تأیید شد. اعتبارنامه فقط در حافظهٔ نشست انتقال استفاده شد؛ فایل توکن محلی ساخته نشد. هیچ خرید/ثبت/تمدید/انتقال، migration، job، flush عمومی یا تغییر backend/config انجام نشد.

هش‌های بالا pin کاندید محلی‌اند؛ تطبیق خام بستهٔ بارگذاری‌شده با pin باید در preview مجاز بعدی تأیید شود.

ادامهٔ لازم پس از اجازهٔ مشخص مالک برای استفاده از نشست فعلی همین پنل: inventory خام تازه و کنترل drift، launcher با همان pin، preview/lint، apply، verify و پذیرش واقعی. پذیرش باید رشد خودکار ردیف‌ها بدون کلیک، مرتب‌سازی هم‌زمان، سه زبان، موبایل/RTL/LTR، نبود خطای console و کاهش حرکت را بسنجد. آمار CI را به‌جای این پذیرش گزارش نکنید.

## بازگشت

چون نصب تازه انجام نشده، rollback فایل تولید فعلاً لازم نیست. پس از نصب مجاز بعدی، ابتدا rollback همین ادامه، با قبل‌هش‌های نسخهٔ نصب‌شدهٔ قبلی و modeهای دقیق، انجام شود. source و compiled قدیمی پیش از حذف وابستگی تازه فعال می‌شوند؛ فایل یکسان یا تغییر جدیدتر نباید کور بازنویسی شود. برای برگشت فراتر، پس از تأیید rollback این مرحله، stage اصلاح دوره و سپس stage اولیه به‌ترتیب با payload/engine خودشان و مسیر ثابت استفاده شوند. پشتیبان‌های دو مرحلهٔ پیشین تا پایان پذیرش حفظ شوند. بازگردانی کل اپ یا دیتابیس لازم نیست و مجاز این بسته نیست.
