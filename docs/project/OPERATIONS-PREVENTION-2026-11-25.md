# Preventive operational health — 25 November 2026

This change extends the existing native health job. It does not add a second scheduler or modify purchase, settlement, provisioning, deletion, or sales-eligibility decisions.

- Observe actual filesystem headroom with lightweight operating-system statistics. Warn before critical disk pressure; file-backed public HTML cache inserts stop at critical or unavailable readings while valid cached copies and ordinary response rendering remain available. The expired cache cleaner stays scoped to genuine expired entries. Disk-only notices belong to the central health watcher; abnormal cache growth retains its existing independent signal.
- Persist private, small run receipts for the full scheduled release gate, coordinated FX refresh, domain catalogue refresh, and actual file-cache prune. A start is not a completed run. Missing, failed, stale, or interrupted runs appear in health reporting. Limited gate samples and dry-run pruning cannot certify the corresponding full job. Bulk release-gate HTML inspection bypasses page caching in-process; only the dedicated cache samples explicitly enable it.
- Track observed incident state separately from notification attempts. New critical changes notify immediately; warnings previously deferred by throttling remain eligible. Persistent failures and warnings receive bounded reminders. Optional stable impact digests make a real change in affected scope visible without storing raw detail or creating an alert per record. Existing owner-selected notification cadence and dedicated GPU monitor ownership are preserved.
- Detect partial catalogue quarantine while independently verified peer plans remain sellable. Only local, already-verified price snapshot data are inspected; intentionally disabled offers and full supplier outages are not treated as partial incidents. A quarantine warning never overrides the pricing or availability guard.

Acceptance: run the relevant isolated Laravel regression tests, verify the existing schedule contains one full nightly gate with its receipt flag, verify the health checks and file-backed cache behavior, then record the exact reviewed production hashes and observed natural receipts. A sample gate is evidence for the inspected pages only; the next scheduled full receipt establishes full-run freshness. Preserve prior health state during rollout and rollback; do not fabricate successful receipt timestamps.
