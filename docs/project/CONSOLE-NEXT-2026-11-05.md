# کنسول موازی مشتری — ۵ نوامبر ۲۰۲۶

**وضعیت: آماده‌سازی و آزمون محلی؛ روی تولید نصب یا تأیید نشده است.** مالک انتشار یک رابط مستقل برای آزمون زنده را خواسته و تصریح کرده پنل فعلی فعال بماند. جایگزینی پیش‌فرض، پس از تأیید نهایی مالک، کار جداگانه است؛ این بسته فرمان ارتقای خودکار به پنل پیش‌فرض ندارد.

مرجع پایه `develop` در `e133689778abfb3abbd8579965ecd938216a181c` است. checkout ایزوله از `b57153194c5723f4cc1dde3e889b7882758aaca1` آغاز و با تازه‌ترین develop همگام شد؛ اختلاف این دو SHA فقط یک مستند هرمس بود و بایت‌های منابع برنامه در این بازه تغییر نکردند. SHA نهایی، شناسهٔ بسته و رسید تحویل هنگام بسته‌بندی ثبت می‌شوند؛ وضعیت Git، نصب فایل و پذیرش تولید از یکدیگر مستقل‌اند.

## دامنهٔ تغییر

مقصد آزمایش پس از نصب و فعال‌سازی، `https://console.servernet.cloud/account/next` و نسخه‌های `/en/account/next` و `/tr/account/next` است. این نشانی‌ها هنوز لینک زندهٔ تحویل‌شده نیستند. `/account` و نسخه‌های زبانی آن همان پنل فعلی می‌مانند؛ انتخاب رابط در همان درخواست است و کوکی یا نشست، پنل پیش‌فرض را عوض نمی‌کند.

| قسمت | رفتار آماده‌شده |
|---|---|
| مسیرها و داده | همان تعریف مسیر مشتری دو بار ثبت می‌شود: ۱۳۷ مسیر در هر زبان، ۴۱۱ جفت اصلی/جدید. کنترلر، ترتیب محافظ‌های موجود، throttle، محدودیت پارامتر و model binding حفظ می‌شوند. DNS، AI، احراز هویت، مدار، عودت و منوهای وابسته به نقش از کد جاری می‌آیند. |
| پوسته | `panel.next` با CSS و JavaScript اختصاصی؛ کارت‌های شیشه‌ای، هدر سایت، منوی واحد موبایل، ناوبری پایین، جست‌وجوی مسیرهای واقعی، تم مشترک و کرهٔ هماهنگ با تم. محتوای هر صفحه فقط یک بار رندر می‌شود. |
| عملیات | فرم‌ها، CSRF، تأییدها، داده‌های حساب، تیکت، خرید و noVNC واقعی همان قرارداد قبلی را دارند. اسکریپت‌ها و داده‌های ساختگی پیش‌نمایش قبلی در این رابط بارگذاری نمی‌شوند. گفتگوی موجود سایت نیز حفظ شده است. |
| پیوندها | `lroute()` در درخواست جدید، مسیرهای حساب را در همان رابط نگه می‌دارد؛ ریدایرکت‌های داخلی هم‌مبدأ نیز تطبیق می‌یابند. اعلان مالی، نشانی پایدار پنل اصلی را می‌فرستد. پیوند صریح بازگشت به صفحهٔ متناظر پنل فعلی وجود دارد. |
| حفاظت | پیش‌فرض خاموش؛ ورود و محدودیت حساب/IP، مالکیت، CSRF، پاسخ خصوصی/no-store/noindex و محدودیت دقیق CSP کنسول حفظ می‌شوند. |

Callbackهای پرداخت در `/payment/*` تغییر نکرده‌اند و ممکن است کاربر را به صورت‌حساب معمول پنل فعلی برگردانند؛ بازگشت به رابط جدید از نشانی مستقل آن ممکن است. این رفتار به معنی انتقال پنل پیش‌فرض نیست. انتخابگرها در رابط جدید به شکل native و با حفظ مقدار/اعتبارسنجی فرم ارائه می‌شوند.

بستهٔ هدف ۱۹ منبع دارد: ۱۲ فایل جدید و هفت فایل مشترک محدود. manifest تولیدشده فهرست و hash نهایی را تعیین می‌کند. فایل‌های مشترک شامل مسیرها، helper، bootstrap، CSP، انتخاب layout و دو اصلاح تک‌خطی پیوند اعلان/صورت‌حساب سرور هستند. schema، migration، سیاست مالی، provider، زمان‌بند و تنظیمات واقعی حساب تغییر ندارند.

## فعال‌سازی مستقل

`config/console-next.php` پیش‌فرض `CONSOLE_NEXT_ENABLED=false` دارد. فایل خصوصی `storage/app/console-next.state` با مقدار دقیق `enabled` یا `disabled` بر config اولویت دارد؛ مقدار نامعتبر، فایل ناخوانا یا symlink، رابط جدید را خاموش نگه می‌دارد.

```bash
/opt/cpanel/ea-php84/root/usr/bin/php artisan console-next:enable
/opt/cpanel/ea-php84/root/usr/bin/php artisan console-next:disable
```

این فرمان‌ها فقط وضعیت خصوصی رابط جدید را با نوشتن اتمی عوض می‌کنند. به دیتابیس، job، cache یا `.env` دست نمی‌زنند و پنل اصلی را غیرفعال نمی‌کنند. فرمان‌ها و نصب‌کننده از قفل مشترک `storage/app/.console-next-release.lock` استفاده می‌کنند تا فعال‌سازی وسط نصب انجام نشود.

## آزمون‌های اجراشده

- **۲۱ تست PHP / ۴۱۱۷ assertion، exit 0**: برابری هر ۴۱۱ جفت مسیر، ورود مهمان و intended URL سه‌زبانه، مالکیت، CSRF، ثبت تیکت با منابع ساختگی، سفارش ماهانهٔ پرداخت‌نشده، پیوند اعلان پایدار، ریدایرکت، cache خصوصی، کنسول/توکن یک‌بارمصرف/CSP و قفل فعال‌سازی.
- **۱۸ تست نصب‌کننده موفق**: پیش‌بررسی بدون نوشتن، رد اختلاف hash/مسیر ناامن/تغییر هم‌زمان، قفل مشترک، وضعیت disabled، نصب محدود، رسید خصوصی و بازگشت محافظت‌شده.
- **رگرسیون موجود: ۷۴ تست، ۷۱ موفق، ۶۰۲ assertion و سه شکست baseline**. همان سه شکست در snapshot دست‌نخوردهٔ `b5715319` بازتولید شدند: `AccountSectionsTest::test_no_section_blade_contains_a_style_block` به علت `crypto-pane` و دو تست `ImpersonateBannerTest::test_nothing_leaks_when_not_impersonating` و `test_clicking_the_bar_button_really_returns_the_admin`. این شکست‌ها حذف یا اصلاح جانبی نشدند.
- **مرورگر: ۱۱۵۰ assertion / ۱۲۶ رندر موفق**؛ ۲۱ نمای واقعی × سه زبان × دو اندازه. منو، اسکرول کشو، Escape، جست‌وجو، چت موجود، پیکسل واقعی کره در دو تم و فاصلهٔ نوار خرید/ناوبری بررسی شدند؛ خطای JavaScript، درخواست غیرمنتظره یا عملیات نوشتنی ثبت نشد. بازبینی مستقل برنامه و نصب‌کننده نیز انجام شد و یافته‌های مسدودکنندهٔ ثبت‌شده اصلاح شدند.

گزارش‌های این نشست در `/workspace/artifacts/servernet-redesign/live-candidate/` هستند: `php-next-test.json`، `php-existing-regression.json`، `php-pristine-baseline.json`، fixtureهای ساختگی و `browser/results.json`. fixtureها از پاسخ کنترلرهای واقعی با دیتابیس تست ساخته شده‌اند؛ دادهٔ مشتری تولید نیستند و در بستهٔ نصب قرار نمی‌گیرند. این نتایج ادعای اجرای کل suite، سازگاری تازهٔ MariaDB یا پذیرش تولید نیستند.

## مانع انتشار فعلی

در محیط این نشست، اعتبارنامه/هویت/دسترسی سرور یا cPanel تنظیم نشده است. درخواست HTTPS به مقصد پیش‌بینی‌شدهٔ `/account/next` و اتصال GitHub API در proxy با `CONNECT 403` رد شدند؛ این پاسخ وضعیت خود سایت را اثبات نمی‌کند. میزبان cPanel و روش دسترسی امن از مالک درخواست شده و هنوز مشخص نیست. هیچ راز، `.env` تولید یا دادهٔ مشتری خوانده نشده و نصب، فعال‌سازی یا آزمون حساب زنده انجام نشده است.

## بسته و نصب محدود پس از اتصال دسترسی

مرجع عمومی انتشار، [DEPLOYMENT](DEPLOYMENT.md) است. ساخت محلی بسته، آپلود یا فعال‌سازی نیست:

```bash
python3 -B tools/build-console-next-release.py
```

خروجی در `/workspace/artifacts/servernet-redesign/live-candidate/` شامل ZIP، manifest، patch و SHA-256 است. ZIP فقط نصب‌کننده و منابع مصوب را دارد؛ `.env`، vendor، تست، مستند، storage، upload و `public/index.php` در payload نیستند. مقصد اپ `/home/servernetcloud/servernet_app` و مقصد مستقل دارایی عمومی `/home/servernetcloud/public_html` است؛ وجود این مسیرها و نسخهٔ PHP باید روی همان میزبان تأیید شود.

بسته و نصب‌کننده را در پوشهٔ خصوصی خارج از هر دو ریشه قرار دهید. پیش از نوشتن، هماهنگی انتشار، SHA-256 بسته و hash مقصدها بررسی شود. autoloader تولید باید امکان PSR-4 برای کلاس‌های تازه داشته باشد؛ فقط مقدار `isClassMapAuthoritative()` را بدون bootstrap یا نمایش config/راز بسنجید. اگر authoritative باشد، پیش از نصب طرح autoload سازگار لازم است؛ helper مشترک را با کلاس غیرقابل بارگذاری فعال نکنید.

فرمان‌های زیر از پوشهٔ خصوصی بسته‌اند؛ نبود `--apply` یعنی فقط‌خواندنی:

```bash
python3 installer.py --prepare-disabled \
  --app-root /home/servernetcloud/servernet_app \
  --webroot /home/servernetcloud/public_html

# فقط برای اولین نصب و marker غایب؛ وضعیت enabled/نامعتبر را بازنویسی نمی‌کند.
python3 installer.py --prepare-disabled --apply \
  --app-root /home/servernetcloud/servernet_app \
  --webroot /home/servernetcloud/public_html

python3 installer.py --archive console-next-release.zip \
  --app-root /home/servernetcloud/servernet_app \
  --webroot /home/servernetcloud/public_html \
  --backup-root /home/servernetcloud/console-next-releases
```

پس از پیش‌بررسی موفق، همان فرمان archive با `--apply` نصب بایت‌ها را انجام می‌دهد. اختلاف ناشناختهٔ فایل زنده با hash پایه، ادامهٔ نصب را متوقف می‌کند؛ کد همکار با snapshot قدیمی جایگزین نشود. نصب، فایل‌های جدید را پیش از adapterهای مشترک و مسیرها قرار می‌دهد و رسید/پشتیبان خصوصی می‌سازد. وضعیت رابط باید در تمام نوشتن‌ها `disabled` بماند.

سپس route cache مؤثر، کامپایل محدود Bladeهای تغییرکرده و وضعیت واقعی OPcache وب بررسی و فقط فعال‌سازی مرتبط انجام شود. نصب‌کننده هیچ cache یا FPM را پاک/بازنشانی نمی‌کند. `optimize:clear` پیش‌فرض نیست؛ reset در CLI نیز اثبات reset پردازش وب نیست. مقدار تاریخی `validate_timestamps=0` را وضعیت امروز فرض نکنید. پس از تأیید بارگذاری منابع/مسیرهای جدید، فرمان `console-next:enable` اجرا و ورود محلی‌سازی‌شده، مسیر فعلی، پاسخ خصوصی و CSS عمومی در میزبان واقعی بررسی شوند. پذیرش تعاملی نهایی با حساب مالک و محدودهٔ آزمون مصوب انجام می‌شود؛ هنوز چنین پذیرشی ثبت نشده است.

## بازگشت

ابتدا `console-next:disable` اجرا شود؛ `/account` فعال می‌ماند. رسید خصوصی همان نصب را به کار ببرید:

```bash
python3 installer.py --rollback /ABSOLUTE/PRIVATE/RECEIPT/receipt.json \
  --app-root /home/servernetcloud/servernet_app \
  --webroot /home/servernetcloud/public_html \
  --backup-root /home/servernetcloud/console-next-releases
```

پس از پیش‌بررسی موفق، افزودن `--apply` فقط فایل‌های مشترک تغییرکردهٔ همان رسید را با کنترل hash نصب‌شده بازمی‌گرداند؛ تغییر جدیدتر را بازنویسی نمی‌کند. فایل‌های افزوده‌شده باقی می‌مانند و با مسیر/حالت غیرفعال مصرف نمی‌شوند. فعال‌سازی runtime مرتبط پس از بازگشت نیز باید جدا بررسی شود. این بازگشت فایل است و تغییری در تراکنش‌ها یا داده‌های واقعی انجام نمی‌دهد.
