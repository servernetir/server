# کارت‌های سیستم‌عامل و برنامه آماده — ۱۸ اکتبر ۲۰۲۶

## دامنه و وضعیت

درخواست مالک: بازطراحی بخش انتخاب سیستم‌عامل/برنامه آماده صفحه `account/cloud-store` با کارت و انتخاب نسخه، با الهام از Aeza و ظاهر مدرن متناسب با سرورنت. مبنای شاخه `codex/cloud-store-image-cards-20261018`، commit `4f49732e` است؛ این مبنا تغییرهای سیاست استرداد و حذف توضیح آن از فرم خرید را هم حفظ می‌کند.

وضعیت فعلی: **منبع و پیش‌نمایش آماده؛ هنوز در تولید نصب نشده**. نشست اولیه cPanel پس از تغییر IP خارج شد. مالک در مرورگر داخلی دوباره وارد شد و hash فایل‌های فعال خوانده شد؛ پیش از آپلود، اتصال WebSocket قطع و سپس cPanel صراحتاً «session cookie invalid» اعلام کرد. ورود مجدد از مالک خواسته شد. بسته نصب هنوز به تولید منتقل نشده است.

## رفتار نهایی منبع

- بهبود تدریجی با JS مستقل: یک کارت برای هر خانواده، لوگوی خودمیزبان، علامت انتخاب و منوی بومی نسخه برای خانواده دارای چند نسخه قابل‌نصب. خانواده‌های عمومی از روی نام عمومی تصویر تفکیک می‌شوند؛ برچسب زیرساخت به کارت منتقل نمی‌شود.
- رادیوهای اصلی و شناسه‌های واقعی سفارش حفظ می‌شوند. selectها name ندارند؛ تغییر نسخه همان رویداد change ورودی اصلی را اجرا می‌کند. نام کامل مانند Ubuntu 24.04 به برگه سفارش می‌رود.
- سازگاری با پلن از همان imageMap موجود می‌آید؛ نسخه ناموجود پنهان/غیرفعال و کارت کاملاً ناموجود پنهان می‌شود. GPU و قرارداد برنامه/ظرفیت آن مستقل و دست‌نخورده می‌مانند.
- انتخاب/مقایسه نسخه باعث اسکرول خودکار به مرحله بعد نمی‌شود؛ دکمه «ادامه» اقدام صریح برای نام‌گذاری است. دکمه‌های تازه type=button هستند و خریدی ثبت نمی‌کنند.
- چیدمان سه‌ستونه دسکتاپ، دو ستون در عرض مناسب موبایل و یک ستون در فضای بسیار باریک؛ رنگ‌های موجود dark/light، فوکوس صفحه‌کلید، نام قابل‌دسترسی select و کاهش حرکت رعایت شده‌اند.
- بدون JS یا در صورت بارگیری‌نشدن asset، رادیوهای قبلی قابل استفاده‌اند. منطق سفارش، قیمت، صورتحساب، ارائه‌دهنده، ظرفیت، کاتالوگ و سیاست استرداد تغییر نمی‌کنند.

فایل‌های اجرا: `website/public/assets/js/cloud-image-cards.js`، افزودنی محدود `public/assets/css/panel.css`، اتصال قالب `resources/views/account/cloud-store.blade.php` و چهار کلید ترجمه یکسان در سه `lang/*/ui.php`.

## اعتبارسنجی انجام‌شده

هشت تست Node22.17/jsdom26.1.0 موفق: گروه‌بندی نسخه، حذف گزینه ناسازگار، انتخاب کارت، انتشار change اصلی، FormData با تنها یک شناسه اصلی، جایگزینی نسخه پس از تغییر پلن، ادامه بدون submit/پنهانی در کاتالوگ خالی، برنامه‌ها و حفظ کارت‌های GPU. دستورات در worktree ایزوله:

```powershell
npm install --prefix output/cloud-image-cards-20261018/test-runtime --ignore-scripts --no-audit --no-fund jsdom@26.1.0
$env:NODE_PATH=(Resolve-Path output/cloud-image-cards-20261018/test-runtime/node_modules).Path
node --check website/public/assets/js/cloud-image-cards.js
node --test website/tests/js/cloud-image-cards.test.cjs
```

وابستگی آزمون فقط در پوشه خروجی محلی نصب شد؛ package/lockfile اپ و مسیر build Vite تغییر نکردند. متغیرهای CSS تازه با تعاریف واقعی و توازن آکولادها بررسی شدند.

پیش‌نمایش محلی با markup فقط‌خواندنی فهرست واقعی ایران/ارومیه و همان assetهای منبع بررسی شد: انتخاب Ubuntu24.04 و نمایش خلاصه موفق؛ عرض۳۹۰، دو ستون۱۴۸٫۵پیکسل و بدون overflow افقی (clientWidth=scrollWidth=375). این پیش‌نمایش گواه انتشار تولید نیست. برای این مکان، کاتالوگ برنامه آماده خالی است؛ قابلیت ساختگی به فروش اضافه نشد.

## نصب و بازگشت آماده

میزبان وب `/home/servernetcloud/servernet_app`؛ PHP مجاز `/opt/cpanel/ea-php84/root/usr/bin/php`. `scripts/deploy-cloud-image-cards-20261018.py` شش مسیر ثابت را اجازه می‌دهد، روی متن جاری فقط جایگزینی دقیق انجام می‌دهد، فایل قبل/بعد و hash را در بسته خصوصی نگه می‌دارد و پیش از نصب lint ترجمه/compile قالب را اجرا می‌کند. asset تازه باید قبل از قالب نصب شود؛ همه فایل‌ها پیش و پس از نصب با hash سنجیده می‌شوند. رسید موجود مانع اجرای دوباره apply است. بازگشت فقط با برابر بودن hash جاری و حفظ تغییرهای هم‌زمان انجام می‌شود؛ تنها asset تازه در صورت نداشتن نسخه قبل حذف می‌شود.

پس از نصب، reset رسمی کش/OPcache و بررسی واقعی fa/en/tr، تغییر نسخه و پلن، حالت روشن/موبایل و خطاهای JS لازم است. هیچ سفارش، پرداخت، پذیرش قرارداد، migration، seeder، cron یا عملیات provider برای آزمون مجاز یا لازم نیست. هیچ route، NAT/firewall، DNS، VM یا state عامل شبکه در این تغییر درگیر نیست.
