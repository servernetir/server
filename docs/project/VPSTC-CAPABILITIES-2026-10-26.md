## سه نکتهٔ تعیین‌کننده

**کنسول JWT-only فعلاً مسیر رسمی قابل اتکا ندارد.** قرارداد `console` یک grant یک‌بارمصرف ۶۰ثانیه‌ای، cookie نشست مرورگر موجود، WebSocket همان origin، subprotocol باینری و ارسال token در اولین frame متنی را توصیف می‌کند. token نباید در URL، log یا storage پایدار قرار بگیرد. اعتبارنامهٔ JWT سرویس به‌تنهایی cookie موردنیاز را فراهم نمی‌کند. اشتراک cookie یا حساب مادر با مشتری راه‌حل قابل قبول نیست. برای کنسول سفیدبرچسب، تأمین‌کننده باید grant/SSO مخصوص reseller و قابل صدور با API را تأیید کند؛ سپس broker و WebSocket relay متعلق به ServerNet لازم است. این ممیزی هیچ cookie یا grant واقعی دریافت نکرده است.

**تغییر رمز با بازنشانی اجباری یکی نیست.** `vms_password` فیلدهای `guest_username`, `current_password`, `new_password` و `request_token` دارد. حذف رمز فعلی فقط در حالت ورود ذخیره‌شدهٔ تأییدشده یا ورود پذیرفته‌شدهٔ نصب Cloud توصیف شده است. بنابراین می‌توان adapter مستقل تغییر رمز را طراحی کرد، ولی ادعای «بازیابی هر رمز گم‌شده»، پشتیبانی همهٔ templateها یا هزینهٔ صفر بدون پذیرش واقعی درست نیست. باید task و سپس ورود واقعی مهمان تأیید شود؛ رمز تازه فقط پس از موفقیت جایگزین اطلاعات دسترسی شود.

**نصب مجدد سیستم‌عامل مجوز مالی نامحدود نیست.** فهرست `S/templates` برای سرویس مادر با گزینهٔ OS در فرم خرید دو منبع متفاوت‌اند. باید معلوم شود انتخاب template هزینهٔ لایسنس، backup یا بستهٔ دیگری را تغییر می‌دهد یا خیر. مجوز Windows/cPanel/Plesk و template رایگان نباید در یک گزینهٔ بدون قیمت ادغام شوند. API rebuild در این نسخه token idempotency مستند ندارد؛ timeout مجوز ارسال مجدد خودکار نیست.

## تطبیق هزینهٔ مشتری با تأمین‌کننده

| وضعیت اثبات‌شدهٔ عملیات | رفتار مطلوب ServerNet |
|---|---|
| داخل بسته و بدون هزینهٔ اضافه، با شاهد همان حساب/محصول | عملیات برای مشتری بدون هزینهٔ مستقل؛ اجارهٔ اصلی و سهمیهٔ بسته شفاف بماند. دریافت دوبارهٔ لایسنس/منبع از قبل خریداری‌شده مجاز نیست. |
| هزینهٔ یک‌باره، دوره‌ای یا مصرفی مشخص | قبل از اجرا quote معتبر شامل ارز، قیمت خالص/ناخالص، setup، لایسنس، مالیات تأمین‌کننده و دوره ثبت شود؛ سود و هزینهٔ تبدیل VPS.tc اعمال و مبلغ مشتری پیش از تأیید نشان داده شود. ثبت پرداخت و دفتر یکتا باید پیش از درخواست هزینه‌دار durable شود. |
| بها یا entitlement نامعلوم | «نامشخص/در دسترس نیست/نیازمند بررسی»؛ نه صفر، نه مبلغ فرضی و نه هزینهٔ پیش‌فرض ارائه‌دهندهٔ دیگر. |
| پاسخ async یا timeout | نتیجه در حالت pending/unknown بماند؛ token/receipt ثابت با همان درخواست immutable و تطبیق `S/tasks/{taskid}`؛ تغییر اطلاعات/قیمت/رمز فقط پس از تأیید نتیجه. |

`VpsTcCatalog` فعلاً فقط دورهٔ ماهانه و انتخاب‌های بررسی‌شدهٔ بدون اضافه‌قیمت را می‌پذیرد و تطبیق ارقام فرم/کاتالوگ، ارز و کارمزد را الزام می‌کند. این گاردها باید هنگام افزودن قابلیت‌ها حفظ شوند. رفع ناهماهنگی پاسخ API با حدس ارز، تبدیل رشتهٔ قالب‌بندی‌شده به قیمت، استفاده از نرخ نمایش سایت یا فرض‌کردن `Array` به معنی صفر، مبنای فروش سالم نیست.

`CloudAddons::DEFAULT_EXTRA_IP_COST` و سقف عمومی snapshot سیاست مشترک برنامه‌اند، نه تعرفهٔ VPS.tc. فعال‌کردن `extra_ip` یا `snapshot` به‌تنهایی جریان پرداختِ افزونه، تمدید هزینهٔ جاری یا لغو اجارهٔ آن را کامل نمی‌کند. افزودن مصرف/ذخیره‌سازی بدون این اتصال ممکن است هزینهٔ تأمین‌کننده را بدون صورتحساب مشتری افزایش دهد.

در تطبیق فاکتور، `total` بعد از مصرف اعتبار می‌تواند صفر باشد؛ بهای ناخالص صفر نشده است. `VpsTcInvoiceAmounts` مبلغ `total + credit` را با `subtotal + tax + tax2` و در صورت وجود `grandtotal` تطبیق می‌دهد. سقف خرید/تمدید روی همین ناخالص اعمال می‌شود؛ برداشت تازه فقط به اندازهٔ بدهی مثبتِ بررسی‌شده و با مبلغ صریح است. وضعیت `Paid` همچنان جدا لازم است؛ از صفرشدن `total` موفقیت پرداخت استنتاج نمی‌شود و فیلدهای FX فاکتور بدون قرارداد تبدیل تفسیر نمی‌شوند.

برای ارزِ دقیقاً خالیِ پاسخ balance، `VpsTcMoneyContract` فقط سند بررسی‌شده و رمزنگاری‌شدهٔ همان حساب را می‌پذیرد؛ فاکتور پرداخت‌شده و هویت سرویس مرجع را تازه می‌خواند. قیمت فروش نیز جدا با فرم، کاتالوگ و محاسبهٔ جاری همان محصول تطبیق می‌یابد. این سند نرخ بازار ارز نیست و جای بهای جاری را نمی‌گیرد. ارز غیرخالیِ متعارض، سند مفقود، حساب متفاوت یا مرجع تغییریافته اجازهٔ برداشت نمی‌دهد؛ فاکتور خرید/تمدید همچنان باید ارز و ناخالص مستقل و معتبر داشته باشد.

## دامنهٔ توسعهٔ امن در مرحلهٔ بعد

۱. wrapperهای GET برای `resources`, `traffic`, `tasks` و قابلیت‌های واقعی سرویس، همراه کنترل مالکیت، schema، واحد و دورهٔ داده. این‌ها سفارش/پرداخت/ماشین را تغییر نمی‌دهند. نمودار مصرف فقط وقتی دادهٔ واقعی موجود است؛ مقدار نامعلوم صفر نیست.

خواندن فهرست snapshot/backup باید از مجوز ساخت/زمان‌بندی جدا بماند؛ روشن‌کردن capability مشترک صرفاً برای نمایش فهرست، مجوز مالیِ عملیات نوشتن نیست.

۲. طراحی adapter تغییر رمز مستقل و نصب مجدد، با گیت پیش‌فرض خاموش و تست ساختگی. فعال‌سازی واقعی پس از روشن‌شدن entitlement، هزینهٔ عملیات/لایسنس، سازگاری template و پذیرش روی سرویس دورریختنیِ مجاز. در حال حاضر هیچ عملیات اضافهٔ تغییردهنده‌ای صرفاً بر مبنای این منابع، «هزینهٔ صفر تأییدشده» ندارد.

۳. IP/backup/snapshot/ارتقا پس از quote و مدل مالی مخصوص همان حساب و همان محصول. کنسول پس از قرارداد grant/SSO مناسب reseller. وجود endpoint یا متن بازاریابی جای این مراحل را نمی‌گیرد.

## شواهد و مسیر بازبینی

- **A — API رسمی:** [رابط مستندات](https://portal.vps.tc/userapi/)؛ [Swagger JSON رسمی](https://portal.vps.tc/?cmd=userapi&action=swagger&display=1&redirect=1). نسخه و hash در ابتدای سند ثبت شده‌اند. نام‌های operationId جدول برای جست‌وجوی دقیق در specification هستند؛ examples تعرفه یا شاهد اجرای حساب نیستند.
- **B — محصول و قرارداد عمومی:** [VPS و FAQ](https://www.vps.tc/en/vps)؛ [شرایط سرویس](https://www.vps.tc/en/terms)، به‌ویژه §4.1، §4.4، §6، §12، §13.2، §21 و §22؛ [Cloud](https://www.vps.tc/en/cloud-server) فقط برای مقایسهٔ وعدهٔ طرح Cloud، نه تعمیم به VPS. public VPS خرید اختیاری backup را می‌گوید؛ Terms §13.2 ارائهٔ backup را بدون توافق اضافه الزام نمی‌کند.
- **C — کد واقعی:** `website/app/Services/Cloud/VpsTcApi.php`، `VpsTcClient.php`، `VpsTcCatalog.php`، `VpsTcPricing.php`، `VpsTcRenewal.php`، `CloudOperations.php`، `CloudAddons.php`؛ `website/app/Http/Controllers/Account/CloudServerController.php`. `capabilities()` فعلی VPS.tc برای `console`, `rebuild`, `resize`, `snapshot`, `metrics`, `reset_password`, `ipv6`, `ssh_key`, `extra_ip` همگی false است؛ power بیرون از این فهرست در adapter پیاده شده است.

این سند فقط تطبیق قرارداد عمومی و پیاده‌سازی است. تعرفهٔ اختصاصی حساب، مجوز واقعی هر method، رفتار تغییر رمز/نصب مجدد و بهای افزونه‌ها در تولید توسط این ممیزی آزموده نشده‌اند؛ خروجی خام حساب یا رازها برای اثبات آن‌ها در مخزن عمومی قرار نمی‌گیرند.
