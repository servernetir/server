# برنامه‌های آماده و انتخاب نسخه — ۱۸ اکتبر ۲۰۲۶

وضعیت: منتشر و در فروشگاه زنده بررسی شد. شاخه `codex/ready-apps-animated-versions-20261018`.

## علت و محدوده

فهرست ایران خالی بود چون `ArvanClient::regionImages` فقط `type=distributions` را می‌خواند. API مستقل marketplace در هر پنج منطقه پاسخ موفق داد. ادعای قبلیِ خالی‌بودن آلمان دقیق نبود: پس از اتمام navigation، ۱۲ کارت برنامه موجود بود؛ این مشکل آلمان نبود.

ممیزی اولیهٔ SELECT-only: Aeza دارای ۶۰ ردیف برنامهٔ فعال، Hetzner دارای ۲۴ ردیف فعال، OVH دارای ۵ و Salad دارای ۳ بود. تعداد ردیف با تعداد کارت قابل انتخاب فرق دارد؛ معماری، منطقه و منابع فیلتر می‌شوند. LightNode مسیر نصب و اعتبارسنجی فعلی خود را به `System` محدود می‌کند؛ برای آن برنامهٔ تأییدنشده یا نصاب عمومی اضافه نشد. این تغییر واردکنندهٔ بومی ایران را تکمیل می‌کند و کاتالوگ سایر ارائه‌دهندگان را بازنویسی نمی‌کند.

## آنچه منتشر شد

۹ برنامه در هر یک از پنج منطقه: `ir-southwest1-a`, `ir-tbz-sh1`, `ir-thr-ba1`, `ir-thr-fr1`, `ir-thr-si1`. جمعاً ۴۵ ردیف منطقه‌ای جدید، با ۹ کلید عمومی یکتا. تصویر تکراری BigBlueButton در بعضی پاسخ‌ها بر اساس key در همان منطقه یک‌بار وارد شد.

| برنامه | نسخهٔ اعلام‌شدهٔ ایمیج | CPU | RAM MB | دیسک GB |
|---|---|---:|---:|---:|
| Docker | 26.1.1 | 1 | 1024 | 10 |
| WordPress | 6.2.0 | 1 | 1024 | 20 |
| Node.js | 20.1.0 | 1 | 1024 | 10 |
| LAMP Stack | 8.2.5 | 1 | 2048 | 20 |
| NGINX | 1.24.0 | 1 | 512 | 10 |
| Django | 4.2.1 | 1 | 1024 | 10 |
| GitLab | 14.2.1 | 8 | 16384 | 80 |
| Jitsi Meet | 1.0 | 4 | 8192 | 25 |
| BigBlueButton | 2.4.4 | 8 | 16384 | 50 |

این اعداد، کف محافظه‌کارانهٔ فروش ما هستند؛ هر نیاز بزرگ‌تر اعلام‌شده توسط زیرساخت نیز رعایت می‌شود. اعداد نسخه از metadata همان ایمیج‌اند، نه سنجش باینری داخل ماشین. برخی نسخه‌ها قدیمی‌اند؛ عرضه در API اثباتِ به‌روز بودن، پشتیبانی امنیتی یا آمادگی کامل برنامه پس از boot نیست. ساخت آزمایشی پولی، boot، ورود root و پیکربندی دامنه/ایمیل/برنامه انجام نشد و نباید تأییدشده گزارش شود.

پنل‌های Plesk، cPanel و DirectAdmin اضافه نشدند؛ صفر بودن هزینهٔ ایمیج، وجود مجوز نرم‌افزار را اثبات نمی‌کند. فقط خانواده‌های مشخص، قیمت صفر صریح در سه دوره و امکان رمز SSH پذیرفته می‌شوند؛ دادهٔ ناقص، شناسهٔ نامعتبر یا هزینهٔ نامعلوم/غیرصفر رد می‌شود.

شناسهٔ خصوصی `app:<region>:<image-id>` تنها داخل adapter به UUID بومی همان منطقه تبدیل می‌شود. انتخابگر، کنترل سفارش و `CloudImage::compatibleRefFor` منطقه/CPU/RAM/disk/معماری را رعایت می‌کنند. driver بلافاصله پیش از ثبت create intent، کاتالوگ بومی را دوباره با GET می‌خواند و نیاز منابع تازه را بررسی می‌کند؛ ناهماهنگی پیش از POST پولی متوقف می‌شود. منطق idempotency موجود تغییر نکرد.

واردکنندهٔ دوره‌ای همین مسیر marketplace را همراه سیستم‌عامل‌ها می‌خواند. خطای کاتالوگ منطقه به exception منجر می‌شود تا sync ناقص ردیف‌های مناطق دیگر را غیرفعال نکند؛ هماهنگ‌کنندهٔ موجود خطای هر provider را جدا ثبت می‌کند. هیچ sync عمومی قیمت/پلن برای این انتشار اجرا نشد.

## انتخاب نسخه

سبک مرجع AnimatedSelect کاربر به Blade/JS موجود تطبیق داده شد: منوی لایه‌ای خارج از کارت، ظاهرشدن مرحله‌ای گزینه‌ها، تبدیل فلش به ضربدر، نمایش انتخاب، حرکت با کیبورد، Escape و کلیک بیرون. حالت روشن/تیره و reduced-motion رعایت می‌شوند. React، Tailwind یا بستهٔ runtime جدید اضافه نشد؛ radio اصلی همچنان تنها `image` در payload سفارش است. مرجع سبک: AnimatedSelect از GreatUI / Saurabh Sharma طبق متن ارسالی کاربر.

## انتشار و شواهد

ماشین متاثر فقط میزبان cPanel موجود بود: `/home/servernetcloud/servernet_app` و document root مستقل `/home/servernetcloud/public_html`. چهار فایل PHP برنامه و CSS/JS در هر دو ریشه، مجموعاً ۸ مسیر، با exact substitution، پیش‌شرط hash و پشتیبان خصوصی نصب شدند. CSS عمومی متفاوت با CSS برنامه بود و با patch محدود حفظ شد. guard نهایی فقط ArvanClient را به‌روزرسانی کرد. PHP 8.4 lint برای همهٔ PHPهای مرحله‌بندی‌شده موفق بود؛ وب reset رسمی پاسخ HTTP 200 و `opcache_reset=true` داد و cacheهای config/route/view/application را پاک کرد. hash نهایی هر ۸ مسیر با manifest آخر تطبیق داشت.

پوشه‌های خصوصی، با دسترسی محدود و خارج public root:

- `/home/servernetcloud/ready-apps-20261018/release`: manifest، backupهای هر فایل، receipt نصب، candidate/before/receipt کاتالوگ؛ `deploy.py` و `catalog.php`.
- `/home/servernetcloud/ready-apps-20261018/resource-guard`: manifest و backup تک‌فایل guard، آزمون read-only و receipt نصب.
- `/home/servernetcloud/ready-apps-20261018`: ممیزی اولیه و پاسخ پاک‌سازی‌شدهٔ marketplace؛ فاقد اطلاعات مشتری یا credential در خروجی.

اعتبارسنجی:

- ۱۰ تست رفتاری JS موفق؛ شامل grouping، تغییر پلن، payload اصلی، popup portal، نسخهٔ ناسازگار، کیبورد، Escape، کلیک بیرون و گزینهٔ قدیمی پس از refresh.
- آزمون pure PHP بدون bootstrap/DB: پذیرش ایمیج بومی رایگان، رد مجوز تجاری/قیمت نامعلوم/شناسه و نسخه نامعتبر، مرزبندی منطقه، کلید نسخه و کف منابع؛ `APPLICATION_CONTRACT_PASS`.
- آزمون یکپارچهٔ GET-only روی کد مرحله‌بندی‌شدهٔ نهایی: UUID بومی صحیح؛ منطقهٔ نادرست، RAM/disk ناکافی و CPU کم رد شدند؛ هیچ create intent/POST/سروری ثبت نشد.
- پس از ثبت ۴۵ ردیف، ۷۰ انتخاب قابل نمایش در دو سر طیف منابع هر پنج منطقه با resolver مدل تطبیق داشت: پلن‌های کوچک ۵ و پلن‌های بزرگ ۹ برنامه.
- مرورگر واقعی: ایران ۵ کارت روی 1GB و ۹ روی پلن 8CPU/32GB/150GB؛ Docker انتخاب شد و خلاصه/ radio به همان کلید تغییر کرد؛ آلمان ۱۲ کارت حفظ شد. FA/EN/TR، منوی کیبورد و Escape، روشن/تیره و نمایش باریک بدون overflow بررسی شد. viewport موقت و حالت رنگ قبلی بازگردانده شدند.
- هیچ خرید، پرداخت، نصب روی guest موجود، migration، invoice/wallet/price/plan mutation انجام نشد. route، NAT، firewall، DNS، cron و state عامل‌های شبکه تغییر نکردند. تنها DB write این کار، همان ۴۵ ردیف catalog بود.

تصاویر محلی بررسی در `output/ready-apps-20261018/` هستند؛ در Git قرار نگرفتند. محدودیت تصویر موبایل: ابعاد CSS مرورگر به‌دلیل zoom با اندازهٔ درخواستی دقیق برابر نبود؛ عرض واقعی ۴۳۳px، دو ستون، popup داخل viewport و نبود overflow سنجیده شد. این بررسی، تست روی دستگاه فیزیکی نیست.

## بازگشت

همیشه ابتدا وضعیت زنده و سفارش‌های تازهٔ برنامه‌ها را بررسی کنید؛ helperها یک‌بارمصرف‌اند و receipt موجود باعث توقف می‌شود. با تغییر هم‌زمان فایل یا کاتالوگ، بازگشت خودکار متوقف می‌شود؛ guard را دور نزنید.

۱. `release/catalog.php --rollback` با PHP 8.4 فقط ۴۵ ID ثبت‌شده را غیرفعال می‌کند و رکوردها را نگه می‌دارد. این مرحله باید پیش از حذف gateهای کد باشد تا سفارش تازه/درصف به شناسهٔ رمزگذاری‌شدهٔ نامعتبر نرسد. اگر sync بعدی snapshot را تغییر داده باشد، تطبیق دستی لازم است.
۲. `resource-guard/deploy.py --rollback` سپس `release/deploy.py --rollback` را با Python 3 اجرا کنید؛ هر مرحله hash فعلی را با نسخهٔ نصب‌شدهٔ خودش تطبیق می‌دهد و وب cache را reset می‌کند.
۳. در این ترتیب، adapter قدیمی نیز دیگر برنامه‌ها را وارد نمی‌کند و sync بعدی آن‌ها را دوباره فعال نخواهد کرد. سرویس‌های ایجادشده پس از انتشار را حذف یا reinstall نکنید؛ سفارش درصف باید جداگانه بررسی شود.

منابع قرارداد: مسیر marketplace و `image_id` در [provider رسمی Arvan](https://github.com/arvancloud/terraform-provider-arvan)، به‌ویژه `internal/api/iaas/image.go` و `server.go`؛ نیازهای مرجع برنامه‌های سنگین در [GitLab](https://docs.gitlab.com/install/requirements/)، [Jitsi](https://jitsi.github.io/handbook/docs/devops-guide/devops-guide-quickstart/) و [BigBlueButton](https://docs.bigbluebutton.org/administration/install/). معیار نهایی این انتشار، metadata زندهٔ هر منطقه به‌علاوهٔ سیاست منابع بالاست؛ این اسناد جایگزین boot test همان ایمیج نیستند.
