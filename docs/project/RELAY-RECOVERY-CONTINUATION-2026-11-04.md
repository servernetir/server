## پذیرش ایزوله از مسیر امضاشدهٔ موجود

`IranEffectPublisher.publish_isolated_accept` فقط پس از نتیجهٔ موفق stage
اصلی، با همان claim پایدار، candidate و incident و هش‌های config/registry،
درخواست تازهٔ فقط‌خواندنی می‌سازد. کلید عمومی SSH و fingerprint از همان
manifest اصلی می‌آیند؛ job نمی‌تواند مسیر یا فرمان محلی انتخاب کند. enrollment
خصوصی پین‌شده، producer/verifier و baseline وابستگی و proxy واقعی را می‌بندد.

agent، CLI ثابت producer را با SPEC و configهای محلیِ پین‌شده اجرا می‌کند؛
زمینهٔ امضاشده برای CT و مهمان به همان target، scope، jobs_hash و هویت
trial/restore مقید می‌ماند. producer، snapshot وابستگی‌ها، پذیرش تازهٔ واقعی
NodeStage/CT و پاسخ امضاشدهٔ native Windows candidate را جمع می‌کند. رسید
cacheشدهٔ NodeStage، مدرک تازه نمی‌شود. CLI فقط evidence خام برمی‌گرداند؛
verifier موجود adapter تنها مصرف‌کنندهٔ نهایی nonce مهمان است.

فقط SPEC صریحِ همین پروفایل می‌تواند سقف۲۰ثانیه‌ای داشته باشد؛ محدودیت عادی
پروب/accept/reconcile هشت ثانیه می‌ماند. مهلت کوتاه‌تر همان درخواست تا خواندن
وابستگی، تحویل CT، پاسخ مهمان و تأیید نهایی حفظ می‌شود و permitِ stage/apply
را تمدید نمی‌کند. نتیجهٔ نامعلوم باعث تکرار mutation یا نمایش مجدد مبهم نمی‌شود.

درخواست پیش‌فرض و درخواست ایزوله، جای یکدیگر را نمی‌گیرند. inbox به profile،
proof تایپ‌شده، scope و زمان‌های اصلی مقید است؛ رسید ایزوله وارد سلامت عادی
یا پذیرش سراسری نمی‌شود. این اتصال، مترجم آمادگی driver یا factory سراسری
نیست. نصب واقعی recipe، input pinها، مسیر native candidate، registry کامل و
پذیرش امضاشدهٔ محیط واقعی همچنان لازم‌اند.

## منبع واقعی و artifact مالکیت DNS

عملیات جدید و ثابتِ فقط‌خواندنیِ `dns_ownership` در پل خصوصی PHP، هویت جاری
core و binding واقعی CloudInstance/Service/customer محافظت‌شده را بررسی
می‌کند. فقط شناسه‌های zone صریحاً انتخاب‌شده در enrollment خصوصی و همان
customer خوانده می‌شوند؛ zone باید active/published و از نوع NS باشد. مالکیت
canary تحت اختیار سرویس رله بررسی می‌شود و `service_id` تهی یا متفاوت zone،
به‌اشتباه برابر سرویس رله فرض نمی‌شود.

reader فقط ستون‌های محدود zone و یک ردیف خام `dns_catalog_zone` را می‌خواند؛
از Setting cache، مقدار پیش‌فرض یا accessorِ credential استفاده نمی‌کند.
catalogِ داخلیِ واقعاً ذخیره‌شده می‌تواند پسوند `.invalid` داشته باشد؛ مقدار
گمشده با نمونه یا fallback پر نمی‌شود و صحت آن روی primary واقعی جدا لازم است.
record، secret، API credential و metadata خام سرویس در پاسخ نیستند.

`DnsOwnershipBridge.build()` فقط از همین pipe ثابت و پین‌شده می‌خواند. زمینه،
انتخاب zoneها، هویت جاری و pin دوباره بررسی می‌شوند؛ پاسخ تاریخی یا دارای
clock نامعتبر HOLD می‌شود. منبع canonical و artifact با نام مبتنی بر hash،
به‌شکل تغییرناپذیر و mode۰۶۰۰ ذخیره می‌شوند. مهلت artifact از زمان اصلی backend
حداکثر۹۰۰ثانیه است؛ زمان نوشتن یا دریافت، آن را تازه نمی‌کند و شکست خواندن،
فایل قبلی را بازنویسی یا تمدید نمی‌کند.

این بخش آماده‌سازی artifact است. حمل آن در job امضاشده، transport/receiver
ثابت PVE→DNS و حالت صریح digest برای دادهٔ قابل‌تازه‌سازی هنوز اضافه نشده‌اند؛
pinهای config/SPEC/artifact نصب‌شده تغییر نمی‌کنند. انتخاب یک تا سه canary،
پوشش کل کاتالوگ، origin، publisher یا آمادگی حذف نسل قبل نیست. جزئیات در
[راهنمای DNS](../../infra/relay_recovery/native_dns_consumer_notes.md) ثبت است.

## مرز سرد snapshot، rebuild و فعال‌سازی

شناسهٔ دقیق مبدأ و خاموش‌بودن آن پس از خواندن‌های کند provider و پیش از POST
دوباره بررسی می‌شوند. در تطبیق نتیجه نیز موفقیت action یا availableبودن image
کافی نیست؛ خواندن تازهٔ مبدأ پس از دریافت نتیجه باید OFF را تأیید کند. شناسهٔ
image می‌تواند موقتاً ثبت شود، اما تصویر نامطمئن، backup کامل محسوب نمی‌شود.

مشاهدهٔ روشن‌شدن یا تغییر lifecycle مبدأ حین snapshot/rebuild ارسال‌شده،
همان تلاش را با نتیجهٔ پایدار `source_power_state_conflict` نامعلوم نگه می‌دارد؛
OFF بعدی، آن تاریخچه را پاک یا تصویر را سرد معرفی نمی‌کند. وضعیت مبهم یا خطای
خواندن موقت، مجوز پذیرش یا POST دوباره نیست. فقط ثبت شناسه‌ها و خواندن نتیجه
ادامه می‌یابد. خاموش‌کردن عادیِ پیش از ساخت image، مسیر مستقل خود را حفظ می‌کند.
وضعیت‌های `running/starting/stopping/rebuilding/initializing/deleting` حین تلاش
ارسال‌شده، conflict پایدارند. `unknown/migrating` و خطای خواندن، HOLD موقت‌اند؛
مشاهدهٔ نخستِ غیر OFF در همان poll، حتی با OFF بعدی پذیرفته نمی‌شود. عدم‌قطعیت
موقت فقط با poll تازهٔ OFF قابل رفع است.

workflow پیش از فعال‌سازی candidate، بعد از preflight مربوط به SSH نیز هویت و
OFF مبدأ، scope و انقضای همان permit را دوباره کنترل می‌کند. این کنترل، fence
یا attestation اصلی را تمدید نمی‌کند و بازیابی هنگام قطع کامل SSH مبدأ پیش از
fence را پیاده‌سازی نمی‌کند.

## آنچه هنوز برای پایان واقعی لازم است

- اتصال coordinator سراسری و callbackهای واقعی trial network، pre-fence
  readiness و سلامت همهٔ مصرف‌کنندگان پس از restore؛ `build_integrations()`
  فعال همچنان با `production_hooks_global_integration_incomplete` متوقف می‌شود.
- enrollment و نصب واقعی producer/Windows candidate، پروب‌های DNS/storage/VPN،
  publisherها، control/origin و رجیستری کامل؛ probe گمشده به‌تنهایی خرابی سرویس نیست.
- تحویل و تازه‌سازی احرازشدهٔ artifact مالکیت DNS، پاسخ واقعی zone/serial و
  پذیرش NS/glue/DNSSEC/TSIG طبق رجیستری؛ canary موجود و احرازشدهٔ storage.
- backup مستقل و restore سازگار همهٔ داده‌ها، writer fencing و مسیر پذیرفته‌شدهٔ
  قطع کامل SSH مبدأ؛ هویت و کلیدهای پایدار نسل بعد و IPv6 دقیق در صورت نیاز.
- تراکنش واقعی CRM روی Laravel/MariaDB و مانور محدود بودجه‌دار با restart،
  مدیریت/سرویس/DNS/TTL و تأیید نبود دقیق سرور و IP قدیمی، پیش از روشن‌کردن auto.

نسخهٔ نصب‌شده و نتایج زنده فقط از checkpoint عملیاتی خصوصی تازه تأیید می‌شوند.
این تغییر کد، کامل‌شدن بازیابی، نصب همهٔ اجزا یا مجوز هزینهٔ زنده را اعلام نمی‌کند.
گزارش‌ها، ابزارهای کشف، نام zone، نشانی و شناسه‌های واقعی محیط وارد Git نمی‌شوند.

## اعتبارسنجی و بازگشت

کاندید نهایی ترکیبی روی Python 3.12، ۷۶۰ آزمون مرتبط در ۲۹ ماژول را در
۲۰٫۸۴۷ ثانیه گذراند. ۲۹۳ بررسی native PHP، lint هر دو ورودی PHP، کنترل diff،
تطبیق بایت‌های ورودی‌های بازبینی‌شده و بازبینی مستقل نیز موفق بودند. تست‌ها
مسیر واقعی امضاشدهٔ publisher/agent/CLI/producer/backend/client/verifier را با
transport ساختگی provider، OS و مهمان می‌سنجند؛ اجرای محیط واقعی نیستند.

اجرای جامع محلی نیز انجام شد: ۹۴۷ آزمون در۲۳٫۰۴۵ثانیه، با۲ failure و۹ error
و۷ skip؛ این اجرا موفق اعلام نمی‌شود. ده مورد به محافظ دست‌نخوردهٔ
`keygen_binary_untrusted` در محیط دارای SSH binary غیر root و یک مورد به فرض
قدیمی تست دربارهٔ ancestor موقت writable مربوط‌اند. کد/تست bootstrap و backup
client در این کاندید تغییر نکردند؛ محافظ تولید، مالکیت و مجوزها دست‌کاری نشدند.
CI استاندارد تازه روی نسخهٔ منتشرشده همچنان لازم است؛ native Windows این
کاندید محلی دوباره اجرا نشده و نتیجهٔ پایه جای آن معرفی نمی‌شود.

```sh
python3 -B -m unittest discover -s infra/relay_recovery/tests -q
git diff --check
```

آزمون‌ها از credential و provider واقعی استفاده نمی‌کنند. محافظ مالکیت SSH و
مسیرهای خصوصی برای سبزکردن تست تضعیف نمی‌شوند؛ محدودیت محیط محلی باید جدا از
شکست منطق کد ثبت شود. بازگشت پیش از نصب به Git محدود است. هر نصب بعدی manifest،
pin، پشتیبان، پذیرش و مسیر بازگشت جدا می‌خواهد؛ state و سابقهٔ عملیات حذف نمی‌شوند.
