# پیگیری سروری تیکت و گزارش شواهد شبکه

۲۸ اکتبر ۲۰۲۶؛ وضعیت: **در تولید تأیید شد**. مالک انتقال پایش تیکت انتخاب‌شده از رایانهٔ شخصی به هرمس سرور و اعلان خصوصی بله را خواست. اطلاعات مشتری، متن تیکت و شناسهٔ binding وارد این گزارش نشده‌اند.

## مجری و ماندگاری

در تولید، `hermes_support_enabled=1`، عملیات هرمس فعال و binding مدیر بله برقرار بود. زمان‌بند موجود `hermes:support-review` هر دقیقه با قفل overlap اجرا می‌شود. پیشرفت طبیعی sequence و last_success با صفر failure مشاهده شد؛ زمان‌بند مالی یا `schedule:run` دستی اجرا نشد. زمان‌بند، daemon یا poller موازی ساخته نشد.

چرخه پیام‌های عمومی تازهٔ مشتری را با cursor پایدار کشف می‌کند، مالکیت سرویس را از دیتابیس تطبیق می‌دهد، diagnostics خواندنی را پیش از ارزیابی می‌گیرد و نتیجه را از مسیر موجود مالک بله اعلام می‌کند. کلید هر رخداد به تیکت و پیام مشتری وابسته است و رسید اعلان، تکرار معمول را مهار می‌کند. نتیجهٔ مبهم تحویل بله همچنان محدودیت مسیر موجود است؛ تضمین exactly-once مطرح نیست.

task انتخاب‌شده با حفظ سابقه به `waiting_customer` رفت و `followup` پس از آخرین پاسخ عمومی ثبت شد. مرجع درخواست در دانش رمزگذاری‌شدهٔ مالک و دو context هرمس VM ثبت و از broker بازخوانی شد. پایش محلی Codex با شناسهٔ خودش به `PAUSED` رفت. مجری بررسی تیکت، اپ تولید روی سرور است؛ VM دانش و گفت‌وگوی مدیریتی را نگه می‌دارد. هیچ وابستگی اجرایی به رایانهٔ مالک باقی نماند.

پاسخ خودکار مشتری فعال نشده است؛ workflow همچنان `allowSend=false` دارد. تیکت بسته واجد بررسی پیام جدید نیست. هیچ تغییری در route، NAT، فایروال، توان مهمان، صف مالی یا state عامل‌های reconcile انجام نشد.

## اصلاح گزارش ادامهٔ مشکل

نسخهٔ زندهٔ `HermesSupportInvestigation` برای ادامهٔ مشکل شبکه فقط چک‌لیست عمومی می‌داد، با اینکه diagnostics پیش از آن گرفته شده بود. شاخهٔ شبکه اکنون نتیجهٔ همان شواهد را در اعلان داخلی نشان می‌دهد:

- فقط service ID دقیق، `provider_api`، نتیجهٔ verified و زمان معتبر در ۱۵ دقیقهٔ گذشته پذیرفته می‌شوند؛ دادهٔ سرویس دیگر، آینده یا کهنه مجوز ادعای سلامت نیست.
- وضعیت ماشین از مقادیر محدود روشن/خاموش/نامعلوم گزارش می‌شود. خاموشی به معنی اجرای روشن‌کردن نیست.
- مجوز همهٔ TCP/UDP فقط با چهار مقدار boolean صریح جهت/خانواده گزارش می‌شود. پوشش ناقص، مسدودبودن پورت درخواستی را ثابت نمی‌کند.
- listener، فایروال مهمان و تحویل واقعی UDP آزموده‌شده فرض نمی‌شوند؛ آزمون هماهنگ مبدأ/مقصد گام بعد است و دسترسی مجاز می‌خواهد.

این شاخه فقط گزارش می‌سازد؛ ابزار عمومی اجرای دستور، انتخاب ماشین از متن مشتری یا اختیار تغییر زیرساخت اضافه نمی‌کند. بررسی PHP و مسیرهای قبلی حفظ شدند.

## نصب و پذیرش

تنها مقصد کد `app/Services/Hermes/HermesSupportInvestigation.php` بود: پشتیبان خصوصی، قفل، کنترل هش پیش از فعال‌سازی، lint، جایگزینی اتمی و ابطال همان OPcache. هش قبل `098fb75c41a5bd68d3c229c12fe2d970de0418d37d75f6c3f96a9f9e7ab75538` و بعد `8c17554ca5116176e8f4f1d466f55d7b2736c277b9e55fb5fcbe6236daa92a6a` است.

snapshot در `infra/hermes/server-ticket-followup-20261028/` خارج از autoload نگهداری می‌شود، چون کل runtime پشتیبانی روی این پایهٔ Git نیست. این پوشه installer نیست؛ مقصد تازه باید پیش از هر نصب خوانده و تغییر بعدی حفظ شود.

در checkout ایزوله با PHP۸.۴.۲۶ و HTTP ساختگی، فرمان زیر **۳۲ تست و ۸۲ assertion موفق** داشت؛ ۹ تست این تغییر و ۲۳ تست فایروال/playbook قبلی واقعاً دوباره اجرا شدند:

`php -d memory_limit=1024M vendor/phpunit/phpunit/phpunit --filter 'HermesNetworkFollowupEvidenceTest|HermesCloudNetworkPlaybookTest|ArvanFirewallEvidenceTest'`

پذیرش تولید، پیام ادامهٔ مشکل را فقط در حافظه شبیه‌سازی کرد و آن را به شواهد خواندنی سرویس واقعی داد؛ ماشین روشن و هر چهار پوشش فایروال true بودند. نتیجهٔ ارزیابی، محدودیت UDP/مهمان و ممنوعیت ارسال/تغییر را حفظ کرد. پیام مشتری آزمایشی، پاسخ عمومی تازه یا تغییر وضعیت واقعی ماشین ساخته نشد. تأیید فعال‌شدن پایش از `BaleSender` به binding همان مالک ارسال و پاسخ موفق دریافت شد؛ این شاهد دریافت API است، نه خوانده‌شدن پیام توسط مالک. هنوز پاسخ تازهٔ واقعی مشتری برای آزمون انتهابه‌انتهای رخداد آینده وجود نداشت.

رسید و پشتیبان خصوصی در `storage/app/private/hermes-server-ticket-followup-20261028` و رسید دانش VM در مسیر خصوصی knowledge-updates باقی‌اند؛ وارد Git نمی‌شوند. helperهای موقت حذف‌شدن خود را تأیید کردند. شناسه و آخرین پیام تیکت در رسید خصوصی است.

## بازگشت

بازگشت کد فقط با تطبیق هش نصب‌شده، حفظ تغییرهای بعدی، پشتیبان همان مقصد، lint و OPcache همان فایل انجام شود. برای پیگیری، فقط metadata و مرجع دانش همین درخواست با revision/hash تازه اصلاح شوند؛ کل state، cursor، رسیدهای اعلان و history برنگردند. فعال‌کردن مجدد پایش رایانهٔ شخصی تصمیم مالک است. فایل helper انتشار به‌دلیل رسید موجود نباید کور تکرار شود.
