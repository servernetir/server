# ServerNet International — برنامهٔ رشد هفت‌زبانه

## هدف و دامنه

تبدیل سایت و تجربهٔ مشتری از سه زبان فعال (fa/en/tr) به هفت زبان
(fa/en/tr/ru/az/fr/ar)، با مسیر خرید قابل‌اعتماد، کشف‌پذیری در جستجو و
معیار فروش سودده. زبان رابط، کشور خریدار، کشور دیتاسنتر، ارز فاکتور و
مجوز ارائهٔ سرویس پنج تصمیم مستقل‌اند. زبان جدید هیچ مجوز دسترسی به
محصول، ارز، زیرساخت یا درگاه جدید ایجاد نمی‌کند.

مبنای بررسی کد: develop، 174be0972e6e28b3e2399e3a91cc37fd18c5d796.
این برنامه گزارش فروش یا رتبهٔ تضمینی نیست. اطلاعات مشتریان و گزارش‌های
خصوصی بازار در مخزن عمومی ثبت نمی‌شوند.

## تصمیم معماری: یک محصول، یک منبع حقیقت

| لایه | تصمیم |
|---|---|
| URL | حفظ همهٔ URLهای fa/en/tr؛ پیشوند مجزای زبان تازه؛ بدون فورس ریدایرکت بر اساس IP |
| دادهٔ محصول | همان کاتالوگ، قیمت، موجودی، دوره و کنترل خرید واقعی؛ بدون قیمت/ترافیک/موجودی ساختگی در ترجمه |
| محتوا | ترجمهٔ بومی با کلیدهای همسان، متن و متای متناسب با نیت جستجو؛ عدم استفاده از fallback انگلیسی به‌عنوان صفحهٔ ترجمه‌شده |
| کشف | canonical خود صفحه، alternate دوطرفه فقط برای صفحات معادل واقعی، sitemap از فهرست صفحات آماده |
| نمایش | فونت مناسب هر خط، RTL برای fa/ar، نمایش صحیح اعداد و خوانایی موبایل |
| کنسول | مسیرهای احراز، CSRF، session، MFA، کیف پول، پرداخت و تحویل با قراردادهای موجود |
| مدیریت | محیط مدیریت داخلی فارسی باقی می‌ماند |
| آراز | ایجاد پیش‌نویس، بازبینی ترجمه، بررسی ادعای محصول و پیگیری وضعیت خزش؛ انتشار ماشینی انبوه بدون کنترل ممنوع |

## مرحلهٔ ۱ — روسی و آذربایجانی

### ۱٫۱. Launchpad عمومی آمادهٔ آزمایش

در مرحلهٔ نخست، ۶ مسیر اطلاعاتی برای هر یک از ru و az ساخته می‌شود:

| مسیر (با پیشوند /ru یا /az) | نیت |
|---|---|
| / | معرفی و انتخاب سرویس |
| /cloud | انتخاب VPS براساس نیاز و محل |
| /vps/hourly | کاربرد و شرایط اجارهٔ ساعتی |
| /cloud/n8n | اتوماسیون و استقرار n8n |
| /gpu | قیود واقعی GPU ساعتی و محیط‌های آماده |
| /ai | انتخاب مدل و API |

این ورودی‌ها محتوای مستقل و کامل برای همین دامنهٔ کوچک دارند؛ تا زمان
تکمیل ترجمهٔ کاتالوگ و پنل، لینک ادامه به صفحهٔ انگلیسی با برچسب واضح
(EN) می‌رود. ۱۲ روت خواندنی، ترجمه‌های هم‌ساخت، قالب واکنش‌گرا، لینک
متقابل بین دو زبان، JSON-LD از نوع WebPage و اتصال به sitemap مشترک
در این بسته قرار دارند. نسخه‌های قدیمی به صفحات جدید لینک ناوبری می‌دهند،
اما تا برابری محتوا، hreflang گمراه‌کننده بین صفحهٔ کامل و صفحهٔ پایلوت
ثبت نمی‌شود.

**پرچم انتشار:** `INTERNATIONAL_MARKET_LOCALES=` پیش‌فرض خالی است.
پرچم فقط ru و az را می‌پذیرد. حتی با route cache، حالت خاموش پاسخ ۴۰۴ و
بدون لینک/alternate/sitemap دارد. ar/fr هنوز آماده و قابل فعال‌سازی نیستند.
این تمهید از نمایش زبان ناقص و فعال‌شدن تصادفی مسیرهای خرید جلوگیری می‌کند.
به هیچ مسیر خصوصی، قیمت‌گذاری، خرید، provider، schema یا پرداخت دست زده
نشده است.

### ۱٫۲. تبدیل پایلوت به تجربهٔ کامل

- فهرست کلیدهای `lang/fa/en/tr`، configهای محصول و دادهٔ CMS؛ به‌ازای هر
  گروه، مالک ترجمه و وضعیت کامل/بازبینی/منتشر تعیین شود.
- مسیر اصلی و helperهای lroute/lc را تنها پس از آمادگی مصرف‌کننده‌های
  route، cache، robots، canonical، لینک‌ها و error page گسترش دهیم.
- صفحهٔ اصلی، ناوبری، VPS، GPU، n8n، AI، هاست، دامنه و صفحات تجاری
  پرفروش را به همراه جدول قیمت زنده و محتوای فنی بومی کامل کنیم.
- ثبت‌نام، ورود، بازیابی، خطاهای فرم، پنل، پشتیبانی، قوانین و اعلان‌های
  تراکنشی؛ آزمون خرید فقط با fixture، بدون پرداخت/تماس provider واقعی.
- جداگانه: محتوای معتبر موردی برای بازارها، مانند انتخاب سرور برای
  توسعه‌دهندگان، مقایسهٔ ساعتی و ماهانه و راهنمای n8n.

دروازهٔ عبور: برابری داده و عملکرد با fa/en/tr، بدون کلید خام ترجمه،
fallback بی‌نام، قیمت خیالی یا تغییر eligibility؛ تست HTTPS، موبایل،
دسکتاپ، RTL و خطاهای مرورگر. انتقال هر مسیر پایلوت به صفحهٔ کامل با همان
URL انجام می‌شود و نیازی به حذف اعتبار جستجو ندارد.

## مرحلهٔ ۲ — عربی و فرانسوی

- ترجمهٔ همان مسیرهای فروش و کنسول با واژه‌نامهٔ مشترک؛ RTL واقعی عربی با
  CSS logical properties و فونت مناسب؛ بررسی متن طولانی فرانسوی.
- محتوای بومی برای بازارهای فرانسوی و عربی‌زبان، بدون ادعای وجود دفتر یا
  دیتاسنتر غیرواقعی. روش پرداخت/ارز فقط گزینهٔ واقعاً فعال و مجاز.
- گسترش مرحله‌ای به کاتالوگ‌های هاست/دامنه و مستندات فنی؛ بخش‌های فقط
  فارسی یا محصولات غیرقابل عرضه، ترجمه و ایندکس مصنوعی نمی‌شوند.
- بازبینی مستقل ترجمهٔ قوانین و پیام‌های تراکنشی قبل از فعال‌سازی.

## مرحلهٔ ۳ — SEO، GEO و تولید محتوای اصیل

1. URL و sitemap و تگ‌های HTML را در همهٔ زبان‌های آماده بررسی کنیم؛
   مسیرهای خصوصی همچنان خارج از index و دسترسی crawler بمانند.
2. عنوان/H1/توضیح یکتا، Breadcrumb و Schema متناسب با نوع صفحه؛
   اطلاعات محصول از منبع واقعی، نه امتیاز یا review ساختگی.
3. صفحات شواهد: SLA، وضعیت سرویس، روش تست سرعت، راهنمای عملی و FAQ با
   تاریخ به‌روزرسانی واقعی. اطلاعات قابل مشاهده در HTML عرضه شوند.
4. Google Search Console: sitemap کامل و بخش‌بندی‌شده، خزش، خطاها،
   query/صفحه/کشور، CTR، ایندکس و Core Web Vitals.
5. Bing Webmaster و IndexNow برای نسخه‌های جدید و به‌روزشده؛ دسترسی
   crawlerهای جستجوی AI طبق سیاست فعال robots سایت و CDN. دسترسی آموزش
   مدل تصمیم جداگانه است. فایل کمکی مخصوص AI جایگزین محتوای معتبر نیست.
6. ارجاع واقعی و شفاف از مستندات، پروژه‌های نمونه، و جامعهٔ توسعه‌دهندگان؛
   لینک یا تجربهٔ مشتری ساختگی، برنامهٔ ساخت انبوه صفحات صرفاً برای رتبه
   و ادعای رتبه/معرفی تضمینی وجود ندارد.

## مرحلهٔ ۴ — کمپین آزمایشی و سود

قبل از هزینهٔ تبلیغ، مسیر کاربران از لندینگ تا ثبت‌نام و پرداخت معتبر
با analytics پس از رعایت رضایت/سیاست حریم خصوصی و بدون ارسال شماره تلفن،
ایمیل یا شناسهٔ زنده به سرویس تحلیل بررسی می‌شود. پایلوت مستقل اولیه
هیچ اسکریپت تبلیغاتی جدیدی اضافه نمی‌کند.

| شاخص | اندازه‌گیری و استفاده |
|---|---|
| صفحه/زبان/کشور | Search Console و تفکیک landing page؛ کشور IP با کشور شماره تلفن یکی نیست |
| مشاهده و تعامل | GA4 پس از کنترل کیفیت ترافیک و حذف ترافیک غیرواقعی از تحلیل تصمیم |
| CTA و ثبت‌نام | رویدادهای قیف با نام‌گذاری یکسان بین زبان‌ها |
| فروش | پرداخت واقعی یکتا و تحویل موفق در سیستم داخلی؛ فاکتور صادرشده فروش قطعی نیست |
| سود | درآمد منهای هزینهٔ provider، FX، کارمزد پرداخت، هزینهٔ پشتیبانی و CAC |
| ارجاع AI | خزش، ارجاع و متریک citation در ابزارهایی که آن را پشتیبانی می‌کنند |
| نگهداشت | تمدید/ریزش و فروش مکمل در گروه‌های هم‌زمان، نه فقط تعداد بازدید |

برای هر بازار یک لندینگ و پیشنهاد مشخص انتخاب شود. مثال‌ها: VPS ماهانه،
n8n آماده و GPU با شرایط روشن؛ آزمایش کوچک و قابل توقف، مقایسهٔ سود واقعی
و هزینهٔ جذب، توسعه فقط پس از نتیجه. هیچ کمپینی فعال و هیچ بودجه‌ای در
این مرحله خودکار هزینه نمی‌شود؛ طرح بودجه و محتوای نهایی باید جدا
مشخص شود.

## پذیرش و بازگشت پایلوت

- تست `InternationalMarketPilotTest` و آزمون‌های sitemap، متادیتا،
  سلامت سه زبان فعلی، قیمت‌گذاری و robots در محیط مجزا؛ CI مخصوص PR.
- قبل از انتشار: تطبیق SHA و diff با develop و manifest محدود مطابق
  [DEPLOYMENT](DEPLOYMENT.md). فایل CSS هم در مقصد webroot واقعی بررسی
  شود. تست رندر واقعی و مرورگر در دو زبان و موبایل مستقل از CI است.
- پیش‌فرض خاموش برای نصب اولیه، پذیرش خصوصی با localeهای آماده در محیط
  ایزوله؛ فعال‌سازی تولید فقط پس از تأیید زبان، مسیر handoff، کنسول،
  نمای موبایل، analytics و کنترل sitemap. invalidate نسل PageCache هنگام
  تغییر publication flag لازم است؛ config cache قدیمی نباید flag را پنهان کند.
- rollback: خاموش کردن flag، refresh config و ابطال نسل PageCache، سپس
  بررسی حذف مسیرها از ناوبری/sitemap و عدم نمایش alternate؛ برای بازگشت
  خود کد از manifest و بکاپ مصوب استفاده شود.
- وضعیت این سند: برنامه و آغاز توسعهٔ پایلوت. ثبت PR/CI، نصب و پذیرش
  تولید جدا ثبت می‌شوند؛ هیچ وعدهٔ رتبه یا نتیجهٔ فروش پیش از دادهٔ واقعی.
