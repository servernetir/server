## مانع قابل آزمون که جلو رفت

`owner-growth-caller.php` وابستگی‌های runtime را با `__DIR__` بارگذاری می‌کند. preflight پیشین سه فایل client، cycle و caller را از نظر مسیر canonical، SHA-256، مالک، مجوز و متمایزبودن بررسی می‌کرد، اما الزام نمی‌کرد هر سه در یک پوشه باشند. بنابراین سه فایل هش‌درست در مسیرهای جدا می‌توانستند `ready` گزارش شوند، درحالی‌که caller هنگام اجرا نسخه دیگری را از پوشه خودش بارگذاری کند.

در PR شماره ۲۸۹:

- check تازه `runtime_files_share_directory` اضافه شد و ترکیب پراکنده fail-closed می‌شود؛
- آزمون منفی، cycle هش‌درست و هم‌مالک را در پوشه دیگر قرار می‌دهد و `not_ready` را الزام می‌کند؛
- مرز این کنترل در README بسته مستند شد؛
- workflow «Hermes Growth read client» با PHP 8.4 و cURL موفق شد و lint، آزمون ایزوله و probe واقعی بدون راز را گذراند؛
- workflowهای incident روی SQLite و MariaDB نیز موفق شدند؛

PHP محلی این executor موجود نبود و اجرای محلی با `php: command not found` متوقف شد؛ نتیجه محلی ادعا نمی‌شود. این فقط **رسید Git و CI ایزوله** است. نصب روی VM Araz، secret موجود در دو سمت، درخواست HMAC زنده، پذیرش دوطرفه، اجرای مستقل یا زمان‌بند را ثابت نمی‌کند. هیچ کلید، دسترسی، شبکه، داده مشتری یا scheduler تازه ایجاد نشد.
