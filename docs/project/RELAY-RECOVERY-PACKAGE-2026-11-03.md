## دامنه

بستهٔ مستقل [relay_recovery](../../infra/relay_recovery/README.md) شامل برنامه‌ریز
پایدار، کانال امضاشدهٔ عامل، پروب واقعی ویندوز، workflow بازیابی، اجزای وابستگی
و مرحلهٔ مستقل CRM است. اصلاح جایگزینی فایل ضدتکرار در PowerShell 5.1، رشتهٔ
تهیِ واقعی را به .NET می‌دهد و حفاظت بازپخش را حفظ می‌کند.

انتشار این بسته، نصب یا فعال‌سازی آن روی سرورها نیست. تابع اتصال سراسری همچنان
در حالت روشن `production_hooks_global_integration_incomplete` می‌دهد. رجیستری
کامل، انتقال واقعی مصرف‌کنندگان و DNS، restore کامل، حفاظت نویسنده‌ها، سناریوی
قطع SSH مبدأ، ادامهٔ امن مجوز و مانور واقعی هنوز پذیرش جدا می‌خواهند.

## حریم اطلاعات

- آدرس‌های عمومی و شناسه‌های واقعی محیط از fixtureهای این بسته حذف شدند؛
  تست‌ها فقط از هویت ساختگی و آدرس‌های عمومی شناخته‌شده استفاده می‌کنند و
  تماس شبکه ندارند.
- مقصد کنترل میزبان از کد به enrollment محلی و خصوصی منتقل شد. نبودن، خرابی
  یا نامعتبرشدن آن، شاهد کنترل سالم تولید نمی‌کند. راه‌اندازی نسخهٔ جدید به
  ثبت همین تنظیم و پین دوبارهٔ SPEC نیاز دارد.
- رمز، کلید خصوصی، credential، دادهٔ مشتری، پیکربندی زنده و آرشیو تشخیصی،
  جزو این انتشار نیستند. بایت‌های عمومی کلید و توکن ساختگی در تست‌ها راز نیستند.
- شاخهٔ انتشار از مبنای تازه ساخته می‌شود؛ commitهای محلیِ قبل از حذف اطلاعات
  محیط، والد این انتشار نیستند. تاریخچهٔ قبلاً موجود مخزن موضوع ممیزی جداست.

تغییر visibility کل مخزن، نیازمند آماده‌سازی دریافت احرازشده یا بستهٔ مستقل
است: ابزارهای نصب و دریافت دانش مخزن در هرمس، مسیر خواندن عمومی دارند. تغییر
فوری visibility در این انتشار انجام نمی‌شود.

## اعتبارسنجی و بازگشت

نسخهٔ پاک‌سازی‌شده، ۷۲۴ آزمون Python در ۱۷۴٫۳۴۹ ثانیه و ۷۲ بررسی مستقل PHP را
گذراند؛ lint هر دو ورودی PHP و بازبینی مستقل نیز موفق بودند. نتیجهٔ native
ویندوز در workflow، جدا از این اجرای محلی ثبت می‌شود.
workflow محدود `relay-recovery.yml`، تست‌های Linux/PHP
را در namespace بدون شبکه و قراردادهای native ویندوز را روی fixture دورریختنی
اجرا می‌کند؛ credential و عملیات provider یا نصب تولید در آن وجود ندارند.

تا زمان پذیرش مستقل استقرار، rollback صرفاً بستن/برگرداندن تغییر Git است.
نسخه‌های نصب‌شده و state عملیاتی با این PR جایگزین نمی‌شوند. هر نصب بعدی باید
manifest، پین، پشتیبان خصوصی و رسید پذیرش خودش را داشته باشد.
