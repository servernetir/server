# کنترل انقضا و ابطال لینک گزارش SEO — ۳۱ اکتبر ۲۰۲۶

مبنای نهایی تغییر develop در SHA c444fd7051281b359d5c95cdef91f02a605f2a4e است. این تغییر پاسخ مستقیم به مانع ثبت‌شدهٔ برنامه رشد است: گزارش عمومی هدرهای noindex/no-store/no-referrer داشت، اما لینک خصوصی تاریخ پایان و امکان ابطال عملی نداشت. دامنه فقط کنترل دسترسی گزارش است؛ ارسال ایمیل، خزش، CRM تولید، داده مالی و زمان‌بند تغییر نمی‌کنند.

## رفتار آماده‌شده

- گزارش تا ۳۰ روز تازه است؛ پس از آن فرم مشاوره بسته می‌شود، ولی خود گزارش برای مرور تا ۹۰ روز در دسترس می‌ماند.
- لینک پس از ۹۰ روز ۴۰۴ می‌دهد. برای گزارش‌های قبلی که expires_at ندارند، مهلت از created_at + 90 days محاسبه می‌شود.
- مدیر می‌تواند همان گزارش را از /admin/seo با POST و CSRF باطل کند. ابطال تکراری بی‌اثر و امن است.
- ابطال، ردیف‌های منتظر همان گزارش را skipped/report_revoked می‌کند. گزارش منقضی یا باطل در send-next ارسال نمی‌شود و نتیجهٔ آن report_unavailable است؛ خطا به‌عنوان suppression معرفی نمی‌شود.
- تا پیش از وجود هر دو ستون تازه، پنل SEO ready نمی‌شود. لینک نامعتبر، منقضی یا باطل وجود گزارش را افشا نمی‌کند و ۴۰۴ می‌دهد.
- توکن همچنان در serialization پنهان است؛ هدرهای حریم خصوصی گزارش فعال باقی می‌مانند.

مهاجرت تازه فقط دو timestamp nullable و index آن‌ها را اضافه می‌کند: expires_at و revoked_at. حذف یا پاک‌سازی گزارش و داده تماس انجام نمی‌شود.

## آزمون و پذیرش

سناریوهای تازه با داده ساختگی: انقضای GET و POST مشاوره بدون CRM، fallback نودروزه گزارش قدیمی، ابطال مدیر و توقف ردیف منتظر، تکرار امن ابطال و منع ارسال گزارش منقضی. workflow محدود PHP 8.4 روی SQLite و MariaDB چهار قرارداد رفتاری و syntax فایل route را اجرا می‌کند؛ declaration مسیر POST نام‌دار در بازبینی diff داخل گروه auth:web/admin است. هیچ API خارجی، ایمیل واقعی، scan، migration تولید یا deploy ندارد. بررسی تکمیلی نشان داد نبودن home و سایر مسیرها در آن نسخه ناشی از محتوای نامعتبر web.php بود، نه شکست مستقل قدیمی یا رفتار عادی CLI. ## انتشار و بازگشت

ترتیب انتشار آینده: پشتیبان و snapshot تازه، migration، کد، پاک‌سازی cache طبق راهنمای انتشار، سپس کنترل ۴۰۴ fixture منقضی/باطل و رندر پنل. هیچ گزارش واقعی مشتری برای آزمایش باطل نشود. بازگشت کد پیش از migration امن است؛ حذف ستون‌ها فقط پس از اطمینان از نبود وابستگی نسخه نصب‌شده انجام شود. این سند مجوز deploy یا اجرای migration تولید نیست.
