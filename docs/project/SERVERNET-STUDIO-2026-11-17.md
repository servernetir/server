# ServerNet Studio — حساب مشترک و کیف پول

نسخهٔ مشتری ServerNet Studio محصولی با رابط اختصاصی ServerNet و فونت IRANSans است.
مخزن رابط و سرویس مشتری: `servernetir/servernet-studio`، پوشهٔ `servernet/`.
این تغییر فقط قرارداد حساب در اپ Laravel را اضافه می‌کند و به‌طور پیش‌فرض خاموش است.

## ورود و ثبت‌نام

Studio کاربر را ابتدا به `/login/studio` کنسول هدایت می‌کند. این مسیر فقط callback/PKCE معتبر و یکی از روش‌های account، google یا register را می‌پذیرد و مقصد داخلی مجوز را در نشست نگه می‌دارد. دکمهٔ گوگل به همان GoogleController فعلی سایت می‌رود؛ حساب، OAuth callback، تأیید دومرحله‌ای و ثبت‌نام مستقل ساخته نمی‌شوند. کاربر جدید همان پیامک، احراز هویت و پذیرش قوانین فعلی سایت را طی می‌کند. کاربر دارای نشست به مجوز Studio می‌رود. مقصد برگشت، `/account/studio/authorize` است. middlewareهای ورود مشتری، وضعیت حساب، محدودیت IP و CSRF فعلی حفظ شده‌اند. کاربر در خود کنسول وارد یا ثبت‌نام می‌شود؛ Studio رمز یا OTP او را نمی‌گیرد.
پس از تأیید دسترسی، code یک‌بارمصرف ۶۰ثانیه‌ای با PKCE S256 به callback از پیش تنظیم‌شده برمی‌گردد. فقط backend Studio با client secret و verifier می‌تواند آن را با کلید کوتاه‌عمرِ همان مشتری تعویض کند.
کلید به پروژهٔ اختصاصی `servernet-studio` و فقط سه scope مدل، چت و خواندن موجودی متصل است؛ بودجه/وضعیت پروژه، سقف تعداد کلیدها و admission موجود حفظ می‌شوند. پروژهٔ غیرفعال دوباره روشن نمی‌شود.

## مسیرها

| مسیر | احراز و اثر |
| --- | --- |
| GET `/login/studio` و نسخه‌های en/tr | query معتبر؛ نگهداری مقصد داخلی، ادامه در ورود/گوگل/ثبت‌نام فعلی؛ بدون صدور کلید |
| GET/POST `/account/studio/authorize` و نسخه‌های en/tr | نشست مشتری؛ GET نمایش مجوز، POST با CSRF صدور code |
| POST `/api/studio/token` | client secret و PKCE؛ مصرف اتمیک code؛ صدور کلید محدود، بدون برداشت پول |
| GET `/v1/studio/account` | Bearer و scope صریح `ai:wallet:read`؛ موجودی دفتر و رزرو از Wallet، مصرف ماهانه از ai_usage |
| POST `/v1/studio/revoke` | همان کلید محدود؛ فقط ابطال کلید خودش |

شناسه مشتری از توکن/نشست می‌آید و از query/body پذیرفته نمی‌شود. واحد پول پاسخ **تومان، IRT** است؛ مقدار توکن مصرفی مستقل از مبلغ است.
هیچ کسر/شارژ/دفتر مالی تازه‌ای در این تغییر ایجاد نشده است. درخواست مدل همچنان از `/v1/chat/completions` و `AiCaller` عبور می‌کند. شارژ فقط در `/account/topup` کنسول انجام می‌شود.

## نصب و بازگشت

متغیرهای موردنیاز: `SERVERNET_STUDIO_ENABLED=false`، `SERVERNET_STUDIO_CLIENT_SECRET` تصادفی حداقل۳۲نویسه و `SERVERNET_STUDIO_REDIRECT_URI=https://<studio-host>/auth/callback`.
secret باید در backend هر دو سمت یکسان و خصوصی باشد. هیچ secret واقعی در مخزن یا build مرورگر قرار نگیرد. ابتدا migration جدید، نصب دو سمت، تطبیق HTTPS/callback و پذیرش خصوصی انجام شود؛ سپس feature روشن شود. لاگ callback و token endpoint نباید query/body حاوی code/secret را ثبت کند.
برای توقف، feature را خاموش و کلیدهای Studio را از پنل مشتری ابطال کنید. rollback با revert کد و خاموش‌ماندن feature است؛ جدول grant و سابقهٔ مالی حذف نشوند.

## تکمیل ورود گوگل

آزمون‌های جدید، برگشت هر سه زبان، ثبت‌نام فارسی با پیامک/هویت/قوانین و ورود دومرحله‌ای را با سرویس‌های ساختگی می‌پوشانند. گردش اختصاصی اکنون GoogleAuthTest موجود را هم اجرا می‌کند. پذیرش واقعی گوگل و نصب تولید انجام نشده‌اند؛ نتیجهٔ CI این تغییر جداگانه ثبت می‌شود.

پذیرش تکمیل گوگل: روی SHA `2382ddcedbeab4ef89f40f6daff0d8de836a7a9e`، run `44057595824`، job `133950847698` با PHP۸٫۴٫۲۷ موفق شد: **۷۵تست/۹۸۵بررسی** در StudioSsoTest، GoogleAuthTest و V1ChatTest. run اول توسعهٔ آزمون‌ها فقط به سقف درخواست آزمون ترکیبی خورد؛ موارد معتبر و نامعتبر جدا شدند و throttle تولید تغییری نکرد. تست‌های برنامهٔ مشتری در همین تغییر۴۳مورد موفق و build TypeScript/Vite موفق بودند. نصب و ورود گوگل واقعی انجام نشده‌اند.

## نسخهٔ نصبی و صفحهٔ دانلود

کلاینت مستقل `servernet/desktop` برای Windows x64 و macOS 13+ Intel/Apple Silicon آماده می‌شود. ورود در مرورگر سیستم با کد تأیید دستی و PKCE محدود به همان برنامه است؛ secret مشترک و کلید Gateway در نصب‌کننده نیست. backend Studio نشست همان مشتری را فقط یک بار به برنامهٔ دارای verifier تحویل می‌دهد.

مسیر عمومی `/studio/download` و نسخه‌های en/tr، وضعیت آماده‌سازی یا بسته‌های تأییدشده را نمایش می‌دهد. پس از تغییر Windows-first، manifest می‌تواند فقط ویندوز را داشته باشد؛ کارت‌های مک همچنان آماده‌سازی نشان می‌دهند. تا فعال‌بودن SSO، فعال‌کردن `SERVERNET_STUDIO_DOWNLOADS_ENABLED`، وجود manifest خصوصی `storage/app/studio/release.json` و فایل‌های فهرست‌شدهٔ امضاشده (مک notarized) با نام/اندازهٔ دقیق، لینک دانلود عرضه نمی‌شود. manifest خالی، پلتفرم ناشناخته یا هر ورودی نامعتبر رد می‌شود. `SERVERNET_STUDIO_DOWNLOADS_DIRECTORY` باید با مسیر واقعی public_html/downloads/studio در cPanel تطبیق داده شود؛ کپی دارایی فقط به app/public انتشار عمومی نیست. checksum باید هنگام آماده‌سازی/نصب تطبیق داده شود؛ صفحه برای هر بازدید فایل‌های بزرگ را دوباره hash نمی‌کند.

نصب هنوز اجرا نشده است: cPanel در ادامهٔ نشست وارد شد؛ بررسی فقط‌خواندنی Python3.12.16، Node و Passenger و نبود Docker را تأیید کرد. فایل‌های SSO هنوز نصب نیستند. نوشتن مخزن جدید Studio همچنان403 است و صفحهٔ تنظیم اتصال GitHub تأیید هویت مالک را می‌خواهد. نتیجهٔ آزمون و بسته‌ها پس از ساخت جدا ثبت می‌شود. فایل بدون امضای TEST، نسخهٔ عمومی نیست.

پذیرش صفحهٔ دانلود: run `44062680272`، job `133968326218`، روی SHA `1cf62aa100e6ba0af61ae069741ea5e28c109503`، PHP۸٫۴٫۲۷: **۷۸تست/۱۰۱۲بررسی** موفق. سمت مشتری۵۲آزمون Python و۸آزمون Node و build وب موفق‌اند. سه ZIP آزمایشی بدون امضا ساخته شدند. ## بازطراحی صفحهٔ دانلود

`/studio/download` و نسخه‌های انگلیسی و ترکی، در زمان فعال‌بودن ورود مرکزی، دکمهٔ ورود به نسخهٔ وب را حتی پیش از انتشار نصب‌کننده نشان می‌دهند. کارت هر سیستم‌عامل پیش‌نیاز و وضعیت بستهٔ همان سیستم را نمایش می‌دهد. انتشار لینک نصب رسمی همچنان از manifest مصوب و کنترل امضا و فایل عبور می‌کند و SHA-256 از همان manifest خوانده می‌شود. برای بازگشت کافی است کنترلر دانلود، نمای Blade و سه فایل ترجمه به نسخهٔ پشتیبان همان انتشار برگردند.

## پیش‌نمایش قابل دانلود

انتشار آزمایشی مستقل از نصب‌کنندهٔ رسمی است. پس از تأیید اجرای بومی هر معماری و تطبیق SHA-256 فایل منتقل‌شده با بستهٔ ساخت، اپراتور فایل را در مسیر واقعی عمومی `downloads/studio-preview/` قرار می‌دهد و سپس manifest خصوصی `storage/app/studio/preview.json` را به‌صورت اتمی منتشر می‌کند. ریشهٔ فیزیکی با `SERVERNET_STUDIO_PREVIEW_DIRECTORY` قابل تنظیم است و پیش‌فرض کنار دایرکتوری تنظیم‌شدهٔ دانلود رسمی است.

manifest دارای `public_preview: true`، `unsigned_test: true`، `version` سه‌جزئی، `source_sha` چهل‌رقمی hexadecimal و `files` است. کلیدهای مجاز `windows_x64`، `macos_x64` و `macos_arm64` هستند؛ هر ورودی نام دقیق `ServerNet-Studio-UNSIGNED-TEST-<version>-<platform>.<ext>` با suffixهای `win-x64.exe`، `mac-x64.zip` و `mac-arm64.zip`، اندازهٔ واقعی، digest و `native_verified: true` دارد. معماری تأییدنشده در manifest قرار نمی‌گیرد. ورودی نامعتبر، فایل غایب یا symlink انتشار آزمایشی را غیرفعال می‌کند. فایل‌ها هنگام انتشار مستقل hash می‌شوند و برای هر درخواست صفحه دوباره خوانده نمی‌شوند.

نسخهٔ امضاشدهٔ آماده برای هر پلتفرم نسبت به پیش‌نمایش اولویت دارد. پیش‌نمایش‌ها در سه زبان با علامت بدون امضا، نسخه، سورس، checksum و وضعیت آزمون اجرای بومی معرفی می‌شوند. مسیر update feed، manifest رسمی و شرط امضا/notarization تغییر نکرده‌اند.

## راهنمای نصب وب‌اپ — ۲۱ نوامبر

از همان ورودی `https://studio.servernet.cloud/`، صفحات معرفی AI و `/studio/download` در سه زبان و در صورت فعال بودن ورود مرکزی، وب‌اپ را برای استفادهٔ روزمره پیشنهاد می‌کنند؛ راهنمای مستقل `#studio-web-install` برای Chrome و Edge روی Windows/macOS و Safari روی macOS Sonoma 14 یا جدیدتر تعریف شده است. این قابلیت همان تجربهٔ آنلاین مرورگر است، به اینترنت نیاز دارد و هیچ‌یک از مجوزهای بومی دسکتاپ را به کاربر نمی‌دهد. مسیرهای دانلود، manifest پیش‌نمایش، الزامات امضا و update feed دست نخورده‌اند.

منوهای نصب بر اساس راهنمای رسمی [Chrome](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DDesktop&hl=en)، [Edge](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge) و [Safari](https://support.apple.com/104996) معرفی شده‌اند. نصب کد وب‌اپ در مخزن/هاست Studio جداست. نصب راهنما در سایت اصلی باید فقط دو Blade و سه فایل ترجمهٔ `studio_download.php` را تغییر دهد؛ بازگشت نیز با همان پنج فایل و پاک‌سازی هدفمند کش نمای مرتبط انجام می‌شود. هیچ تغییر تنظیم، migration یا داده‌ای لازم نیست.

آزمون ایزوله روی پایهٔ `develop@0ed2d4f1177fde712b0ca077efb895e5b3feac7e` با PHP 8.4.24 و SQLite: `tests/Feature/StudioDownloadsTest.php`، ۱۱ آزمون و ۲۴۷ بررسی موفق شامل نمای هر سه زبان، غیرفعال بودن ورود یا نصاب رسمی، عرضهٔ مستقل پیش‌نمایش و اولویت فایل امضاشده. چهار فایل PHP تغییرکرده نیز lint شدند. این شواهد نصب یا پذیرش مرورگر واقعی را اثبات نمی‌کنند.
