# ServerNet Studio — حساب مشترک و کیف پول

نسخهٔ مشتری ServerNet Studio محصولی با رابط اختصاصی ServerNet و فونت IRANSans است.
مخزن رابط و سرویس مشتری: `servernetir/servernet-studio`، پوشهٔ `servernet/`.
این تغییر فقط قرارداد حساب در اپ Laravel را اضافه می‌کند و به‌طور پیش‌فرض خاموش است.

## ورود و ثبت‌نام

Studio کاربر را ابتدا به `/login/studio` کنسول هدایت می‌کند. این مسیر فقط callback/PKCE معتبر و یکی از روش‌های account، google یا register را می‌پذیرد و مقصد داخلی مجوز را در نشست نگه می‌دارد. دکمهٔ گوگل به همان GoogleController فعلی سایت می‌رود؛ حساب، OAuth callback، تأیید دومرحله‌ای و ثبت‌نام مستقل ساخته نمی‌شوند. کاربر جدید همان پیامک، احراز هویت و پذیرش قوانین فعلی سایت را طی می‌کند. کاربر دارای نشست به مجوز Studio می‌رود. مقصد برگشت، `/account/studio/authorize` است. middlewareهای ورود مشتری، وضعیت حساب، محدودیت IP و CSRF فعلی حفظ شده‌اند. کاربر در خود کنسول وارد یا ثبت‌نام می‌شود؛ Studio رمز یا OTP او را نمی‌گیرد.
پس از تأیید دسترسی، code یک‌بارمصرف ۶۰ثانیه‌ای با PKCE S256 به callback از پیش تنظیم‌شده برمی‌گردد. فقط backend Studio با client secret و verifier می‌تواند آن را با کلید کوتاه‌عمرِ همان مشتری تعویض کند.
کلید به پروژهٔ اختصاصی `servernet-studio` و فقط سه scope مدل، چت و خواندن موجودی متصل است؛ بودجه/وضعیت پروژه، سقف تعداد کلیدها و admission موجود حفظ می‌شوند. پروژهٔ غیرفعال دوباره روشن نمی‌شود.

## مسیرها

| مسیر | احراز و اثر |
| --- | --- |
| GET `/login/studio` و نسخه‌های en/tr | query معتبر؛ نگهداری مقصد داخلی، ادامه در ورود/گوگل/ثبت‌نام فعلی؛ بدون صدور کلید |
| GET/POST `/account/studio/authorize` و نسخه‌های en/tr | نشست مشتری؛ GET نمایش مجوز، POST با CSRF صدور code |
| POST `/api/studio/token` | client secret و PKCE؛ مصرف اتمیک code؛ صدور کلید محدود، بدون برداشت پول |
| GET `/v1/studio/account` | Bearer و scope صریح `ai:wallet:read`؛ موجودی دفتر و رزرو از Wallet، مصرف ماهانه از ai_usage |
| POST `/v1/studio/revoke` | همان کلید محدود؛ فقط ابطال کلید خودش |

شناسه مشتری از توکن/نشست می‌آید و از query/body پذیرفته نمی‌شود. واحد پول پاسخ **تومان، IRT** است؛ مقدار توکن مصرفی مستقل از مبلغ است.
هیچ کسر/شارژ/دفتر مالی تازه‌ای در این تغییر ایجاد نشده است. درخواست مدل همچنان از `/v1/chat/completions` و `AiCaller` عبور می‌کند. شارژ فقط در `/account/topup` کنسول انجام می‌شود.

## نصب و بازگشت

متغیرهای موردنیاز: `SERVERNET_STUDIO_ENABLED=false`، `SERVERNET_STUDIO_CLIENT_SECRET` تصادفی حداقل۳۲نویسه و `SERVERNET_STUDIO_REDIRECT_URI=https://<studio-host>/auth/callback`.
secret باید در backend هر دو سمت یکسان و خصوصی باشد. هیچ secret واقعی در مخزن یا build مرورگر قرار نگیرد. ابتدا migration جدید، نصب دو سمت، تطبیق HTTPS/callback و پذیرش خصوصی انجام شود؛ سپس feature روشن شود. لاگ callback و token endpoint نباید query/body حاوی code/secret را ثبت کند.
برای توقف، feature را خاموش و کلیدهای Studio را از پنل مشتری ابطال کنید. rollback با revert کد و خاموش‌ماندن feature است؛ جدول grant و سابقهٔ مالی حذف نشوند.

## تکمیل ورود گوگل

دکمه‌های ورود حساب، ادامه با گوگل و ثبت‌نام در رابط مشتری از یک تراکنش PKCE وابسته به مرورگر عبور می‌کنند. مهلت تراکنش یک ساعت است تا مراحل ثبت‌نام انجام شوند؛ عمر code همچنان۶۰ثانیه است. در نبود پیکربندی گوگل، مسیر به ورود معمول کنسول برمی‌گردد. پارامتر مقصد دلخواه پذیرفته نمی‌شود و درخواست نامعتبر مقصد قبلی نشست را تغییر نمی‌دهد.

آزمون‌های جدید، برگشت هر سه زبان، ثبت‌نام فارسی با پیامک/هویت/قوانین و ورود دومرحله‌ای را با سرویس‌های ساختگی می‌پوشانند. گردش اختصاصی اکنون GoogleAuthTest موجود را هم اجرا می‌کند. پذیرش واقعی گوگل و نصب تولید انجام نشده‌اند؛ نتیجهٔ CI این تغییر جداگانه ثبت می‌شود.

## نسخهٔ نصبی و صفحهٔ دانلود

کلاینت مستقل `servernet/desktop` برای Windows x64 و macOS 13+ Intel/Apple Silicon آماده می‌شود. ورود در مرورگر سیستم با کد تأیید دستی و PKCE محدود به همان برنامه است؛ secret مشترک و کلید Gateway در نصب‌کننده نیست. backend Studio نشست همان مشتری را فقط یک بار به برنامهٔ دارای verifier تحویل می‌دهد.

مسیر عمومی `/studio/download` و نسخه‌های en/tr، وضعیت آماده‌سازی یا سه بستهٔ تأییدشده را نمایش می‌دهد. تا فعال‌بودن SSO، فعال‌کردن `SERVERNET_STUDIO_DOWNLOADS_ENABLED`، وجود manifest خصوصی `storage/app/studio/release.json` و هر سه فایل امضاشده (مک notarized) با نام/اندازهٔ دقیق، لینک دانلود عرضه نمی‌شود. `SERVERNET_STUDIO_DOWNLOADS_DIRECTORY` باید با مسیر واقعی public_html/downloads/studio در cPanel تطبیق داده شود؛ کپی دارایی فقط به app/public انتشار عمومی نیست. checksum باید هنگام آماده‌سازی/نصب تطبیق داده شود؛ صفحه برای هر بازدید فایل‌های بزرگ را دوباره hash نمی‌کند.

نصب هنوز اجرا نشده است: cPanel در ادامهٔ نشست وارد شد؛ بررسی فقط‌خواندنی Python3.12.16، Node و Passenger و نبود Docker را تأیید کرد. فایل‌های SSO هنوز نصب نیستند. نوشتن مخزن جدید Studio همچنان403 است و صفحهٔ تنظیم اتصال GitHub تأیید هویت مالک را می‌خواهد. نتیجهٔ آزمون و بسته‌ها پس از ساخت جدا ثبت می‌شود. فایل بدون امضای TEST، نسخهٔ عمومی نیست.
