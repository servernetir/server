# بازطراحی عودت موجودی کیف پول — ۳۱ اکتبر ۲۰۲۶

**به‌روزرسانی انتشار:** بسته در ۳۱ اکتبر روی تولید نصب شد؛ ۱۱ مقصد، دو Blade کامپایل‌شده، ۷۶تست/۱۰۷۶بررسی و ۱۲حالت رندر تولید با دادهٔ ساختگی تأیید شدند. مرجع جاری نصب، اختلاف‌های حفظ‌شده، پذیرش و بازگشت: [رسید انتشار عودت و منو](WALLET-PANEL-DEPLOY-2026-10-31.md). عبارت‌های «نصب نشده» در بخش‌های بعدی مربوط به نوبت توسعهٔ قبلی هستند.

## دامنه

مبنای develop: `c444fd7051281b359d5c95cdef91f02a605f2a4e`. صفحهٔ `/account/wallet-refunds` به فضای کار کارتی تبدیل شد: عنوان و میان‌بر تاریخچه، دو کارت موجودی و موجودی قابل درخواست، فرم با برچسب/خطای مرتبط، راهنمای مراحل، حالت‌های بسته/درخواست باز/نبود حساب و تاریخچهٔ پنج‌وضعیتی. CSS تازه فقط زیر `.wr-workspace` عمل می‌کند؛ قاعدهٔ گستردهٔ قبلی `.pnl-main .pnl-input` از این view حذف شد.

۱۶ کلید متن در هر سه فایل `lang/{fa,en,tr}/refund.php` افزوده شدند. مبلغ‌ها در همهٔ زبان‌ها همان تومان/IRT هستند. مجموع یا تعداد کل از صفحهٔ فعلی paginator ساخته نمی‌شود. بانک از همان select بومی و افزونهٔ متحرک مشترک سایت استفاده می‌کند؛ اسکریپت مالی تازه‌ای اضافه نشد.

## قراردادهای حفظ‌شده

- ترتیب شرط‌ها: غیرفعال، درخواست باز، نبود بانک، سپس فرم.
- محاسبهٔ موجودی و `max(0, available)` عیناً حفظ شدند؛ اختلاف آن‌ها «رزرو عودت» معرفی نشد، زیرا سایر رزروها نیز مؤثرند.
- routeهای POST، CSRF، idempotency_key و old input، نام فیلدها، محدودهٔ متن/مبلغ و رضایت لازم حفظ شدند.
- لغو فقط برای requested و رسید فقط برای paid است. approved به معنای واریز معرفی نمی‌شود.
- توضیح بررسی/اطلاعات بانکی escaped و جهت شبا/شناسه/رهگیری مستقل است؛ اطلاعات خصوصی مدیر یا مسیر فایل اضافه نشد.
- کنترلر، سرویس، مدل، migration، مجوز، محاسبات و metadata صفحات خصوصی تغییر نکردند.

دو ایراد قبلی منوی پنل در develop موجودند؛ مرجع دقیق [منوی موبایل](PANEL-MOBILE-NAVIGATION-2026-10-28.md) است. آزمون آن به‌صورت مستقل در workflow این تغییر نیز اجرا می‌شود. وجود این کد، تأیید نصب فعلی تولید نیست.

## اعتبارسنجی

آزمون PHP، view واقعی را در سه زبان و هفت حالت با دادهٔ ساختگی می‌سنجد و در CI، ۲۱ HTML مصنوعی برای مرورگر می‌سازد. تست قدیمی WalletRefundWorkflowTest نیز گاردهای مالی/مالکیت را بررسی می‌کند. آزمون Chromium، فرم و تاریخچه را در چهار عرض و دو تم، و حالت‌های فرعی را در عرض۳۹۰ بررسی می‌کند؛ بانک، خطا، نبود overflow و payload بومی فرم سنجیده می‌شوند. رویداد Escape ساختگی است؛ درخواست یا واریز واقعی ثبت نمی‌شود. تست منوی قبلی با همان ۳۳حالت حفظ شده است.

اشتراک helper مرورگر فقط export تابع CDP و محافظ اجرای standalone در فایل تست قبلی است. workflow دسترسی contents:read، checkout بدون credential، PHP۸٫۴ و وابستگی قفل‌شده دارد؛ بدون راز تولید، دادهٔ زنده، deploy یا npm install. تست‌ها فقط در GitHub Actions ایزوله اجرا می‌شوند؛ نتیجهٔ نهایی در بخش پذیرش زیر ثبت شده است.

در بازبینی، کنتراست متن کوچک و وضعیت‌ها بهبود یافت: رنگ‌های تیره‌تر فقط در تم روشن همین فضای کار و hints از رنگ muted استفاده می‌کنند. این اصلاح پالت عمومی سایت را تغییر نمی‌دهد.

## انتشار و بازگشت

در این نوبت نصب یا پذیرش زنده انجام نشده است. بستهٔ صفحه پنج فایل اجرایی دارد: view، CSS و سه فایل ترجمه. CSS در app/public و public_html مقصد مستقل دارد؛ ابتدا asset و ترجمه‌ها، سپس view نصب شوند. تست‌ها، workflow و اسناد مقصد انتشار نیستند.

برای دو ایراد قبلی، سه فایل panel layout/CSS/navigation باید جداگانه با نسخهٔ زنده تطبیق داده شوند؛ کپی کامل panel.css جاری ممکن است تغییر هم‌زمان دیگران را از بین ببرد. انتشار فقط با snapshot خصوصی، ادغام محدود، before/after hash، قفل و compilation همان viewها انجام شود؛ cache عمومی، DB، پول، سرویس و cron تغییر نکنند.

rollback فقط همین فایل‌ها با حفظ تغییرهای بعدی است. کلیدهای ترجمهٔ همکار و CSS خارج از محدوده بازنویسی نشوند. گزارش Git، نصب و پذیرش زنده جدا هستند.
