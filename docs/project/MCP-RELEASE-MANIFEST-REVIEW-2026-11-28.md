# مرحلهٔ اول انتشار استاندارد ServerNet از GitHub (فقط بازبینی)

## هدف و مرز فنی

این قابلیت مستقل، درخواست‌های طولانی و دستورات اجرایی SSH را به مسیر دیگری منتقل نمی‌کند. رابط `release_manifest_review` فقط یک manifest متادیتای تغییرهای وب را از commit ثابت مخزن بررسی می‌کند و وضع هش مقصدهای محلی را گزارش می‌دهد. امکان نصب، تغییر کد، نوشتن فایل، اجرای PHP/SSH، دریافت کد برای اجرا، قبولی خودکار انتشار یا اجرای rollout از این ابزار وجود ندارد. **تأیید MD/CI/manifest مجوز تولید نیست.** ابزارهای SSH، محدودیت‌های درخواست و سیاست تأیید آن‌ها بدون تغییر می‌مانند.

قابلیت برای مالک مجاز MCP و scope تازه `infrastructure:release:review` به همراه `infrastructure:read` است. توکن‌های موجود به‌طور ضمنی scope تازه نمی‌گیرند؛ پس از استقرار مستقل همین نسخهٔ MCP، رضایت OAuth برای آن scope لازم است. `infrastructure:execute` یا حالت تأیید خودکار SSH به این ابزار اختیار انتشار نمی‌دهد. هیچ مجوز اجرای انتشار برای مشتری/کارمند تعریف نمی‌شود.

## ورودی ثابت و قالب manifest

- مخزن ثابت: `servernetir/server`؛ سند فقط از `scripts/releases/<release>/manifest.json` در commit کامل و ثابت Git خوانده می‌شود، نه branch/tag، URL دلخواه یا مسیر ورودی.
- سه ورودی: `release` (شناسهٔ پایین‌حرف)، `commit` (۴۰ رقم hex پایین‌حرف)، `manifest_sha256` (۶۴ رقم hex دقیق بایت‌های سند).
- قالب JSON نسخهٔ `servernet-web-release/v1`، حداکثر ۳۲KiB و ۱ تا ۳۲ ردیف، JSON فشردهٔ canonical UTF-8 با newline نهایی اختیاری. ترتیب ردیف وابستگی مهم است؛ کد/فرمان، overlay محتوا، اعتبارنامه یا کلید اضافی پذیرفته نمی‌شود. `deployment_authorized` باید صریحاً `false` باشد. نمونهٔ صرفاً آزمایشی (هش‌ها برای fixture فرضی‌اند):

```json
{"schema":"servernet-web-release/v1","release":"fixture-release","git_source_commit":"1111111111111111111111111111111111111111","deployment_authorized":false,"files":[{"source":"website/public/assets/css/fixture.css","destination":"public_html/assets/css/fixture.css","operation":"add","before":null,"after":"2222222222222222222222222222222222222222222222222222222222222222"}]}
```

`add` به مقصد غایب نیاز دارد؛ `replace`/`overlay` هش دقیق پیشین و پسین متفاوت دارند. مسیرهای تکراری، پیمایش، symlink، مقصد نادرست، فایل‌های نهان/داده/راز، vendor/cache/bootstrap، migration، تغییر index.php و مسیر خارج از دامنهٔ مصوب پذیرفته نمی‌شوند. دامنهٔ پشتیبانی‌شدهٔ نسخهٔ اول عمداً کوچک است: فایل‌های presentation عمومی و تعدادی کلاس/تنظیم وب از پیش allowlist شده، فقط `routes/web.php` و `routes/international-market.php` برای بازبینی و CSS/JS عمومی. نیازهای جدید با بازبینی دامنه و PR جدا اضافه شوند؛ نه با افزودن wildcard در محیط زنده. مسیر مجاز منبع به مقصد تحت ریشهٔ ثابت app یا webroot نگاشت می‌شود؛ مقصد از ورودی قابل تغییر نیست.

## خروجی و مرحلهٔ بعد

خروجی `review_only` شامل شناسه/commit/هش manifest، نوع بازبینی هر فایل، زمان شروع/پایان مشاهده و وضعیت per-file است: `matching`، `absent` مورد انتظار، `conflict` یا `unsafe`؛ `preflight_unlocked:true` تصریح می‌کند این گزارش فقط مشاهدهٔ خواندنی و غیراتمی است، نه قفل یا وعدهٔ آمادگی نصب. محتوا، رازها و هش‌های واقعیِ ناشناختهٔ فایل زنده در پاسخ چاپ نمی‌شوند. هش Git محتوا و صحت PHP/Blade هنوز باید با روال مستقل تأیید شوند. اکیداً از آن برای نویسندگی خودکار، رفع تعارض کور، تکمیل gate یا اجرای فرمان استفاده نشود.

مرحلهٔ بعد که **نیازمند پیاده‌سازی و استقرار مستقل با بازبینی امنیتی** است: مسئول انتشار باید یک executor از پیش provision شده و محدود به artifacts/manifestهای امضاشده و محدوده‌های ثبت‌شدهٔ پروژه داشته باشد. رضایت جداگانهٔ مالک باید دقیقاً به SHA ثابت، hash manifest، محیط، نسخهٔ پیش‌بررسی و بازهٔ انحصاری متصل شود؛ به مجوز SSH یا autoapproval منتقل نشود. executor مصوب در همان محدوده باید قفل مشترک از پیش‌بررسی نهایی تا نصب و بازگشت، stage خصوصی، پشتیبان قابل بازیابی با هش، lint و آزمون مرتبط، توقف روی drift و rollback فقط فایل‌های همان release را تضمین کند. فعال‌سازی تنظیمات/OPcache و پذیرش HTTP مراحل جداگانهٔ بازبینی هستند؛ پاک‌کردن عمومی cache، عملیات دیتابیس/مالی یا provider، دستور عمومی و transport اجرای کد ممنوع‌اند. انتشار روی GitHub، source review یا `matching` به معنی نصب یا تأیید تولید نیست.

بستهٔ ۱۴فایلی پایلوت روسی/آذربایجانی که در PR #450 و #452 ثبت شده همچنان release candidate مستقل و غیرفعال است. نمونهٔ متادیتای همان بسته در [`scripts/releases/international-market-pilot-20261128/manifest.json`](../../scripts/releases/international-market-pilot-20261128/manifest.json) با هش `d7ca27475a7385d8e3d92af1647d4e79252dabf83ddcdc695e524b33bf03c827` فقط برای خواندن و بررسی ثبت شده است؛ نه کد نصب است و نه مجوز انتشار. این کار نه آن را نصب می‌کند و نه راه مسدود قبلی را بازسازی می‌کند. ثبت sitemap/درخواست ایندکس تنها بعد از پذیرش واقعی صفحات عمومی است.

## وضعیت و آزمون‌ها

این سند وضعیت طراحی و مرز نسخهٔ بازبینی را ثبت می‌کند. آزمون‌های پذیرش شامل مالکیت و scope مستقل با OAuth واقعی، schema/identity/hash، عبور ممنوع مسیر/تکرار/عملیات، byte cap و redirect، conflict، symlink و عدم تغییر فایل یا ایجاد action اجرایی هستند. CI امن موجود تصمیم‌های واقعی هر PR را روی SQLite و MariaDB ثبت می‌کند. هیچ migration، توکن یا ارتباط production جدید در این PR لازم نیست؛ استقرار خود MCP باید با سازوکار انتشار مجاز و رسید جدا تأیید شود.
