# محافظ اعتبار ترافیک آروان

وضعیت: کاندید Git برای develop؛ هیچ سرور واقعی خاموش/روشن نشده، حساب مشتری تغییر نکرده و این سند رسید نصب تولید نیست. مبنا `da62f84f7b73adf3ebb58e0aa117be6d9e50d0ed`؛ نتیجه آزمون CI در PR ثبت می‌شود. PHP محلی 8.3.6 فقط برای lint است؛ اجرای Laravel با وابستگی قفل‌شده و PHP 8.4 در دو job SQLite/MariaDB، بدون شبکه بیرونی انجام می‌شود.

## رفتار مالی

همان منبع کامل صورتحساب، نرخ، مالیات، استثناهای مالک، محافظ تسویه دستی و checkpoint قبلی حفظ می‌شوند. فقط سرویس دارای **برداشت مثبت تازه و معتبر ترافیک در همان تراکنش**، وقتی مانده قابل‌مصرف نهایی مشتری `<=0` است، `provision_meta.traffic_credit_hold` می‌گیرد. مانده از Wallet با خواندن قفل‌دار جاری دفتر و تمام رزروهای AI/استرداد/احراز/نگهداری ساعتی حساب می‌شود؛ snapshot قدیمی InnoDB و ستون مشورتی balance_after مبنا نیستند. یک تومان مثبت پس از رزرو موجود کافی است؛ حداقل ۲۴ساعته خرید دوباره تحمیل نمی‌شود.

فاکتور، پرداخت، برداشت، دفتر تجاری، checkpoint و قصد توقف در یک تراکنش commit/rollback می‌شوند. حساب ماهانه با مانده صفر و بدون برداشت تازه، استثنای مالک، داده تاریخی بی‌تطبیق یا خطای API وارد توقف نمی‌شود. این بسته هیچ مشتری قدیمی را از استثنا خارج نمی‌کند و بدهی/مصرف گذشته را اصلاح یا دوباره محاسبه نمی‌کند.

## توقف و روشن‌شدن

یک worker موجود در scheduler طبیعی، هر دقیقه فقط قصدهای ثبت‌شده را به تعداد محدود و با بودجه زمانی بررسی می‌کند. تماس زیرساخت خارج از تراکنش مالی است. `POST power-off` حتی با HTTP200 رسید نیست؛ GET همان UUID باید وضعیت خام shutoff/stopped را نشان دهد. خطا، timeout، UUID نامطابق یا پاسخ مبهم pending می‌ماند و هیچ برداشت تازه‌ای در worker نیست. نگهدارندهٔ تأییدشده هر پنج دقیقه دوباره بررسی می‌شود تا ON پذیرفته‌شده و دیرهنگام نتواند از توقف خارج شود. صف بر اساس موعد retry مرتب می‌شود؛ موارد تغییر مالک/منبع/حفاظت قرنطینه می‌شوند تا بقیه را معطل نکنند.

کنترل کم‌سطح ArvanClient برای on/reboot/reset/rebuild و مسیر unsuspend خودکار از این نگهدارنده می‌پرسند. اعتبار مثبت فقط همین پرچم را آزاد می‌کند؛ روشن‌شدن خودکار توسط محافظ جدید وجود ندارد. اگر OFF قبلاً صادر شده و هنوز قطعی نیست، حتی شارژ جدید اجازه ON هم‌زمان نمی‌دهد. شارژ پیش از صدور OFF، قصد صادرنشده را لغو می‌کند. شارژ پس از OFF مبهم فقط GET می‌زند؛ بعد از ۱۵ دقیقه وضعیت review_required و علت پایدار ثبت و در خروجی/هشدار فرمان نشان داده می‌شود. بدون اثبات توقف یا تطبیق دستی قطعی، صدور ON امن نیست؛ مالک باید نتیجه همان عملیات و نبود عملیات معوق را در زیرساخت تطبیق دهد، سپس فقط همین نگهدارنده را با قفل و ثبت ممیزی اصلاح کند. فرمان دورزننده عمومی برای حذف این محافظ اضافه نشده است.

این پرچم `status`، hourly_billing_hold، hourly_suspend، suspended_at، ذخیره نگهداری یا سیاست حذف را تغییر نمی‌دهد. سیاست موجود اجاره/اتمام اعتبار/نگهداری/حذف ساعتی مستقل اجرا می‌شود. تازه‌خوانی metadata هنگام resume مانع بازنویسی پرچم آزادشده با شیء کهنه است؛ توقف مدیر و مانع پایش توسط این بسته آزاد نمی‌شوند.

## زمان‌بندی، شاهد و محدودیت

همان یک زمان‌بندی `finance:meter-arvan-traffic --apply` از دو ساعت به پنج دقیقه تغییر می‌کند؛ کرون سیستم یا اجرای دستی متر اضافه نمی‌شود. worker تازه `cloud:traffic-credit-guard` دقیقه‌ای و بدون overlap است. `arvan_traffic_credit_guard_progress` فقط زمان/شمارش confirmed,pending,released,stale,review_required را نگه می‌دارد؛ review_required پایدار شامل قرنطینه‌های قبلی هم هست و سبز بودن اجرای فرمان به معنی توقف همه ماشین‌ها نیست.

تأخیر گزارش تأمین‌کننده به این پنج دقیقه اضافه می‌شود؛ مشاهده قبلی نزدیک ۲۰ دقیقه بود و ضمانت لحظه‌ای نیست. محدودیت نرخ/خطای API و صف محدود نیز می‌توانند زمان را زیاد کنند. node exporter مکمل سنجش است؛ این محافظ بر منبع معتبر مالی فعلی تکیه دارد و قطعی پایش را بدهی فرض نمی‌کند.

آزمون‌ها شامل منبع ساختگی واقعی درایور، قطع API/timeout/UUID، شارژ هم‌زمان، OFF مبهم، ON دیرهنگام، حفظ نگهدارنده مدیر و اجاره ساعتی، ادغام metadata، انصاف صف و rollback پس از نوشتن قصد توقف‌اند. MariaDB از دو اتصال واقعی برای commit پس از snapshot برنامه‌ریزی استفاده می‌کند و negative control نشان می‌دهد حذف current-read تصمیم واقعی متر را خراب می‌کند. اطلاعات یا توکن واقعی در آزمون و مخزن نیست.

## نصب و بازگشت

نصب محدود نیازمند manifest/hash پیش و پس برای فایل‌های برنامه و routes است؛ migration، تغییر نرخ/استثنا/checkpoint و اجرای دستی مالی لازم نیست. هیچ `--initialize` یا بازنشانی baseline انجام نشود. اول فایل‌های کلاس/درایور/Wallet و سپس schedule نصب شوند؛ فعال‌سازی PHP محدود و رسید مستقل root مسئول انتشار است. پذیرش طبیعی باید رشد checkpoint مالی و شمارش worker و رسید دقیق همان UUID را جدا بسنجد.

بازگشت کد/زمان‌بندی با نسخه پشتیبان فایل‌ها انجام می‌شود، ولی برداشت‌های commit‌شده خودکار معکوس و سرورهای خاموش خودکار روشن نمی‌شوند. قبل از عقب‌بردن گیت‌های power، نگهدارنده‌های فعال و OFFهای معلق جدا تطبیق داده شوند؛ حذف JSON یا بازگرداندن checkpoint ابزار rollback مالی نیست.
