## نصب و پذیرش تازه

از ترمینال موجود WHM در کروم متصل، با اجرای ابزارها تحت حساب servernetcloud
انجام شد. هش زندهٔ پیش از نصب دقیقاً با manifest برابر بود. همهٔ منابع stage
از SHA پین‌شده دریافت و هش شدند. راه‌انداز PHP lint شد؛ هفت تست محافظ انتشار
و۴۲ تست رفتاری سه‌زبانه با Node22 روی مقصد موفق بودند. وابستگی fixture قدیمی
در اجرای اول تست رابط stage نشده بود؛ fixture پین‌شده اضافه و همان تست دوباره
با موفقیت اجرا شد. این خطای بسته‌بندی، انتشار runtime ایجاد نکرد.

prepare، apply و verify با قفل‌های native و فایل مشترک، پشتیبان خصوصی و کنترل
تغییر هم‌زمان موفق بودند. فقط مقصد
`resources/views/bale/hermes.blade.php` نصب شد. کامپایل پیش‌بررسی Blade و lint
PHP کامپایل‌شده موفق بود؛ سپس فقط همان view فعال کامپایل شد.

هش نهایی: `a5ccd081516a280acfe6edddef777f1cfae793dc484e2eb8d0971e9710f51a1f`.
سه GET عمومی fa/en/tr همگی HTTP200 و منطق تازهٔ حفظ پیام، تفکیک پردازش و
محافظ پاسخ دیررس را داشتند. رسید خصوصی پذیرش در
`.araz-chat-recovery-20261109/public-acceptance.json` و پشتیبان در
`deploy-backups/araz-chat-recovery-20261109` است. cache عمومی پاک نشد.

Chromium محلیِ executor به علت منع socket شروع نشد. پذیرش تعاملی داخل ظرف
احرازشدهٔ بله هنوز انجام نشده است؛ HTTP و آزمون رفتاری جای آن معرفی نمی‌شوند.

## یافتهٔ موتور و مانع باقی‌مانده

کد زندهٔ MiniAppController با نسخهٔ ثبت‌شده تطبیق داشت. خواندن وضعیت سه درخواست
قبلی، بدون اجرای مجدد، HTTP200/accepted و `failed_or_uncertain` از worker گرفت؛
بنابراین مشکل صرفاً انتظار مرورگر نیست. سرویس‌های engine، broker و owner در
VM127 ابتدا active بودند؛ صف۴۴ نتیجهٔ completed و۵۱ failed_or_uncertain داشت.
متن گفتگو، شناسهٔ مالک، کلید و خروجی خام لاگ وارد این گزارش نشده‌اند.

لاگ engine برای شکست اخیر،۴۰۵ با توضیح تبدیل POST به GET روی
`v1/chat/completions` داشت. POST بدون کلید روی هر دو میزبان اصلی و کنسول اکنون
۴۰۱ و بدون Location می‌گیرد؛ این بررسی، مسیر احرازشدهٔ واقعی مدل را اثبات
نمی‌کند. config مدل به دامنهٔ اصلی اشاره دارد و کلید آن یک ارجاع محیطی است؛
ارسال خودِ عبارت ارجاع به‌عنوان Bearer نامعتبر بود و وضعیت واقعی کلید را ثابت
نمی‌کند. مقدار کلید، نام متغیر راز و فایل محیط نمایش یا منتشر نشدند.

برای یک آزمون مستقل کوتاهِ موتور، اجرای guest-exec پیش از دریافت رسید قطعی
با timeout روبه‌رو شد؛ نتیجه و حتی اجرای کامل آن نامعلوم است و تکرار نشد.
پس از آن QEMU Guest Agent پاسخ‌گو نبود، درحالی‌که `qm status 127` همچنان running
بود. ارتباط زمانی، علت قطع عامل را اثبات نمی‌کند. SSH با هویت موجود و کنترل
سخت‌گیرانهٔ host key، publickey را رد کرد؛ کلید موجودِ منطبق با metadata هم پیدا
نشد. noVNC در Connecting ماند. تغییر دسترسی، کلید یا سخت‌افزار و reboot انجام نشد.

برای ادامه، دسترسی احرازشده به ترمینال داخل VM127 لازم است تا عامل مدیریتی و
نتیجهٔ همان canary تطبیق داده شوند و سپس مسیر واقعی مدل بررسی/اصلاح شود. هیچ
فرمان قبلی، خرید، پیام مشتری یا job مالی replay نشد. تنظیم مدل، session موتور،
دیتابیس، شبکه و cron تغییر نکردند. پاسخ‌گویی سالم آراز هنوز ادعا نمی‌شود.

بازگشت رابط: همان launcher و phase=rollback با کنترل هش جدیدتر، سپس کامپایل فقط
همان view. دیتابیس گفتگو/صف و تاریخچه نباید از snapshot بازگردند.
