# انتشار محدود چندتأمین‌کنندهٔ دامنه — ۹ نوامبر ۲۰۲۶

این بسته فقط دلتای **PR [#298](https://github.com/servernetir/server/pull/298)** (کامیت `6a93883c`، merge `d692e650`) را روی تولید می‌برد:
«روشن‌کردنِ پرچم بدونِ حذفِ قیمت‌ها».

## چرا این بسته لازم است

قابلیت چندتأمین‌کننده (OpenProvider + Joker) **پیش‌تر روی تولید نصب شده**: روت‌های
`/admin/domain-suppliers` زنده‌اند و جدول‌ها ساخته شده‌اند. اما نسخهٔ نصب‌شده پیش از PR #298
است و سه تلهٔ بی‌خطای فعال‌سازی را دارد؛ هر سه در لحظهٔ روشن‌کردن پرچم
`DOMAIN_MULTI_PROVIDER_ENABLED=true` **همهٔ قیمت‌های عمومی دامنه را صفر می‌کنند**،
بدون هیچ خطایی و با پاسخ ۲۰۰ صفحه‌ها:

1. `capabilities.tlds` خالی ⇒ هیچ پسوندی واجد فروش نیست. PR #298 پروفایل استاندارد
   (`DomainSupplierAccount::STANDARD_PROFILE`) و `capabilities.default` را اضافه می‌کند.
2. `health_max_age_seconds` برابر فاصلهٔ کرون بود (۳۰۰ ثانیه) ⇒ هر چرخه همهٔ حساب‌ها
   لحظه‌ای «کهنه» می‌شدند. حالا ۹۰۰ ثانیه.
3. کاتالوگ فقط هر ۶ ساعت ساخته می‌شد ⇒ بین روشن‌کردن پرچم تا اجرای بعدی، سایت بی‌قیمت
   می‌ماند. PR #298 دکمهٔ فقط‌خواندنی «تازه‌سازی کاتالوگ» را اضافه می‌کند.

پس این بسته **پیش‌نیاز ایمنیِ** فعال‌سازی است، نه خودِ فعال‌سازی.

## دامنهٔ بسته

۱۳ فایل runtime، **بدون فایل جدید، بدون migration، بدون تغییر schema**.
فایل‌های `docs/`، تست‌ها و `CLAUDE.md` خارج از بسته‌اند.

هر فایل با SHA-256 **پیش** و **پس** پین شده است. اگر نسخهٔ زندهٔ هر فایل با هش پیش‌بینی‌شده
یکی نباشد، اجرا متوقف می‌شود و چیزی بازنویسی نمی‌شود — کار هم‌زمان همکار هرگز کور
جایگزین نمی‌شود (درس ۲۸ مرداد، [DEPLOYMENT.md](../../docs/project/DEPLOYMENT.md)).

## اجرا

روی ترمینال cPanel، با کاربر `servernetcloud`:

```sh
curl -fsSL https://raw.githubusercontent.com/servernetir/server/<SHA>/scripts/domain-supplier-release-20261109/release.sh -o ~/dsr.sh && bash ~/dsr.sh check
```

`<SHA>` همیشه کامیت دقیق همین فایل باشد، نه نام شاخه: `raw.githubusercontent.com` برای
ref شاخه تا حدود پنج دقیقه کش دارد و ممکن است نسخهٔ قدیمی بدهد. اگر کلون گیت روی سرور
هست، این هم معتبر است:

```sh
git -C <clone> fetch origin && git -C <clone> show <SHA>:scripts/domain-supplier-release-20261109/release.sh > ~/dsr.sh && bash ~/dsr.sh check
```

### قفل مشترک انتشار

سه فایل `~/.servernet-web-release.lock`، `~/servernet-release.lock` و
`~/.codex-web-deploy.lock` قفل **مشورتی `flock`** هستند، دقیقاً مثل
[`scripts/seo-release-20261108/release.py`](../seo-release-20261108/release.py)، و به همان
ترتیب گرفته می‌شوند. این فایل‌ها یک‌بار ساخته می‌شوند و **هرگز پاک نمی‌شوند** — معمولاً
خالی‌اند. پس:

- وجود فایل به‌تنهایی یعنی هیچ؛ فقط `flock` می‌گوید کسی در حال انتشار است.
- **هرگز این فایل‌ها را حذف نکنید.** حذف‌شان قفلِ انتشاری را که همین الان در جریان است
  بی‌صدا می‌شکند. قفل با مرگ پراسس آزاد می‌شود، پس چیزی برای پاک‌سازی نمی‌ماند.
- پیام `shared release lock busy` یعنی یک انتشار دیگر واقعاً در حال اجراست: صبر کنید.

| فرمان | اثر |
|---|---|
| `check` | فقط‌خواندنی: وضعیت هر ۱۳ فایل (BASE/TARGET/DRIFT/MISSING)، کش‌ها، پرچم‌های `.env`، فایل‌های migration، و چهار GET پذیرش. چیزی نمی‌نویسد. |
| `apply` | گرفتن سه قفل مشترک انتشار، دانلود پین‌شده به SHA، راستی‌آزمایی هش، lint، بکاپ پیش‌تصویر، نصب اتمی هر فایل، بازسازی کش‌های موجود، و پذیرش HTTP. |
| `verify` | دوباره‌خوانی هش هر ۱۳ فایل + پذیرش HTTP. |
| `rollback <stage>` | بازگرداندن پیش‌تصویرها؛ فایلی که بعد از نصب تغییر کرده باشد رد می‌شود، نه بازنویسی. |

`apply` فقط فایل‌هایی را می‌نویسد که هش‌شان دقیقاً برابر پیش‌تصویر مصوب باشد، و بلافاصله
پیش از هر نوشتن دوباره drift را می‌سنجد. پیش‌تصویرها در `~/.domain-supplier-release-20261109-<stamp>/preimage`
می‌مانند (خارج webroot).

## آنچه این بسته انجام نمی‌دهد

- پرچم `DOMAIN_MULTI_PROVIDER_ENABLED` را تغییر نمی‌دهد (پیش‌فرض خاموش می‌ماند).
- هیچ حسابی را «فعال فروش» نمی‌کند و `capabilities` هیچ حسابی را نمی‌نویسد.
- هیچ migration، تماس تأمین‌کننده، خرید، تمدید یا تغییر دادهٔ مشتری ندارد.
- OPcache وب را ریست نمی‌کند؛ طبق DEPLOYMENT.md فقط در صورت مشاهدهٔ کد کهنه لازم است.

## ترتیب فعال‌سازی پس از این نصب

مرجع کامل: [DOMAIN-SUPPLIERS-JOKER-2026-10-31.md § ترتیبِ روشن‌کردن](../../docs/project/DOMAIN-SUPPLIERS-JOKER-2026-10-31.md).

1. در `/admin/domain-suppliers` برای هر حساب: تیک «پروفایل استاندارد» → ذخیره
   (عمداً فروش همان حساب خاموش و سلامتش پاک می‌شود).
2. «آزمون خواندنی اتصال» برای همان حساب.
3. «تازه‌سازی کاتالوگ» و بررسی **جدول مقایسهٔ بهای تمام‌شده**.
4. «فعال‌سازی فروش» فقط برای حساب‌های آماده.
5. کارفرما `DOMAIN_MULTI_PROVIDER_ENABLED=true` را در `.env` می‌گذارد؛ اگر
   `bootstrap/cache/config.php` هست، کش کانفیگ باید بازسازی شود.
6. بلافاصله دوباره «تازه‌سازی کاتالوگ»، سپس یک نگاه به خانه و `/domains`.

**بازگشت:** با پرچم روشن، `TldPriceBook::refreshAll()` فقط کاتالوگ چندتأمین‌کننده را
می‌سازد و دفترچهٔ قدیمی OpenProvider بعد از ۲۴ ساعت کهنه است. پس بعد از خاموش‌کردن پرچم،
حتماً دکمهٔ «تازه‌سازی کاتالوگ» زده شود.
