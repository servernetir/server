# Private-stage Arvan FastCGI activation

This transport variant keeps the executable primary outside both observed web roots. It is a narrow clone of the reviewed V3 FPM activation package; the six-source deployment helper, patchdata and frozen original transport are unchanged. Git publication is not installation or production acceptance.

The only executable primary is the fixed private-stage `private-fpm-activation.php`, with mode0600 inside the canonical account-owned0700 release stage. Stage it only into a previously absent fixed filename and freeze those bytes after the first FPM observation. If a later revision is needed, use a separately reviewed fresh path or primary-invalidation procedure; disk hash alone does not establish which primary bytecode OPcache retained. The caller uses that exact `SCRIPT_FILENAME`, a fixed internal script identifier, and the real existing `DOCUMENT_ROOT`. It requires an explicitly observed canonical Unix socket owned by this account, validates private caller/primary metadata, and pins the exact reviewed PHP bytes. No socket discovery, arbitrary script selection, HTTP token or public executable helper is added. The `--host` values remain receipt-slot labels; they do not select a pool or establish hostname routing.

PHP retains the release/action/POST/host/plan, account, helper, mutex, six-source, compiled inventory and recovery guards. Own and peer receipts must bind `private-stage-fcgi-v1`, the fixed private primary path and its exact SHA256; legacy or unbound public receipts cannot be replayed. The caller also checks every successful response's release, action, slot, plan and private transport identity. Receipt and rollback algorithms otherwise match V3.

Operator sequence, in separate reviewed phases:

1. Reserve the stage, six sources and temporary root configuration against concurrent deployment. Stage only exact reviewed files privately; keep the unchanged pinned V3 `deploy.php`, patchdata and approved source plan. Verify canonical paths, owner/mode/hash, the actual owned-listener inventory and immutable one-to-one socket/receipt-slot ledger. Refuse unexpected activation receipts or transport history.
2. Run the new caller with `--action observe` on each validated socket/slot and the approved source-plan SHA. This reads current sources and OPcache capabilities; it does not install sources or invalidate/compile views. FPM `doc_root`, permissions or runtime rejection is a stop without mutation. Never weaken a pool or path guard to make it pass.
3. Only after both observations pass, use the existing hash/metadata guards to remove the old public primary and its exact denial file/empty directory, then remove the scoped ErrorDocument block while the original F rule remains, then clean up the F block. Preserve unrelated root edits and confirm normal HTTP behavior. There is no remaining public executable primary for this transport.
4. Apply the unchanged six-source plan once with the reviewed deployment helper. Require its successful receipt and independently verify all six hashes/metadata before private `activate`, then `verify`, separately on both stable socket/slot assignments. Verify actual hostname UI and Windows console behavior independently; source readiness is not proof of guest logon.

Use the fixed account's native PHP8.4 and Python3 in the approved account shell. The caller arguments remain `--socket <actual-owned-absolute-socket> --host <assigned-slot> --plan-sha256 <reviewed-source-plan-sha> --action observe|activate|verify`. Never infer socket names or reuse one host slot for two sockets. This unchanged two-slot receipt design supports at most two validated socket identities; drift or additional sockets requires separate reviewed design.

After interruption, inspect source/compiled hashes and private receipts before any retry. Keep all evidence. Do not delete receipts to bypass a refusal or replay a receipt from the public transport. No database/provider/financial/VM/scheduler operations, global cache flush or FPM restart belong to this package.

Validation before publication: independent lint,19 compiled assertions,14 CLI flow tests covering38 scenarios,6 protocol tests and8 private-path/response guard tests passed with the available local PHP8.3 runtime. The latter use disposable files and synthetic socket metadata, with no socket creation or connections. The focused CI verifies frozen SHA256 entries and the caller's hard pin, then runs these suites under PHP8.4 without an external network interface. Only copied synthetic fixtures execute; no application bootstrap, real FPM request or production action is performed. Native private `observe` and actual per-host UI remain acceptance steps.
