## Recovery

V3 preallocates and flushes every compiled install/reversal before the first compiled rename. Receipt publication uses an atomic no-overwrite hard link, tracks its dev/inode/hash, and verifies it while still inside the rollback scope. On failure, only the exact receipt owned by this invocation may be withdrawn. A changed or foreign receipt is preserved together with installed artifacts for explicit operator reconciliation. The shared Arvan mutex inode is checked around acquisition, writes and receipt publication; a replaced mutex stops further mutations.

A normal caught failure restores only compiled paths whose rename was attempted by this request and whose current hash/metadata still match this request's after-state. It continues restoration of other owned paths after concurrent drift and reports affected basenames in `compiled_rollback_errors`; drift is never overwritten. Backups and install temporaries have unique random private names, so an interrupted request with no success receipt can recheck current sources/artifacts and safely retry without filename collisions. If rollback errors, an unexpected receipt or hash drift is reported, stop for inspection; do not delete historical receipts or force a retry. A successful activation retry and verify are read-only with respect to compiled artifacts and fail if any recorded source or compiled artifact subsequently changed.
